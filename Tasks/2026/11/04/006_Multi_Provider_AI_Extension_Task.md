# 다중 AI 프로바이더 확장 판단·계획

현재 Staging은 다른 AI가 평가·검증 중이므로 읽기 전용 참고로만 사용한다. 이번 작업은 확장 가능 여부 판단과 관리자 프로바이더 관리·사용자 모델 목록/선택·같은 대화 이어가기·장비관리 내부 대기열의 설계다. Staging/운영 소스·설정·DB·기존 평가 산출물은 변경하지 않고, 실제 모델 호출이나 네트워크 탐색·배포를 하지 않는다. 005 산출물은 다른 작업자의 것이므로 006 독립 문서로 기록한다.

- [x] 기록기/profile/manifest/context와 관련 규칙 확인. profile legacy(runtime-session-mismatch), validate 오류/경고 0.
- [x] 현재 후보의 읽기 기준선과 모델 결합 지점·재사용 경계를 확인.
- [x] 공식 API 자료로 모델 목록·추론·도구/스트림 차이를 확인하고 사실·제안을 구분.
- [x] 확장 또는 재작성의 근거와 대안 비교. 전면 재작성 없이 확장 가능으로 판정.
- [x] 관리자 설정·사용자 선택·대화/작업 스냅샷·provider별 내부 큐·안전 경계 계획.
- [x] 데이터 이전/호환·오류·비활성화·모델 전환·복귀·검증 기준 정리.
- [x] 계획 작성 후 Validation 1~8을 순서대로 보고서에 기록하고 교차 시나리오 검토.
- [x] 후보 16개 파일의 시작/최종 SHA-256 동일 확인, 최종 validate 오류/경고 0. 한국어 표와 설명의 보고 준비 완료.

코드/DB/설정 구현, Staging 변경, 실제 모델 호출/네트워크 탐색, 기존 005 평가 편집은 수행하지 않았다. 별도 계획·작업·판단 보고서 3개만 작성했다.

사용자가 구현 시점을 지정하기 전에는 이 계획을 구현 승인이나 기존 후보 병합 승인으로 해석하지 않는다. 외부 서비스/다른 소비자의 요청 통제는 범위 밖이다.

- [x] 세션 재개 시 마지막 유효 provider/model/추론값 복원과 기본값 우선순위 명세.
- [x] 모델 자동 조회·선택을 기본값으로, 수동 등록을 관리자 선택사항으로 명세.
- [x] 고급 연결 설정은 별도 지시 전 보류로 기록하고 기본 연결 관리와 구분.
- [x] 영향받는 계획·검토 항목을 1~8 순서로 재검토하고 Staging 16개 파일 SHA-256 동일 확인.
