# [Task] 제안-046 서버 점검 모드

## 작업 모드와 범위

- 모드: 스테이징 구현 및 운영 소스 병합
- 현재 승인 범위: 제안·로드맵·계획·검증 문서, 스테이징 구현, 운영 소스 병합
- 현재 제외: 원격 서버 설정 변경, 서비스 재시작, 원격 런타임 검증 및 DB 복원

## 순차 Task

1. 제안 번호와 기존 로그인·세션 만료 구조를 확인한다. 완료.
2. `PROPOSALS.md`, `UNIMPLEMENTED_PROPOSALS.md`, `ROADMAP.md`, `UNIMPLEMENTED_ROADMAP.md`에 제안-046을 채택 상태로 등록한다. 완료.
3. 앱을 중지하지 않고 점검 상태에서 DB 백업·업로드·온라인 복원까지 수행하는 흐름을 설계한다. 완료.
4. 검증 1~8단계를 순서대로 기록한다. 완료.
5. `Staging/`에 운영 복사본을 만들고 점검 상태 파일, 중앙 게이트, 세션 만료, 관리자 화면·API 및 로그인 안내를 구현한다. 완료.
6. JavaScript 구문·변경 공백·템플릿 구조를 정적 검토한다. 로컬 Python 인터프리터 부재로 Python·Jinja 실행 검사는 서버 검증 단계로 이관한다. 완료.
7. GEMINI 운영 적합성 보고서의 유의사항을 확인하고, 스테이징의 다섯 파일을 운영 소스 경로에 병합한다. 스테이징 일치·JavaScript 구문·변경 공백·거버넌스를 재검증한다. 완료.
8. 원격 서버에서 Flask 실행 계정의 `instance/` 쓰기 권한, 관리자/일반 사용자 점검 전환, 점검 해제를 검증한다.
9. 제안-013 단계에서 DB 요청 동결, 온라인 복원, 자동 원복을 구현하고 서버 검증 계획을 승인받은 뒤 검증한다.
