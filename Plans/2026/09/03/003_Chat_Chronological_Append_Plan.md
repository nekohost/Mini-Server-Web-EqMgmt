# 대화 저장 시간순 정렬 보완 계획

## 목적

대화 저장은 긴 작업의 매 중간 과정마다 수행하지 않는다. 기존처럼 작업 완료·사용자 전환 등 필요한 시점에 저장하되, 저장하려는 블록의 실제 KST 시각과 해당 일자 파일의 최근 기록 일부를 비교하여 시간순 위치를 보장한다.

## 핵심 정책 초안

1. `Chat/YYYY/MM/DD.md`의 기본 동작은 append다.
2. 저장할 블록의 확인된 발생 시각이 마지막 기록 시각보다 같거나 늦으면 그대로 append한다.
3. 더 이른 시각이면, 최근 32개 대화 헤더만 먼저 읽어 시간순 삽입 위치를 찾는다. 본문 전체를 컨텍스트에 올리지 않는다.
4. 대상 시각이 최근 창보다 더 이르면, 이전 구간은 본문이 아닌 헤더·파일 오프셋만 제한적으로 추가 탐색한다. 첫 번째 더 늦은 헤더 바로 앞에 블록 전체를 삽입한다.
5. 같은 시각이면 기존 동률 블록 뒤에 기록해 안정적인 순서를 유지한다.
6. 삽입은 대화 블록 전체를 단위로 수행한다. 기존 원문을 수정·삭제하지 않으며, 순서만 변경한다.
7. 편집 직전의 최근 헤더 fingerprint가 바뀌면 저장을 재시도하기 전에 최근 창을 다시 읽는다. 동시 작업자가 기록한 새 블록을 덮어쓰지 않는다.

## 변경 대상

- 사용자용 Rule: 6-1-5, 6-1-7, 6-2-2, 6-2-5, 6-2-8의 append 절대 규칙을 “append 기본값 + 시간순 삽입 예외”로 명확화하고, 중간 안내는 최종 저장에 함께 보존하되 모든 내부 과정의 즉시 저장을 강제하지 않도록 한다.
- 직접 실행 노드: `records/conversation-storage.md`, `records/timestamps.md`. `records/conversation-integrity.md`와 `tools/conversation-exception.md`는 이번 Staging Rule 포인터의 직접 대상이 아니므로 의미 변경 없이 검증 대상에만 포함한다.
- 검증: 시간 역전·동률·최근 창 밖의 지연 블록·동시 기록 재확인 사례를 정책 수용 기준으로 확인한다. 별도 대화 writer를 도입하지 않는 이번 범위에서는 거버넌스 도구가 Rule·노드·추적성 정합성을 검사한다.
- 추적성: Rule 포인터, human-rule-map, Rule 섹션 기준선, node digest, manifest SHA·버전을 같은 변경 단위로 갱신한다.

## 비범위

- 모든 중간 안내를 실시간 저장하도록 강제하는 변경
- 이벤트 저널·별도 타임라인·상시 단일 writer 서비스 도입
- 플랫폼이 제공하지 않는 최종 송신 시각의 임의 생성

## 검증 기준

- 새 블록이 마지막 시각 이후면 append한다.
- 새 블록이 최근 창 안의 과거 시각이면 정확한 위치에 삽입한다.
- 최근 창보다 앞선 시각이면 헤더만 추가 탐색하고 본문 전체를 읽지 않는다.
- 기존 블록의 원문과 헤더가 보존되고, 결과 헤더가 비감소 시간순이다.
- 재확인 시 최근 fingerprint가 달라지면 오래된 판단으로 쓰지 않는다.

## 적용 순서

1. 다음 Rule 개정용 Staging 초안에서 위 정책을 반영한다.
2. 영향 노드·추적성·도구 테스트를 함께 갱신한다.
3. `sync-status`, 전체 변경 섹션의 `sync-plan`, `validate --expected-rule-sha`, 회귀 테스트로 검증한다.
4. 사용자 승인 뒤에만 운영 Rule과 노드를 활성화한다.

## 현재 상태

완료. 오늘 `Chat/2026/09/03.md`의 기존 시간 역전을 정정했고, 사용자 승인에 따라 Rule 6-1-5, 6-1-7, 6-2-2, 6-2-5, 6-2-8과 직접 대상 노드 `records.conversation-storage`, `records.timestamps`를 운영에 반영했다. 거버넌스 버전은 `1.1.0`, 운영 Rule SHA-256은 `0366391F84CF1F9C6AA30DB4E8E60927A05903A159E13AB815A2C586445AD7EB`이며, 기준선·노드 digest·manifest를 같은 변경 단위로 동기화했다. 거버넌스 검증과 12개 회귀 테스트가 통과했으며 Staging 초안도 성공 확인 뒤 정리했다.
