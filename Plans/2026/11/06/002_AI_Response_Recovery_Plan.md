# AI 구조화 호출·빈 답변 보정

사용자가 최신 질문의 답변 누락 진단001을 바탕으로 조치방안과 운영 반영까지 승인했다. 이전 실패 job을 다시 실행하거나 성공으로 바꾸지 않고 앞으로 처리되는 요청의 종료 경계를 보완한다. 근거는001의 complete/calls0/content0/reasoning741과 WEB_SEARCH_PLAN_REQUIRED다.

| 경우 | 조치 | 보존할 경계 |
|---|---|---|
| 첫 자동 검색 판단이 도구 호출 없이 완료 | server context에 고정된 보정 지시를 넣고 같은 job의 다음 단계에서 필수 plan_web_search를 정확히1회 다시 요구 | 명시적 완료·소유자/lease 확인 뒤에만 큐에 재진입, 첫 미실행 단계는 검색/업무 실행0 |
| 완료됐지만 도구 호출·답변 내용이 모두 없음 | 같은 job의 답변 보정 단계를1회 제공. 이 단계는 새 도구 없이 이미 얻은 자료만으로 답변 | 이미 받은 출처/확인 카드/도구 결과 유지, 장비 변경·검색 중복 실행 방지 |

| 연결 종료 미확인·실제 검색/권한/검증 오류·취소/휴지통 | 기존 중단/점유 원장 계약 유지 | 추측한 성공·숨은 외부 재요청·다른 서비스 제어 금지 |

새 보정 상태는 기존 job.context 안의 서버가 만든 정확한 system 메시지로만 구분한다. 사용자의 문자열이나 모델 추론을 보정 권한으로 파싱하지 않는다. 현재 build_context는 대화의 user/assistant 행과 bounded 인계 자료만 만들므로 이전 job의 system 보정 메시지는 새 질문으로 전이되지 않는다. DB/schema·프로토콜·외부 라이브러리는 추가하지 않는다. 동일 요청 재전송이 아닌 감사 가능한 별도의 다음 모델 단계이며 Store의 단계별 lease·공정 큐·취소와 전체 한도를 재사용한다.

최종 교차 검토에서 같은 job 내 완료된 보정 지시가 다음 정상 단계에 남는 경우도 분리한다. 영속 context에는 횟수 원장을 그대로 두고 모델에 보낼 때 정확한 현행/구 버전 서버 제어 메시지만 제외한다. 현재 보정 단계의 지시만 첫 system 메시지에 합쳐 다중 system 역할에 대한 모델 호환성과 단계별 지시 범위를 확인한다. user/assistant에 복사된 문자열이나 다른 실제 대화는 제거하지 않는다.

정상 선택 모델/추론 수준과1800초 읽기 계약을 유지한다. 종료 표식이 없는 스트림은 보정 대상으로 삼지 않는다. worker에는 job/step/outcome/정규화된 종료 사유/DONE·문자량·호출 수만 로그로 남겨 향후 추론만 출력한 종료를 진단할 수 있게 한다. 질문/추론/키는 추가 로그에 출력하지 않으며 기존 본문 감사는 보존한다.

1차 운영 시험의 xhigh 비교 요청은 필수 판단과 실제 검색2회를 통과했으나 마지막 단계가 DONE=true/finish=length, 추론9,355자·답변1,888자로 잘렸다. 이를 성공으로 집계하지 않고 V2 Staging으로 돌아가 보완한다. worker 완료 본문에 선택형 termination 메타를 추가해 서버가 명시적 토큰 종료와 미확인/다른 실패를 구분한다. 구 worker/구 완료 본문은 기존 경로를 유지한다. legacy required에서 아직 검색이 없을 때는 답변 보정으로 검색 의무를 우회하지 않는다. 답변 보정은 별도 단계에서 기존 자료로 간결한 최종 답변을 작성하며, 앞선 잘린 step과 실패 원인은 감사에 보존한다.

Staging에서 순수 상태·실제 API/Store·worker fake SSE·취소/휴지통/세션 변경·late finish/예약·검색 privacy/한도·잘못된 도구·보정 소진과 실제 빈 답변을 검사한다. Linux 전체 회귀 후 원문/SHA 보존→root 병합/정적·전체 재검증→정확한 후보 정리→한정 commit/push를 수행한다. 현재 설정/source/두 DB의 서버·현재PC private 백업과 실제 DB 사본 보존 검사를 통과한 뒤 idle인 자체 web/worker만 전환한다. 실제 일반 계정의 xhigh 비교 질문과 인사/검색 응답·원장·화면을 검증하고 문서/서버를 동기화한다. 사용자에게 추가 승인을 요구하지 않는다.

완료: 최종 Staging/root 각293개를 통과했고 원문8개·후보 정리·현재 백업14개·실제 DB 사본 보존 검사 후 운영에 반영했다. 최종 운영의 같은 비교 질문은191.293초·2단계·실검색1회로 완결됐다. 의도적 빈 답변 요구는 실제 보정1회 소진 후 구체적 오류/잠금 해제를 확인했고, 같은 대화의 다음 질문은15.555초에 정상 응답했다. PC/412×915 화면과 기존 행·감사·설정·구 실패 보존을 확인했다. 최종 근거는 보고서002에 연결한다.
