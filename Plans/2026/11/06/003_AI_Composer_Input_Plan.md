# AI 입력 공간 정리·키 입력 신뢰성

사용자의 세 요구를 현재 운영 산출물에 병합한다. 입력 아래의 접수 모델 변경 안내와 Enter 설정 안내를 제거한다. 저장된 ai_enter_action이 정확히 newline/send인 사용자는 그대로 유지하고, 값이 없거나 유효하지 않을 때만 Enter 보내기·Shift+Enter 줄바꿈을 기본으로 삼는다. 서버 JSON을 일괄 갱신하거나 GET에서 저장하지 않는다. 개인 설정의 두 선택지와 설명은 유지하며 기본 표시만 바꾼다.

프런트 조사는 입력칸 전체의 hit target·focus, 실제 keydown/beforeinput/input/composition/blur 순서, disabled/진행 중/접수 중 잠금, 모델/목록 비동기 갱신, 네이티브 줄바꿈·선택 영역·초안 보존을 포함한다. 현재 키 처리에는 beforeinput 경로와 blur 시 조합 상태 해제가 없다. 이 두 경로를 원본 코드로 재현한 뒤 수정한다. IME의229 키 코드 자체를 전송 근거로 삼지 않고 실제 비조합 줄바꿈 의도를 보조 근거로 사용한다.

기본 키보드 Enter/Shift+Enter는 기존 폼 접수 경계로 보낸다. 모바일 줄바꿈 입력 이벤트만 오는 경우도 처리하되, 같은 키에서 두 이벤트가 와도 한 번만 접수한다. 비취소 beforeinput의 경우 수정 전 스냅샷과 예상된 단일 줄바꿈이 정확히 일치할 때만 원문을 복원해 같은 경계로 접수한다. 조합 확정·수정키·붙여넣기·진행 중 요청·알 수 없는 편집은 임의 전송하지 않는다. 포커스가 바뀌면 해당 입력기의 일시 상태를 해제한다.

enterkeyhint와 aria-keyshortcuts에 실제 설정을 반영하고 화면 아래의 고정 안내는 다시 만들지 않는다. 기존 캐시 템플릿의 안내 노드/aria 참조도 제거한다. 설정 로딩 전후의 기본/저장 값과 입력 초안을 검사한다. 운영 엔진·보정·큐·권한·도구 실행과 현재 모델/추론 설정은 변경하지 않는다.

추가 조사에서 설정 fetch 전에는 기본값으로 먼저 바인딩되는 초기 경합도 확인했다. 서버가 현재 인증 계정의 저장된 두 모드 중 하나를 HTML에 함께 전달하고, 초기 클라이언트는 해당 값을 사용한다. 이후 정상 설정 응답은 기존 이벤트로 반영한다. 설정이 늦어도 첫 키에 기존 사용자 모드가 적용되며, 저장 행은 읽기만 한다. 이 범위 확장 전에 __init__.py를 실제 대상으로 context에 추가해 같은32노드·필수 입력0을 확인했다.

Staging 원본 재현과 수정 후 Linux 격리의 설정 API/네이티브 Chromium/이벤트 교차 검사를 수행한다. 모바일·PC/테마와 버튼 회귀·스크린샷을 확인한 뒤 원문 ZIP/SHA를 보존하고 root 병합·정적/관련 재검증·정확한 후보 정리·한정 commit/push를 수행한다. 연속 작업의 운영 반영 승인 범위에서 현재 백업·실제 DB 사본 보존·idle 자체 서비스 전환 후 일반 계정의 저장 설정 유지와 실제 Enter/Shift+Enter를 검증한다. 실제 폴드7 물리 입력기 시험과 합성 IME/viewport 시험은 구분한다.

완료: Staging/root 각296개, 입력 각24화면·712개 검사/128개 이벤트 교차, 버튼 각4화면·388개 및 모바일 probe92개를 통과했다. 원문11개·정확한 후보 정리·현재 백업14개·실제 DB 사본 보존 후 운영에 반영했다. 기존 newline 계정은 Enter 줄바꿈/Shift+Enter 전송으로14.756초, 미설정 계정은 Shift+Enter 줄바꿈/Enter 전송으로18.491초에 실제 인사 응답을 받았다. 최초 모호한 시험 문구에 대한 모델 거절도 별도 기록했다. 모든 계정의 설정 JSON/UpdatedAt이 배포 직전과 정확히 같고, 운영 source·기존 행·감사·설정·서비스 상태와 PC/모바일 화면을 확인했다. 최종 근거는 보고서003에 연결한다.
