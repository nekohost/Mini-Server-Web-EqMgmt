# AI 도우미 첫 화면과 첫 메시지 저장

사용자가 AI 도우미를 열면 이어갈 대화 또는 새 대화의 환영 화면을 한 번만 표시한다. ‘새 대화’는 입력을 시작하는 버튼으로 두고, 저장된 대화는 서버가 첫 메시지를 접수한 시점에 생기도록 한다.

2026년 11월 9일 승인된 계획을 Staging에 구현했다. [검증 보고서와 화면 기록](../../../../Reports/2026/11/09/006_AI_Conversation_Entry_Staging_Report.md)

## 현재 동작

초기 HTML에 ‘새로운 대화’ 제목과 환영 카드가 보이는 상태로 들어 있다. 브라우저가 권한, 모델, 최근 대화 목록을 차례로 조회하고 목록 첫 항목의 본문을 받은 뒤에야 제목과 본문을 바꾼다. 활성 목록은 계정별 최근 갱신 순이며, 과거에 만든 빈 대화도 포함한다. [초기 화면](../../../../templates/equipment_ai.html) · [초기화와 대화 열기](../../../../static/js/equipment_ai.js) · [목록 조회](../../../../utils/ai_assistant/store.py)

‘새 대화’ 클릭은 즉시 생성 API를 부른다. 대화가 없는 화면에서 첫 메시지를 보낼 때도 대화 생성, 모델 선택 저장, 메시지 접수가 별도의 요청이다. 마지막 접수가 거절되더라도 먼저 저장한 대화는 남을 수 있고 계정의 대화 보관 한도에 포함된다. [화면의 클릭·전송 처리](../../../../static/js/equipment_ai.js) · [생성 및 접수 API](../../../../utils/ai_assistant/__init__.py)

## 화면 동작

| 사용자 상황 | 표시와 동작 |
|---|---|
| AI 도우미에 진입 | 첫 HTML부터 상단 바·목록·입력창의 자리를 잡고 본문은 중립적인 로딩 상태로 시작한다. 제목과 환영 카드, ‘저장된 대화가 없습니다’ 문구는 결과가 확정될 때 표시한다. 빠른 조회에 인위적인 대기 시간을 더하지 않는다. |
| 이어갈 대화가 있음 | 내 활성 대화 중 실제 사용자 메시지가 있는 대화를 최근 갱신 순으로 하나 골라 제목·본문·현재 선택을 함께 표시한다. 과거의 빈 대화도 최근 목록에서 직접 열어 사용할 수 있다. 휴지통과 관리자 전용 모델 시험은 자동 복원 대상에서 제외한다. |
| 이어갈 대화가 없음 | 기존 환영 화면과 제안 문구를 보여 준다. 대화가 전혀 없는 계정, 휴지통에만 대화가 있는 계정, 기존 빈 대화만 있는 계정에 같은 진입 방식을 쓴다. |
| ‘새 대화’를 누름 | 기존 대화의 선택 표시를 풀고 환영 화면으로 즉시 전환한다. 최근 목록에는 항목을 추가하지 않는다. 입력창에 있던 미전송 문구는 보존하고, 모델과 추론은 새 대화의 기본값에서 바꿀 수 있게 한다. 반복 클릭, 제안 문구 선택, 모델 변경, 보내기 전 이탈로는 대화를 생성하지 않는다. |
| 첫 메시지를 보냄 | 서버 접수 시 실제 제목으로 목록에 한 건을 표시하고 그 대화에서 응답을 이어 받는다. 접수 거절 시 입력과 선택을 보존하고 사유를 보여 준다. 접수 후 모델이 응답에 실패하면 질문과 실패 사유는 해당 대화에 남긴다. |
| 조회에 실패함 | 빈 목록으로 처리하지 않는다. 실패한 조회를 다시 할 수 있게 한다. 자동 복원 대상이 그사이 휴지통으로 이동했으면 활성 목록을 한 번 다시 확인한다. 모델 조회만 실패한 경우 저장된 대화는 읽을 수 있게 한다. |

## 구현 순서

1. **자동 복원과 사용자 선택을 구분한다.** 권한 확인 후 최근 목록과 모델 조회를 독립적으로 진행한다. 첫 활성 목록 응답에 자동 복원 대상 ID를 함께 제공한다. 기존 계정·보관 상태 필터와 인덱스를 이용하여 첫 페이지 밖의 대화도 찾고, 목록에 선택 항목을 중복 없이 표시한다. 본문을 읽는 동안에는 로딩 상태와 접근성 안내를 유지한다. 전송은 대상과 모델이 정해진 뒤 허용한다. 로딩 중에 ‘새 대화’나 다른 대화를 직접 고르면 그 선택이 우선이며, 늦게 온 자동 복원 응답이나 모델 기본값이 이를 덮지 않게 한다.
2. **미저장 새 대화를 한 경로로 처리한다.** 빈 계정의 첫 화면과 명시적 ‘새 대화’에서 같은 화면 상태를 사용한다. 저장된 대화 ID가 없으므로 이름 변경·휴지통 조작은 표시하지 않는다. 앞 대화의 스트리밍 표시와 화면 갱신만 분리하고, 이미 접수한 작업은 서버에서 계속한다. 자동 복원 대기 중 ‘새 대화’를 명시하면 목록을 기다리지 않고 작성할 수 있다. 초안 상태에서 다시 접속하면 서버의 실제 대화 목록을 기준으로 진입한다.
3. **첫 접수를 한 번에 저장한다.** 신규 대화 전용 첫 전송 API인 `POST /api/ai/conversations/first-turn`을 추가한다. 기존의 로그인·권한·CSRF와 텍스트·모델·추론 검증을 재사용한다. 대화 행, 선택한 모델·추론, 첫 사용자 메시지, 응답 자리와 큐 작업을 같은 SQLite 쓰기 트랜잭션에 넣고 성공하면 대화 ID와 작업 ID를 반환한다. 저장 함수가 하나의 DB 연결을 공유하도록 구성해 기존 보관·요청 한도와 장비관리 큐 규칙을 한 곳에서 적용한다. 기존 대화의 후속 전송과 관리자 모델 시험은 각자의 기존 경로를 사용한다.
4. **중복 전송과 응답 유실을 처리한다.** 보내기·Enter가 같은 첫 전송에 대해 한 개의 접수 키를 사용하도록 하고, 접수 여부가 불명확하면 보낸 본문·모델·추론과 원래 키를 유지한다. 서버는 새 대화 ID를 발급하기 전에 기존 작업의 소유자, 계정, 용도와 요청 내용을 확인한다. 동일 요청은 이미 접수한 대화·작업 ID를 반환하고, 같은 키에 다른 내용은 거절한다. 새로고침은 읽기만 수행한다. 사용자가 전송 대기 중 새로 입력한 문구는 앞 요청의 접수 응답이 지우지 않게 한다.

## Staging 합격 기준

| 시험 | 관찰할 결과 |
|---|---|
| 목록·본문 응답을 각각 지연, 실패, 재시도 | PC와 좁은 모바일의 최초 렌더부터 관찰한다. 기존 대화의 제목·본문 앞에 새 대화 제목이나 환영 카드가 보인 프레임이 0개다. 조회 실패는 재시도 가능한 오류로 표시한다. |
| 새 계정, 과거 빈 대화, 휴지통, 여러 페이지의 이력 | 각 계정에서 올바른 활성 대화를 고른다. 직접 선택한 과거 빈 대화에서는 해당 ID로 이어 쓸 수 있다. |
| 새 대화 반복 클릭, 입력만 하기, 모델·추론 변경, 전송 전 새로고침 | 대화 생성·전송 요청 0회, 새 대화·메시지·큐 작업 0건이다. 기존 대화에서 진행 중인 작업이 계속된다. |
| 정상 첫 전송, Enter와 버튼 연타, 접수 후 응답 유실·재시도 | 같은 요청당 새 대화 1건, 첫 사용자 메시지 1건, 큐 작업 1건이다. 저장된 모델과 추론이 일치하고 후속 질문은 같은 대화로 간다. |
| 빈 입력, 사용할 수 없는 모델, 요청·보관 한도 초과, 트랜잭션 중 오류 | 이번 시도로 저장된 대화·메시지·작업은 모두 0건이다. 접수 이후의 모델 오류는 저장된 대화에서 원인을 확인할 수 있다. |
| 늦은 응답, 다른 탭의 휴지통 이동, 계정 전환, 한글 입력 | 예전 선택의 본문이 새 화면을 덮거나 다른 계정에 노출되지 않는다. 기존 Enter 설정·한글 조합·접수 중 후속 입력을 유지한다. |
