# 메뉴별 조작 영역의 유동 배치

나의 장비 후보(002)를 포함한 독립 Staging 묶음을 만든다. 실제 메뉴 경로와 템플릿, 동적으로 생성되는 버튼, 폼·선택 상태의 소유자를 먼저 대조한다. 두 조작이 같은 목록·작업에 속하고 폭이 충분하면 한 줄을 공유한다. 버튼과 입력은 기본 44px, 글자 13px, 그룹 간격 8px와 모서리 8px를 공유한다. 긴 텍스트는 필요한 높이까지 자랄 수 있다. 화면 폭 대신 컨테이너의 가용 폭으로 줄을 바꾼다.

| 화면 | 적용 판단 |
|---|---|
| 나의 결재함 | 신청 3종, 상태 조회, 페이지 이동을 표 위의 한 도구줄에 둔다. 신청 설명·상태 메시지와 상세 대화상자를 보존한다. |
| 라인업 노드 관리 | 카테고리→제조사 선택과 최상위 추가를 같은 도구줄에 둔다. 트리·요약·옵션은 별도 영역을 사용한다. |
| 사용자/마스터 관리 | 일괄 조작과 전역 세션 파기를 구분하고 탭과 해당 목록 조작이 폭에 따라 흐르게 한다. 기존 선택/강조 상태를 살린다. |
| 보안 감사 로그/웹 접근 로그/오류 IP | 조회 조건과 결과 제어를 각 대상에 붙인다. 건수·표시 수·페이지 이동은 결과 근처에 둔다. 트래픽 요약, 정리 확인, 열 선택과 상세 필터의 의미를 보존한다. |
| 통계 대시보드/권한 관리 | 차트의 검색 폼과 선택된 역할의 검색·저장만 공통 규격을 쓴다. 차트와 역할별 상세 구조는 유지한다. |
| 내 정보/AI 연결 관리 | 프로필·환경 설정의 조작과 관리자 연결 목록 도구에 공통 규격을 적용한다. 비밀번호·복구·연결 편집 대화상자는 독립 작업으로 취급한다. |
| 전자결재함/서버 점검/DB 백업 및 복원 | 승인·반려는 각 행에, 점검·복원은 각 확인 절차에 둔다. 같은 단계의 조작에만 규격을 반영한다. |
| 포털/관리자 센터, 기존 장비 메뉴 | 카드 탐색은 기존 공통 카드 규격을 사용한다. 나의·공개 장비와 임시저장함은 검증된 002를 이어받는다. |
| AI 도우미/인증·공지 | 대화·입력·모델 설정의 현재 비율을 살피고 공통 도구줄이 영향을 주는지 검사한다. 독립 인증·안내 경로는 목록 도구가 없다. |

정적 검사는 실행 이벤트·폼 데이터·ID·접근성·기존 정적 계약을 비교한다. Linux의 독립 브라우저에서 합성 데이터로 테마/레이아웃, 데스크톱·중간·모바일, 연속 크기 변경, 열린 메뉴·긴 페이지 번호, 키보드와 기존 조작을 검증한다. 검토용 스크린샷·결과·소스 목록을 Reports에 남긴다. 작업의 도착점은 통합 Staging 후보다.

이행 결과는 [메뉴별 Staging 검증 보고서](../../../../Reports/2026/11/09/003_Menu_Toolbars_Report.md)에 기록했다.
