# 나머지 메뉴의 중복 제목과 공간 정리

사용자가 계획부터 Staging 구현·정적/화면 검증·수정·운영 반영까지 명시 승인했다. 11월 6일 포털·나의 장비에서 검증한 기준을 나머지 로그인 후 메뉴에 확대한다.

1. 실제 메뉴와 하위 경로, Jinja 상속과 접근성 참조를 조사한다. 통계 대시보드, 공개 장비, 나의 결재함, 내 정보, 관리자 센터 및 그 하위 메뉴에서 상단 바와 같은 본문 제목을 제거한다. 상단 바의 고유 제목·이전/상위 이동은 유지한다. 로그인·가입·인증 복구·서비스 점검 공지 같은 독립 화면과 모달·패널의 고유 작업 제목은 유지한다.
2. 일반 작업 화면의 상단 여백은 16px로 통일한다. 주요 검색·동작·현황부터 보여준다. 기존 설명은 본문 끝의 접힌 화면 안내로 보존하며, 작업별 경고와 폼 안내는 해당 위치에 그대로 둔다. 기능·ID·이벤트·권한·데이터 계약은 유지한다. 이미 전용 높이 계산을 사용하는 AI 대화 화면은 그 계약을 유지한다.
3. 후보를 Staging에 작성한다. 정적 검사는 제목 한 번, 유효한 접근성 참조, 기존 동작 영역 보존과 JS/Jinja 구문을 확인한다. Linux 격리 브라우저에서 PC·좁은 폴더블 외부 화면·일반 모바일·태블릿, Standard/Edge 및 라이트/다크를 확인한다. 필터·모달·상세·접힘 안내를 조작하고 스크린샷을 검토해 문제를 수정한다.
4. 검증한 원문과 SHA·스크린샷·복구 사본을 보존한 뒤 운영 소스에 병합·정적 재검사·정확한 후보만 정리·Git 반영한다. 서버의 실행 상태와 활성 AI 요청을 확인하고 백업 후 승인 commit을 적용한다. 운영 메뉴를 읽기 전용으로 검증하고 업무·AI·계정 설정 보존 및 서비스 정상 상태를 기록한다.

외부 의존성과 DB/API 변경은 추가하지 않는다. 운영에서 장비·계정·권한·연결을 저장하거나 삭제하지 않는다.
