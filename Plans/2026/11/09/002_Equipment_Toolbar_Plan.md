# 장비 목록 도구줄의 유동 배치

이번 승인 범위는 계획·Staging 구현·정적 및 스크린샷 검증이다. 나의 장비를 기준으로 같은 목록 부품을 사용하는 공개 장비와 임시저장함도 함께 확인한다.

1. 기본 상태에서 등록/임시저장/CSV, 검색어/검색/조건검색, 이전/건수·현재 페이지/다음을 하나의 도구줄에 배치한다. 넓은 PC에서는 한 줄을 사용한다. 별도 검색·페이지 외곽 박스를 제거하고 개별 입력·버튼·페이지 표시의 높이·글꼴·모서리·간격을 맞춘다. 터치 조작도 고려해 기본 높이는 모든 폭에서 44px로 통일하고 글자가 잘리지 않게 한다.
2. 고정된 'PC/모바일' 기기 판별이나 강제 행 수 대신 실제 가용 폭과 컨트롤의 최소 읽기 폭에 따른 flex-wrap을 사용한다. 좁은 PC·태블릿에서는 두 줄, 폴더블 외부 화면에서는 세 줄이 자연스럽게 구성되도록 한다. 더 좁은 폭·긴 건수·향후 추가 버튼도 순서대로 줄바꿈하고 화면 밖으로 밀리지 않아야 한다.
3. 도구줄은 DOM/탭 순서도 등록→검색→페이지 이동 순으로 맞춘다. 기존 검색 form을 도구줄과 상세 검색을 소유하는 하나의 form으로 구성하고, 검색 외 동작은 모두 type=button을 유지한다. 상세 검색 fieldset과 CSV 펼침 영역은 도구줄 아래 전체 폭을 사용한다. 오류/빈 결과의 aria-live 안내와 공개 목록의 포함 범위 체크박스, 기존 모달은 유지한다.
4. 필터·페이지·URL 복원·임시저장·등록/수정·CSV의 동작 스크립트와 API·권한·DB는 변경하지 않는다. Staging에서 원본 ID·입력·버튼·이벤트를 대조하고, Linux 합성 데이터의 실제 Jinja/JS로 검색·페이지 이동·접힘·모달·키보드 및 1440→820→384→1440의 연속 크기 변경을 검증한다.
5. 320/384/412/640/820/1024/1280/1440px, Standard/Edge·라이트/다크를 확인하고 핵심 화면의 스크린샷과 실측을 보고서에 보존한다. 기존 다른 메뉴와 AI 화면에 스타일이 번지지 않는지 검사한다. 현재 요청은 Staging 검증 완료 상태로 납품한다.
