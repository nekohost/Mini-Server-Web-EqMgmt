# AI 화면 개선1~10 통합 Staging 계획

사용자가 기존 미실현1~9와 새10을 Staging 구현·정적/스크린샷 검증까지 승인했다. 이전 계획의 범위를 승계하고 현행 기능에 병합한다. 운영 root/서버/DB에는 반영하지 않는다.

| 번호 | 구현 범위 |
|---|---|
| 1 | 상단 별 아이콘, 녹색 정상/노랑 자체 큐 선행 대기/빨강 선택 프로바이더의 확인된 응답 불가. 오래된 상태는 확인 중으로 구분한다. |
| 2 | 좁은 폭에서도 좌/우 메뉴 영역 두 줄, 긴 이름 두 줄 초과 말줄임. |
| 3 | 모델/추론 지원의 기본 접힌 summary를 추론 dropdown 우측에 배치하고 세로 여유가 있으면2줄. 펼친 본문은 별도 공간을 사용한다. |
| 4 | 목록/현재 대화 휴지통 이동은 테마에 맞는 빨간 테두리·단색 기호·tooltip. |
| 5 | 휴지통 왼쪽 이름 변경, 본인 대화만 수정하고 수동 제목을 자동 생성으로 덮지 않음. |
| 6 | 목록 하단의 장비관리 전용 도구/계정 저장 문구와 전용 장식·여백 제거. |
| 7 | 포털의 admin_center를 항상 마지막, 다른 메뉴 상대 순서·권한 유지. |
| 8 | 휴지통 목록 상단은 `휴지통으로 보낸 시각부터 30일 내에 복구 가능합니다.` 한 문장. |
| 9 | 휴지통 개별/전체 checkbox·선택 건수·선택 전체 복구/영구삭제·확인/부분 결과/재확인. 현재 불러온 목록만 전체 선택하며 더 보기의 신규 항목은 자동 선택하지 않는다. |
| 10 | 추론/답변의 누적 chunk를 작은 단위로 부드럽게 표시하고 기존 안전 렌더링·최종 원문·오류 상태·스크롤·추론 접힘을 유지. |

## 새10: 출력의 부드러움

우선 서버 delta 전달/브라우저 poll 빈도와 메시지 전체 재렌더링을 읽어 병목을 확인한다. 원문 저장/AI 생성 속도를 바꾸는 기능으로 설명하지 않는다. 프레임 기반 표시 queue와 적응형 처리량으로 긴 응답의 지연을 제한하고 Unicode 문자가 잘리지 않게 한다. `prefers-reduced-motion`에서는 즉시 표시하며 완료/오류/취소·세션 전환·탭 복귀/재접속에서 최종 텍스트를 정확히 일치시키고 timer를 해제한다. 기존 읽는 위치·선택 영역과 안전한 Markdown 렌더링을 보존한다.

## 분담과 상태 계약

GPT-6.1 Sol/Max 하위 작업3개를 사용한다. 화면/포털 담당은 template/CSS/공통 메뉴, 생명주기 담당은 main JS의 이름/선택·단건 처리와 rename backend, 출력 담당은 독립 표시 모듈/Node 검사를 소유한다. 부모는 API의 자체 큐·선택 연결 상태와 통합/검증을 맡는다. 같은 파일을 재복사하거나 다른 담당 영역을 덮어쓰지 않는다.

상태 표시는 서버 권한으로 현재 계정의 선택/대기 이유만 읽는다. 다른 서비스 요청을 제어하거나 타 사용자 신원/내용을 노출하지 않는다. 별도 무제한 probe나 긴 정상 생성의 취소를 추가하지 않고 기존 연결 측정의 유효 시각과 실제 오류를 재사용한다. 녹색은 최근 정상 근거가 있는 경우만 확정하고, 미확인/오래된 상태는 설명을 함께 제공한다.

rename·휴지통은 현재 계정/소유자·Origin/CSRF·revision/operation ID·기한·부분 실패의 기존 계약을 유지한다. 필요 시 전진 호환 최소 schema만 후보에 추가하고 합성 데이터로 이전/보존을 검사한다. 영구삭제 확인 없이 실제 사용 데이터를 처리하지 않는다.

## 검증과 완료 조건

변경 전 root 소스 해시와 기준 파일을 보존하고 후보는 `Staging/20261105-ai-polish`에 둔다. Windows에서는 AST/Node 등 정적/순수 검사를 사용하고 Flask 앱은 기동하지 않는다. 기존 Linux 격리 fixture runner를 확장해 합성 backend/browser 검사를 수행한다. 운영 프로세스·DB·외부 모델/Strata는 호출하지 않는다.

두 테마와320/390/820/1440px, 긴 이름/낮은 높이, 접기/펼치기·초안·읽는 위치·기본 기능 회귀, 별 상태/오래된 상태/회복, rename/동시 변경, checkbox/더 보기/부분 실패/미확인 응답, 유니코드/장문/취소/완료 출력과 viewport overflow를 확인한다. 눈으로 확인할 대표 스크린샷을 보존한다. 정적 그림만으로 스트리밍 부드러움을 검증했다고 주장하지 않고 프레임/시간 기반 증거를 함께 남긴다.

완료는 Staging 구현·검증 완료이며 운영 배포 완료가 아니다. 기존011/013/014/015와 제안 원장에는 이 상태를 명시하고 운영 미반영 이력을 보존한다.
