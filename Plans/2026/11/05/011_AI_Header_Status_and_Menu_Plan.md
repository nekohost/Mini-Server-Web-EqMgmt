# AI 상단 상태 아이콘·메뉴 두 줄 표시 — 미실현 계획

> 후속 상태: 사용자의 추가 구현 지시에 따라 [계획016](016_AI_Polish_Staging_Plan.md)에서 Staging 구현·검증을 완료했다. 아래는 등록 당시 원안이며 운영에는 아직 반영하지 않았다.

사용자는 아래 두 건을 계획으로만 보존하고 구현하지 않도록 지시했다. 007/009/010 Staging 운영 배포와 별개이며 이번 배포에 포함하지 않는다. 현재 공통 상단 바에는 아이콘이 없고 좁은 화면의 좌/우 메뉴가 각각 세 줄이 되는 구조를 확인했다.

## 1. 상단 별 아이콘과 상태 색상

- AI 도우미 앞의 기존 별 아이콘을 AI 화면의 상단 바 제목에도 표시한다. 현재 녹색 계열과 비슷한 밝기·채도의 노랑/빨강을 라이트/다크 테마별로 정한다. 기존 배경 테마는 유지한다.
- 정상 기본 상태는 기존 녹색 계열이다. 자신의 요청이 장비관리 내부 큐에서 다른 사용자/세션의 선행 요청 때문에 대기하면 노란색 계열로 표시한다. 현재 선택한 프로바이더가 실제로 응답 불가임이 서버에서 확인되면 빨간색 계열로 표시한다.
- 큐 상태는 장비관리 자신의 job/resource group에서 판단한다. 다른 서비스의 요청/Strata 전체 큐를 제어하거나 타 사용자의 대화·신원을 노출하지 않는다. 상태별 tooltip/접근 가능한 설명을 함께 제공해 색상만으로 정보를 전달하지 않는다.
- 기존 polling/스트리밍에 서버의 큐 대기 이유·선택한 연결의 상태와 확인 시각을 연결해 실시간에 가깝게 갱신한다. 응답이 오래 걸리거나 생성 토큰이 잠시 없다는 이유만으로 정상 요청을 중단하거나 빨간색으로 판정하지 않는다. 일시적 HTTP 오류와 완전 무응답의 기준·재확인/회복·측정 TTL은 구현 전 검토한다.
- 대기 중인 요청의 연결과 다음 요청용 선택 연결이 다를 때 무엇을 표시하는지 명시한다. 오래된 상태나 확인 중 상태를 정상/완전 장애로 허위 확정하지 않는다. 브라우저에서 비밀 키로 직접 probe하지 않는다.

## 2. 상단 좌/우 메뉴를 좁은 화면에서도 두 줄로 제한

- 현재 넓은 화면처럼 좌측 메뉴 이동 영역과 우측 계정/상태 제어 영역을 좁은 폭에서도 두 줄 배치로 유지한다. 세 번째 메뉴 줄로 밀어내는 wrapping을 하지 않는다.
- 긴 메뉴 이름은 최대 두 줄까지 허용하며 그 범위를 넘으면 `…`로 표시한다. 전체 이름은 title/접근 가능한 이름 등으로 확인할 수 있게 한다. 줄 수 제한과 글자 줄바꿈을 구분해 실제 스마트폰 화면에서 확인한다.
- 메인/이전/상위 메뉴, 계정/로그아웃/테마/세션 제어를 유지하고 중앙 제목과 겹치거나 가로 넘침이 발생하지 않게 한다. 버튼의 클릭 영역과 포커스 표시는 보존한다.
