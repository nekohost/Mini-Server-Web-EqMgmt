## 배치·상태 보존

013의 우측 배치는010 운영 배치의 후속 요구다. 과거의 `추론 아래 → 모델 선택 → 지원 안내` 완료 이력을 소급해서 바꾸지 않는다. 추후 구현에는013의 위치 요구를 적용한다.

두 summary의 글자/행 높이와 추론 label/select·보내기 버튼의 실제 높이를 비교해2줄을 허용한다. 제어 행을 불필요하게 늘리거나 보내기 버튼을 덮지 않는다. 펼친 모델 select/새로고침·지원 사유 본문에는 충분한 공간을 따로 확보한다. 좁은 폭/확대 상태에서 부족한 공간의 줄바꿈·표시 방법은 구현 전 실측해 결정하며 대화 높이 측정·최소 크기·초안/선택/읽는 위치를 보존한다.

## 휴지통 기호와 색상

최근 대화 목록의 각 대화별 **동작 버튼**과 현재 대화 toolbar의 이동 버튼이 대상이다. 보관함 전환 탭이나 영구삭제 버튼으로 의미를 바꾸지 않는다.011의 빨강과 테두리/아이콘의 톤을 통일하고 hover/focus/disabled를 구분한다. 아직 미실현인011의 구체적인 색상을 확정된 운영값으로 기록하지 않는다.

색이 고정된 컬러 이모지에 의존하지 않고 CSS 색상 적용이 가능한 단색 휴지통 기호/기존 아이콘 방식을 검토한다. tooltip과 접근 가능한 이름을 함께 제공하고 목록에서는 대상 대화를 구분한다. 모바일에서는 hover 없이도 조작할 수 있어야 한다. 기존 확인/취소·30일 보관·복구·재이동 날짜 갱신·명시적 영구삭제와 진행 요청 처리 정책은 유지한다.

## 세션 이름 변경 동작

- 편집 기호는 현재 대화의 휴지통 아이콘 왼쪽에 둔다. tooltip/접근 가능한 이름은 `대화 세션의 이름 변경`이다. 기존 제목을 보여 주는 입력과 저장/취소·오류/중복 제출 방지·포커스 복귀를 제공하는 방식을 검토한다.
- 현행 `conversations.title`은 존재하지만 관련 공개 AI route/store에서 별도 이름 변경 기능은 확인되지 않았다. 본인 대화/현재 계정·메뉴 권한·Origin/CSRF를 확인하는 이름 변경 처리/API를 계획한다. 관리자 계정도 타인의 대화 변경 권한으로 확대하지 않는다.
- 서버 제목 길이 제한·빈 값/공백·제어 문자·안전한 텍스트 표시·동시 수정/휴지통 이동·읽기 전용 상태와 감사 기록을 검토한다. 취소/실패가 대화 내용·모델·추론·작성 중 초안을 초기화하지 않게 한다.
- 현재 첫 요청에서는 저장 제목이 `새 대화`이면 입력의 앞50자로 자동 제목을 만든다. **직접 바꾼 이름이 다음 요청의 자동 제목으로 덮이지 않게** 조건을 설계한다. title 컬럼 재사용과 수동 제목 식별/동시성 상태의 추가 필요 여부는 구현 전 판단한다. 지금 스키마를 변경하지 않는다.
- 성공 시 목록·선택 표시·모바일 제목/전체 이름 안내를 일치시킨다. 이름 변경이 AI 요청을 취소/재시작하거나 다른 대화로 전환하지 않게 한다.

## 하단 문구와 추후 검증

현재 `ai-sidebar-footer`의 두 문구를 제거하는 UI 정리다. 내용이 비면 점/장식·전용 여백도 정리하고 목록 스크롤과 하단 접근성을 확인한다.

추후 구현 승인 시320/360/390/430/760/761/820/1440px·두 테마·긴 제목/글자 확대에서 제어의 겹침·잘림·가로 넘침과 대화 높이를 확인한다. 접기/새로고침 중 상태 보존, 휴지통 기호/tooltip·키보드/터치·기존 복구 정책, 이름 변경의 정상/취소/오류·타 사용자 ID/HTML 입력·동시 수정 및 수동 제목의 다음 요청/재접속 후 유지가 검증 대상이다.
