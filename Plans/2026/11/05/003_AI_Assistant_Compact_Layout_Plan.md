# AI 도우미 공간 절약 추가 계획

대화 본문에 사용할 세로 공간을 늘린다. 좁은 화면에서는 현재 세션을 식별할 한 줄만 상단에 남기고, 모델 선택·목록 새로고침·추론 선택은 입력창 하단에 모은다. 좌측 목록이 상시 보이는 넓은 화면에서는 대화창 상단의 중복 제목 영역을 없앤다.

현재 완료된 `Staging/20261105-ai-ux-trash`를 기준으로 세운 후속 계획이다. 기존 Plan 001·002 및 1~7번 구현을 대체하지 않는다. 최초 계획 작성은 문서에 한정했고, 이후 사용자가 기존 Staging과의 병합 구현을 승인했다. 그 후속 실행은 별도 Task/Report 004로 기록하며 기존 계획 작성 기록 003을 구현 이력으로 소급 변경하지 않는다.

## 현재 후보에서 확인한 사항

- `overlay/templates/equipment_ai.html`: `.ai-header`에 세션 제목, `#ai-model-caption`, “내 장비, 더 간편하게”가 있다. 별도 `.ai-model-control`에 “사용할 AI”, 모델 선택, 새로고침과 상태 안내가 있다. 추론 선택은 이미 `.ai-composer-actions`에 있다.
- `overlay/static/css/equipment_ai.css`: 좌측 목록은 화면 너비 760px 이하에서 서랍으로 숨겨진다. 헤더에는 기본 최소 높이 78px, 모바일 최소 높이 70px가 있고, 모바일 서랍의 `top:71px`가 여기에 결합되어 있다. 제목 글자만 숨기면 빈 높이가 남는다.
- 같은 CSS에서 모델 선택은 최대 420px이고, 추론 선택에는 고정 너비가 없다. 추론 옵션의 내용과 브라우저 기본 select 폭이 현재 너비에 영향을 준다.
- `overlay/static/js/equipment_ai.js`의 `modelControls()`는 비활성 추론 옵션에 사유를 이어 붙인다. `#ai-model-caption`·`#ai-model-status`를 직접 참조하고 정상 상태에 “장비 업무 가능”을 쓴다. 마크업 이동·제거와 JavaScript 변경을 함께 설계해야 한다.
- 기존 `screenshots-round7/screen-010.png`와 `screen-015.png`에서 상단 두 영역이 각각 공간을 차지하는 것을 확인했다. 이 이미지는 변경 전 기준이며 신규 배치의 스크린샷이 아니다.

## 화면별 배치

넓은 화면의 대화창은 별도 제목/모델 툴바 없이 대화 본문을 위에서부터 사용한다. 모델·추론 컨트롤은 입력창 아래쪽 한 줄에 놓고 전송 버튼은 끝에 둔다.

```text
[대화 본문]
[메시지 입력 내용                                      ]
[AI 모델 ▾] [목록 새로고침] [추론 ▾]            [전송]
```

위 도식의 `AI 모델`과 `추론`은 실제 구현에서 연결된 라벨과 select로 제공한다. 버튼이나 select 안에 라벨을 합쳐 원래 의미를 바꾸라는 뜻이 아니다.

좁은 화면은 상단을 `[대화 목록] [현재 세션 제목…]` 한 줄로 줄인다. 하단은 남은 폭을 기준으로 자연스럽게 줄바꿈한다. 보통 첫 줄에 모델과 새로고침, 둘째 줄에 추론과 전송을 놓는다. 이는 기존 상단 툴바를 복원하는 것이 아니라 입력창 안에서의 줄바꿈이다. 극단적인 확대에서는 필요한 추가 줄바꿈을 허용하고 화면 전체 가로 스크롤이나 작은 터치 영역으로 회피하지 않는다.

- 상단 제목 표시 여부는 현재 좌측 목록 표시 기준인 760px와 같은 media 조건에 묶는다. 760px에서는 제목/목록 버튼이 보이고 761px에서는 좌측 목록과 선택 강조를 사용한다. 추후 breakpoint를 바꾸면 두 조건을 함께 바꾼다.
- 컨트롤 줄바꿈은 페이지 너비뿐 아니라 사이드바·입력창 안쪽 여백을 제외한 실제 사용 가능 폭으로 결정한다. `min-width:0`, 축소 가능한 모델 영역, 줄바꿈 가능한 컨트롤 그룹을 사용한다.
- 축소 전 추론 너비 W0는 CSS 상수가 아니다. 구현 착수 시 변경 전 고정 후보, Qwen3.8 Flash Next 선택, 폰트 로딩 완료, 데스크톱 기준 화면에서 실제 select 외곽 CSS px를 측정하여 문서와 CSS 너비 토큰에 고정한다. 새 배치가 매번 예전 DOM을 만들거나 옵션의 사유 길이로 상한을 재계산하지 않는다. 이번 정적 검토에서 임의의 px 수치를 확정하지 않는다.
- 새 추론 폭은 표준 단계 및 필요한 기본값 예외의 표시 폭 + 화살표/여백/테두리로 정한다. 비활성 사유를 옵션 이름에 길게 덧붙이는 대신 접근 가능한 별도 지원 안내에서 확인하도록 한다. 비활성 단계 자체를 목록에서 숨기거나 지원하지 않는 단계를 활성화하지 않는다.
- 새로고침은 텍스트 버튼을 유지하고 선택 컨트롤과 공통 높이·폰트 토큰을 적용한다. 전송 아이콘은 기존 의미와 포커스를 유지한다. 새로고침의 로딩 안내는 버튼 안의 같은 폭과 상태 안내를 이용해 줄 흔들림을 막는다.
- 모바일 목록 서랍의 `top:71px`는 새 헤더 높이에 연동한다. 헤더 높이와 서랍 위치를 서로 다른 숫자로 관리하지 않는다. 긴 제목·확대·서랍 열림 중에도 목록 버튼과 첫 항목이 겹치지 않아야 한다. 가상 키보드가 열린 상태에서도 입력창과 전송 조작에 도달할 수 있어야 한다.

## 상태와 기존 기능의 연결

정상 상태의 홍보/가능 문구를 없애되 오류와 실제 제약을 감추지 않는다. 불가 사유·저장 실패·모델 목록 오류는 입력창 가까운 조건부 안내로 표시하고 `role=status`와 `aria-describedby`의 참조가 유효하게 연결되어야 한다. 미지원 모델 전체 안내는 필요할 때 펼쳐 확인할 수 있게 두며 정상 상태의 큰 전용 공간은 두지 않는다.

`#ai-model-caption` 제거 시 직접 접근하는 JavaScript도 함께 정리한다. `#ai-model-status`는 조건부 안내로 바꾸며, 숨긴 빈 요소가 항상 높이를 차지하지 않게 한다. `#ai-model`·`#ai-model-refresh`·`#ai-level`의 안정적인 ID와 이벤트 연결은 유지한다. 컨트롤이 form 안으로 이동하므로 새로고침의 `type=button`을 보존해 의도치 않은 전송을 막는다.

대화 전환·추론 복원·접수된 요청의 모델 동결·다음 요청 설정·대화 전용 모델 제한·휴지통 읽기 전용·복구·응답 스트리밍·초안·표 스크롤·펼친 추론 상태를 보존한다. 너비 변경만으로 컨트롤을 새로 생성하거나 모델 API를 다시 호출하지 않는다. 사용자 제목과 모델 이름은 계속 텍스트로 삽입한다. 서버 권한·세션·큐·DB·감사 기록의 규칙을 바꾸는 작업은 필요하지 않다.

## 향후 구현 순서와 검증 기준

1. 현재 고정 후보와 검증 기록을 보존하고 변경 전 W0 및 대화 본문 높이를 같은 데이터·뷰포트에서 측정한다. 미래 구현 후보의 fingerprint를 새로 남겨 기존 002 성공 근거와 혼합하지 않는다.
2. template의 헤더를 정리하고 모델 컨트롤을 이동한다. JavaScript의 캡션/상태/추론 옵션 표시 계약과 관련 EN 기준 주석을 함께 갱신한다.
3. scoped CSS로 반응형 제목·줄바꿈·공통 크기·너비 상한·서랍 위치를 적용한다. 전역 테마 배경이나 다른 관리 화면의 CSS를 변경하지 않는다.
4. 기존 UI fixture에 요구별 정적/DOM·동작 검사를 추가하고 허용된 Linux 격리 브라우저에서 실행한다. Windows에서 Staging 앱을 직접 구동하지 않는다.
5. 아래 수용 기준을 검증하고 변경 전후 같은 상태의 스크린샷, DOM 치수와 실제 결과를 보고한다.

| 검증 영역 | 수용 기준 |
| --- | --- |
