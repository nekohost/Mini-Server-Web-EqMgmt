# 장비관리 AI 웹 검색 도구와 운영 반영

사용자는 web_search 구현부터 운영 반영까지 명시 승인했다. 기존017의 내부 ID 표시·상태/대화 UX·본인 업무 권한·확인/감사 계약을 유지하면서 공개 웹 검색을 가산한다. 다른 서비스의 모델·큐는 제어하지 않는다.

## 검색 경로·의존성 선택

현재 프로젝트/서버에는 검색 API 설정이나 검색 서비스가 없다. 서버에서 공개 검색 페이지를 읽기 진단한 결과 DuckDuckGo HTML은202 봇 확인, Bing RSS는200이지만 Flask 검색어와 무관한2개 결과였다. 이를 실제 검색 성공으로 채택하지 않는다. 사용 중인 검색 서비스가 있는지 선택 질문을 보냈고, 답변을 기다리면서 API 키/유료 계약 없이 가능한 공식 검색 라이브러리/자가 호스팅 경로의 실제 품질을 검증한다.

외부 검색 의존성은 기존 Flask 환경과 분리한 private Python 환경에 버전을 고정한다. 후보 DDGS는 여러 엔진을 지원하는 공식 공개 라이브러리이며, SearXNG 자가 호스팅은 더 많은 서비스 구성/메모리 관리가 필요한 대안이다. 무의존 HTML/RSS 직접 파싱은 비용이 작지만 이번 실측에서 차단/품질 문제가 확인됐다. 새 계정·유료 API·다른 앱의 인증정보 복사는 하지 않는다. 선정 엔진/버전·패키지/운영 비용과 한계를 결과에 기록한다.

선정: DDGS9.6.1과 primp0.15.0을 포함한16개 binary 패키지를 SHA256 lock으로 고정하고 Yahoo 엔진만 허용한다. 최신 primp2.0.1은 구버전 DDGS의 client impersonation 인수와 맞지 않아 후보 단계에서 발견·분리했다. Brave/Mojeek는 이번 서버에서 결과를 확인하지 못해 fallback으로 사용하지 않는다. Yahoo 경로는 한국어 Samsung S25·서울시청 및 영어 Flask 검색에서 각각5건과 실제 공식 도메인을 확인했다. 공개 검색엔진이므로 차단/변경·혼합된 검색 품질은 실패/출처 안내로 다루며 SLA를 주장하지 않는다. 별도 유료 계약·listener·Flask 환경 변경 없이 검색 전용 subprocess로 동작한다.

## 구현 계약

1. UI에 공간을 적게 쓰는 `웹 검색` on/off 제어를 둔다. 기본은 off이며 검색어가 외부 검색 엔진으로 전송됨을 tooltip/접근 가능한 설명으로 안내한다. 모델/추론처럼 변경은 다음 요청부터 적용하며 접수한 job의 허용값은 immutable route snapshot에 기록한다. 지원되지 않거나 서버에서 비활성인 경우 이유와 비활성 상태를 제공한다.
2. `web_search`는 공개 검색어와 제한된 결과 수만 받는다. 임의 URL fetch·파일·SQL·셸·LAN 주소 접근 도구는 추가하지 않는다. 허용 모델·현재 사용자/계정·AI 메뉴·job/lease·취소/휴지통/만료를 서버에서 재확인한다. off job의 위조 호출은 외부 요청 전에 차단한다.
3. 검색은 기존 DB write transaction 밖에서 수행하고, 별도 프로세스의 제한된 시간/크기·호출 횟수로 web worker의 정상 heartbeat/종료 계약을 유지한다. 검색 timeout은 검색 요청만 제한하며 정상 LLM 생성에 전역 시간 제한을 추가하지 않는다. 검색 실패/빈 결과/일부 결과를 구분하고 실패를 성공으로 꾸미지 않는다.
4. 외부로는 필요한 공개 검색어만 전달한다. 계정/세션/인증·연락처·일련번호/비공개 장비 메모 등을 검색어에 포함하지 않는 지침과 서버 검증을 둔다. 검색 결과는 비신뢰 자료로 취급하며 도구 호출이나 권한·시스템 지침을 바꿀 수 없다. 업무 변경에는 기존 확인이 필요하다.
5. 결과는 제목·공개 HTTPS URL·짧은 요약·검색 시각·검색어/엔진을 포함하고 결과 수/문자 예산을 제한한다. credentials/로컬/비공개 주소·위험 스킴·제어문자 링크를 제외한다. 결과 URL을 서버가 열어보는 기능은 제공하지 않는다.
6. 모델에는 검색 결과의 근거 인용과 불확실성 구분을 지시한다. 화면은 안전한 출처 링크·검색 경과/실패를 보여 주고 HTML을 삽입하지 않는다. 원래 대화·검색/tool 결과·오류는 기존 소유자 저장·감사/문자 예산·휴지통 보존 경로를 따른다. 모델 전환에서도 출처가 유지돼야 한다.

검색 허용 요청에는 최대2회×5건의 출처 JSON과 escape 증가분을 위해 기존 답변 예약에64,000자를 추가한다. 최초32,000자 후보는 최종 경계 검사의48,764자 사례를 수용하도록 보강했다. 기본 보관32,000,000자와 기존 확장32,000,000자는 변경하지 않는다. 실제 저장한 검색 JSON의 증가분만 사용량에 반영하며 다음 추론 단계에서 중복 차감하지 않는다. 휴지통 이동/복구는 사용량을 유지하고 영구삭제/30일 정리 때 실제 출처량을 함께 환급한다. 취소/삭제 이후의 늦은 검색 결과는 writer transaction에서 거부한다.

## 검증·배포

Staging 후보에서 Python AST/JS 구문·backend 통합·검색어/URL/오류/취소/권한/예산·근거 표시의 실제 Linux browser 화면을 검증한다. 실제 공개 검색은 서버에서 짧은 공개 질문으로만 수행하고 실패/캡차 우회는 하지 않는다. 원문·해시를 보존한 뒤 Windows root에 병합·재검증하고 해당 후보만 정리한다. 기존 다른 dirty 변경은 보존하고 scoped commit/push한다.

운영은017과 같은 private 백업·retention 잠시 정지/진행 중 cleanup 정상 종료·active job/orphan guard gate·owned web/worker 정상 전환·같은 commit pull·실제 DB 사본 보존 검사 순서를 따른다. 분리한 검색 runtime은 loopback listener나 공개 엔드포인트를 만들지 않는 방향을 우선한다. 실패하면 승인 코드/설정을 복원하며 최신 대화·삭제 원장·감사를 과거 DB로 덮지 않는다. 운영 실제 검색/답변·출처·모바일/PC·권한과 원장/명세를 확인한 뒤 완료 보고한다.
