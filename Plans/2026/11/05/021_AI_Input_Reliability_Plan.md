# AI 입력과 응답 실패 개선

사용자는 보내기 버튼 전체 클릭 영역 복구, 개인 설정의 Enter/Shift+Enter 동작 선택, nekohost 대화의 실제 실패 원인 개선을 요청했고 계획부터 운영 검증까지 한 번에 명시 승인했다. GPT-6.1 Sol Max 또는 xHigh 하위 에이전트 협업도 승인했다. 기존020 자동 검색·권한/확인·대화/감사·휴지통·프로바이더별 큐와 실패 기록을 보존한다.

| 범위 | 구현·판단 기준 | 검증 |
|---|---|---|
| 보내기 버튼 | 실제 hit-test와 중앙·상하·좌우 클릭으로 원인을 재현한다. 겹친 요소/stacking/scroll 레이아웃을 교정하고 비활성화·중복 접수 방어는 유지한다. | PC/모바일·다크/라이트·동적 입력 높이에서 버튼 내 클릭과 단일 요청 확인 |
| 개인 입력 설정 | 내 정보/개인 설정에서 Enter를 줄바꿈 또는 보내기로 선택·계정별 저장한다. 기본은 줄바꿈. Shift+Enter는 항상 반대 동작이다. 기존 설정의 저장/권한 계약을 우선 재사용한다. | 저장·reload·새 로그인·다른 계정 분리·비정상 입력/CSRF 거부 |
| 키보드 | 한국어 IME 조합 확정 Enter는 전송하지 않는다. 반복 keydown·비활성 버튼·진행 중 요청을 우회하지 않는다. 현재 선택한 키 동작을 입력창에서 안내한다. | 두 설정의 Enter/Shift+Enter·IME·중복/진행 상태 회귀 |
| 실제 응답 실패 | 승인된 Linux의 nekohost 소유 대화/job/감사/worker 기록에서 실패를 분류한다. 실제 재현되는 제어·호환 결함을 수정하고 모델/공급자 제한과 구분한다. | 실패 원인별 회귀와 일반 권한 계정의 실제 모델 응답·종료/예약/guard 해제 |

일반 소스는 `Staging/20261105-ai-input-reliability/`부터 작성한다. 새 외부 라이브러리는 추가하지 않는다. Windows에서는 Flask를 import/구동하지 않고 정적 검사를 수행하며 실제 fixture/브라우저와 운영 실행은 승인된 SSH 호스트 eqmgmt-backup에서 수행한다. 대화 조사 원문과 인증값은 공개 보고서/Git에 넣지 않고 원인·비민감 구조만 기록한다. 요청을 자동 재실행하거나 실패 기록을 성공으로 바꾸지 않는다.

역할은 버튼 hit 영역/CSS, 개인 설정/키보드, 실패 기록 진단으로 나누고 파일 소유권을 고정한다. 루트 에이전트가 실패 수정·통합 검증과 배포를 책임진다. 각 하위 에이전트는 자신의 recorder/profile/context를 확인한다.

실제 진단에서20:59 실패는 검색1회 뒤 모델이 추가2회를 한꺼번에 요청해 총2회 한도와 한 단계1회 제약을 위반한 경우였다. 이후 단계에 남은 실제 검색 횟수를 명시하고0이면 검색 도구를 제거한다. schema/소유자/현재 권한/민감정보 검증을 통과한 검색 전용 batch는 한 finish에서 최대1회만 실제 검색하고, 나머지는 별도 kind의 ‘미실행’ 제어 결과로 상관 ID에 답해 다음 단계에서 남은 예산 또는 기존 근거로 이어간다. 총2회·64K는 유지한다. 검색+업무 변경이 섞인 다중 검색은 I/O 전에 거부해 근거가 덜 확인된 변경 카드를 준비하지 않는다. 실제 검색 오류·검색 금지/권한/민감정보 위반은 기존처럼 중단한다. 두 번의8초 검색을 한15초 finish 요청에 넣지 않는다.

17:33의 과거 ValueError는 기록상 구체적인 스트림 종료 형태를 확정할 수 없다. 별도로 현 SSE parser가 EOF 직전의 명시적 `[DONE]`에 빈 구분 줄이 없으면 실패시키는 경계를 회귀로 검사한다. 정확한 종료 표식이 있을 때만 호환 처리하고 표식 없는 잘린 응답을 성공으로 바꾸지 않는다. 이를 과거 실패의 확정 원인이라고 주장하지 않는다.

사용자는 버튼 문제 환경을 갤럭시 Z 폴드7 외부 화면·확대 없음으로 명확히 했다. 물리 화면 해상도와 브라우저 CSS viewport를 구분하고360/384/412/430px의 모바일 직접 화면·표준/Edge와 축소 높이를 검사한다. 실제 좁은 viewport에서 긴 입력을 포커스한 채 높이가540/576px로 줄면 기존 최소 높이가 전송부를 화면 밖에 남기는 문제를 재현했다. 모바일 composer에 포커스가 있는 동안만 입력 높이와 최소 대화 영역을 이용해 전송부를 보이는 viewport에 맞추고, pointerdown→up 사이에는 크기 재계산을 유예해 누르는 중 버튼이 이동하지 않게 한다. 포커스/키보드 축소 조건 밖과 확대 상태의 기존 최소 높이 스크롤은 유지한다. 특정 삼성 키보드/브라우저의 물리 재현이라고 확대하지 않는다.

변경 schema가 필요하면 추가 방식으로만 적용하고 기존 모든 행과 다른 설정을 보존한다. 운영 전 현재 source/설정/두 DB를 private 백업하고 현재PC 사용자 전용 사본과 SHA 대조한다. idle인 장비 앱 자체 web/worker만 전환하고 새 source의 실제 DB 사본 검증 후 서비스 활성화한다. 정상 생성은 끊지 않으며 Strata/다른 서비스 큐를 제어하지 않는다. 롤백은 이전 코드와 최신 DB를 유지하는 전진 호환 방식으로 한다.
