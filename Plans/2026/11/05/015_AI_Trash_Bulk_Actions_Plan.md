# AI 휴지통 안내·일괄 작업 — 미실현 계획

> 후속 상태:016의 Staging 검증 원안을 보존하고 사용자 명시 승인에 따른 [017 운영 반영](../../../../Reports/2026/11/05/017_AI_Display_Status_Release_Report.md)을 완료했다. 아래 본문은 등록 당시 원안이다.

사용자가 요청한 휴지통 개선2건을 계획으로만 추가한다. 최근 화면 개선 표의 기존1~7번은 유지하고 이번 항목은 **8~9번**으로 이어 붙인다. 실제 구현·Staging/운영 반영과 대화 데이터 변경은 별도 지시 전 시작하지 않는다.

| 표 번호 | 요구사항 | 예정 동작 |
|---|---|---|
| 8 | 휴지통 목록의 안내 문구 축약 | 목록 상단의 중복 `휴지통` 제목/장황한 안내를 정리하고 **`휴지통으로 보낸 시각부터 30일 내에 복구 가능합니다.`** 한 문장만 표시한다. 최근 대화/휴지통 전환 탭은 유지한다. |

## 안내 문구와 기존 정책

현행 `ai-history-title`은 휴지통 탭에서 `휴지통`으로 바뀌며 `ai-trash-help`는 보관·복구·재이동 날짜를 여러 문장으로 설명한다. 휴지통 탭의 목록 상단은 사용자가 지정한 한 문장으로 줄인다. 중복 제목을 화면에서 정리해도 목록의 접근 가능한 이름은 유지한다. 개별 대화 날짜 정보와 영구삭제 확인/오류 안내까지 제거하는 요구로 확대하지 않는다.

표시 문구의 축약이며 실제30일 정책은 변경하지 않는다. 서버가 기록한 이동 시각부터30일 후 자동삭제, 만료 전 복구, 복구 후 다시 이동하면 새 이동 시각부터30일 계산하는 기존 동작을 유지한다. 클라이언트의 날짜나 체크 여부로 보관 기한을 연장하지 않는다.

## 선택과 일괄 작업 UX

- 체크박스는 휴지통 목록에서만 표시한다. 체크박스 조작과 대화 열기를 분리하고 각 대화 제목을 접근 가능한 이름으로 연결한다.
- 상단 체크박스는 선택 가능한 항목의 전체 선택/전체 해제를 수행하며 일부만 선택되면 중간 상태를 표시한다. 초기에는 선택된 항목이 없고 선택0건/빈 목록에서는 일괄 버튼을 비활성화한다.
- 현재 목록은 `더 보기`로 대화를 추가한다. 기본 전체 선택 범위는 **현재 불러온 휴지통 목록**이며 `불러온 N개 전체 선택`처럼 범위와 건수를 표시한다. 아직 불러오지 않은 대화를 몰래 포함하지 않는다. 더 보기로 추가된 대화는 자동 선택하지 않고, 최신 범위에서 다시 전체 선택할 수 있게 한다. 이 범위를 전체 계정의 무제한 삭제 요청으로 해석하지 않는다.
- 목록 재렌더링/갱신 중 유효한 선택은 대화 ID로 유지하고, 복구·삭제·만료 등으로 목록에서 빠진 항목은 선택에서도 제거한다. 탭/계정 전환이나 로그아웃 시 선택을 해제한다.
- 일괄 버튼은 선택 항목만 대상으로 한다. 복구 전 선택 건수를 확인하고, 영구삭제는 선택 건수와 대상 대화를 확인하는 모달 및 명시적인 최종 확인을 제공한다. 취소 시 변경하지 않는다. 영구삭제 버튼은 테마의 위험 색상을 사용하며 기존013 휴지통 이동 아이콘과 동작 의미를 구분한다.
- 처리 중 로딩/진행 건수와 중복 제출 방지를 제공한다. 완료 시 성공·실패·확인 중 건수 및 항목별 사유를 안내하고 목록·선택 건수를 갱신한다. 일부 성공을 전부 성공/전부 실패로 표시하지 않는다. 실패 항목은 다시 확인해 재시도할 수 있게 한다.

## 서버 처리와 실패·복구 범위

현행 공개 route는 대화별 `trash`·`restore`·`purge`와 `lifecycle_revision`/`operation_id` 검증을 사용한다. 추후에는 단건 처리를 유한한 묶음으로 순차 호출하는 방법과 전용 일괄 API를 비교해 선택하되, 항목별 현재 계정/소유자·휴지통 상태·보관 만료·revision·Origin/CSRF·중복 처리 방지 계약을 유지한다. 무제한 병렬 요청이나 장시간 DB 잠금은 피하고 서버가 처리 가능한 묶음 크기를 제한한다. 지금 새 route나 스키마를 만들지 않는다.

선택 이후 다른 탭에서 복구/삭제됐거나 보관 기한이 지난 항목은 서버 최신 상태로 판단한다. 네트워크 단절은 결과 미확인 상태로 구분하고, 같은 작업 ID의 결과를 확인한 뒤 필요한 항목만 재시도한다. 확인하지 않은 작업을 새 ID로 반복 제출하지 않는다. 현재 열려 있는 대화가 대상이면 기존 단건 처리의 읽기 전용/화면 전환·삭제 보호 동작을 유지한다.

복구는 대화를 최근 목록으로 되돌리며 이전에 취소된 AI 요청이나 장비 업무를 재실행하지 않는다. 영구삭제는 기존 대화 저장소의 삭제 범위를 그대로 따르고 독립 감사 기록·운영 백업을 일괄 삭제하는 권한으로 확대하지 않는다. 이 기능은 실제 사용자의 UI 조작으로만 제공하며 AI 모델에 대화 삭제 도구를 추가하지 않는다. 영구삭제 후 앱에서 복구할 수 없다는 기존 확인 문구를 유지한다.
