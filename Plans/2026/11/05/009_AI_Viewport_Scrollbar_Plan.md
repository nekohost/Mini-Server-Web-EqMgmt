# 현재 AI Staging에 화면 높이·스크롤바 개선 병합

사용자는 홀딩했던 항목 중 화면 높이와 스크롤바 두 건만 계획 후 현재 Staging에 병합하도록 승인했다. web_search 가능성 검토·구현은 제외한다. 기존 CSV 팝업·하단 정리/권한/추론·대화/휴지통을 유지한다. 운영 소스·서버 적용은 이번 범위가 아니다.

1. 기존007 후보 원문8개와 baseline/README를 ZIP/해시로 보존한 뒤 같은 `Staging/20261105-ai-csv-popup/overlay`에 가산 병합한다. 이전 검증 결과는 보존하고 새 상태는009로 연결한다.
2. 고정 `100dvh - 116px/100px` 대신 실제 viewport와 내비게이션/컨테이너/하단 여백을 측정한다. 데스크톱620px/모바일550px의 기존 최소 조건을 유지하고, 고정 제어 영역과 읽을 대화 공간도 확보한다. 충분한 화면에서는 남은 높이를 픽셀 단위로 맞추고 문서 세로 스크롤을 제거한다. 부족한 화면/확대·키보드에서는 문서 스크롤을 허용해 내용을 잘라 숨기지 않는다.
3. ResizeObserver·window/visualViewport 변화·폰트 로딩을 animation-frame 단위로 모아서 반영한다. DOM 높이 쓰기는 실제 값이 바뀔 때만 하고 pagehide에서 감시를 해제한다. 입력·모델 선택·대화/표의 스크롤 위치·기존 요청 상태를 초기화하지 않는다.
4. 대화·좌측 목록·추론·표·코드/CSV 미리보기·모달·입력창의 가로/세로 scrollbar를 AI 영역 안에서만 테마 색상/얇은 track/thumb/hover로 통일한다. 숨기거나 드래그 기능을 대체하지 않고 forced-colors에서는 OS 대비 설정을 존중한다. 다른 장비관리 화면·테마 배경은 변경하지 않는다.
5. 기존39개 화면/3043개 검사와 backend 기준을 승계하고 영향을 받는 브라우저 회귀를 수행한다. 신규 viewport 높이/가로폭·실시간 리사이즈·내비게이션 높이 변화·최소 미충족·스크롤 조작/테마/CSV 팝업 유지 여부를 격리 Linux에서 측정한다. 실제 운영 DB/모델은 사용하지 않는다.
6. PC/모바일·라이트/다크의 기본/스크롤/팝업 대표 스크린샷을 직접 검토하고, 최소 충족 시 document scrollHeight와 clientHeight 차이를 근거로 남긴다. 기존007 원본/검증과 현재 통합009 결과를 구분한다.

복귀는 보존한007 후보의 해당 CSS/JS 및 검증 보조를 구조화 편집으로 되돌리는 방법이다. 코드/DB 배포나 전체 저장소 reset은 수행하지 않는다.
