# 메인 포털 관리자 센터 마지막 고정 — 미실현 계획

> 후속 상태: 사용자 추가 지시에 따라 [계획016](016_AI_Polish_Staging_Plan.md)에서 Staging 구현·실제 포털 화면 검증을 완료했다. 아래는 등록 원안이며 운영에는 반영하지 않았다.

메인 포털에서 **관리자 센터는 항상 마지막 메뉴로 표시**한다. 나의 결재함·AI 도우미 및 앞으로 추가되는 메뉴도 관리자 센터 앞에 표시되어야 한다. 이번에는 계획만 등록하며 실제 구현·Staging/운영 반영은 별도 지시 전 시작하지 않는다.

| 항목 | 향후 적용 기준 |
|---|---|
| 대상 | 메인 포털에 표시되는 메뉴 카드의 순서 |
| 관리자 센터 식별 | 표시 이름이나 생성 순서 대신 기존 `MenuCode=admin_center` 사용 |
| 순서 | 권한에 따라 표시할 메뉴 중 관리자 센터를 마지막에 배치하고 나머지 메뉴의 상대 순서는 유지 |
| 신규 메뉴 | 나중에 추가되거나 정렬값이 큰 메뉴도 관리자 센터 앞에 표시 |
| 권한 | 관리자 센터를 볼 수 없는 계정에는 기존대로 표시하지 않음 |
| 범위 | 관리자 센터 내부 메뉴와 다른 화면의 공통 카드 정렬에는 영향이 없도록 제한 |

현행 메인 포털은 `/api/portal/menus` 응답을 `MenuCards.render`에 전달하며 별도 포털 정렬을 하지 않는다. 공유 renderer에는 관리자 센터 내부 메뉴용 `orderAdmin`이 있으므로 그 정렬 규칙과 혼동하지 않는다. 구현 시 포털의 메뉴 수집·권한 필터링 이후 안정적인 마지막 배치 규칙을 적용하는 위치를 검토한다. DB 정렬값만 크게 올리는 방식으로 영구 보장을 대신하지 않는다.

비동기 메뉴 로드·새로고침 후에도 같은 규칙을 적용하고 카드 누락·중복을 만들지 않는다. 실제 DOM 순서와 화면·키보드 이동 순서가 일치하도록 하며 CSS 표시 순서만 바꾸는 방식은 피한다. 기존 메뉴명·경로·권한 검사는 유지한다.

추후 구현 검증에서는 관리자/일반 사용자, 현재 메뉴와 신규 메뉴 추가, 관리자 센터가 없는 목록·단일 메뉴·빈 목록, 재로드, PC/모바일 및 두 테마를 확인한다. 나의 결재함·AI 도우미가 관리자 센터 앞에 있고 나머지 메뉴의 상대 순서가 유지되는지, 관리자 센터가 마지막 DOM 카드인지 확인한다.
