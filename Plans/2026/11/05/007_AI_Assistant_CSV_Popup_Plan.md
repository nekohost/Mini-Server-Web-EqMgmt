# AI 하단 정리·요청형 CSV 팝업

사용자는 계획부터 Staging 구현·정적 및 스크린샷 검사까지 지시했다. 운영 소스 병합·배포·실제 DB 변경은 이번 범위가 아니다. 기준은 운영 반영된 cb1d72c 및 현재 root 파일이며 다른 dirty/후보는 보존한다.

1. 하단의 “등록·수정·신청은…” 상시 문구를 제거한다. 실제 업무 확인 카드와 권한 제약은 유지하고, SYSTEM에서 사용자가 가능 업무를 물으면 현재 허용 도구 범위와 사용자 확인 절차를 설명하도록 명시한다. 매 답변에 긴 기능 안내를 반복하지 않는다.
2. 하단 “파일 첨부·CSV 가져오기” details를 제거한다. CSV 가져오기 및 기존 파일 첨부는 대화에서 정확히 허용한 내부 링크를 눌렀을 때 native dialog로 연다. 파일 첨부도 팝업으로 옮겨 기존 기능을 보존한다. 자동 키워드 가로채기나 임의 모델 HTML/JS 삽입은 사용하지 않는다.
3. CSV 가져오기는 고정 `/assistant?panel=csv-import`, 첨부는 `/assistant?panel=attachment` 링크다. 기존 허용된 CSV 다운로드 링크 `/api/ai/csv/export?scope=my|public`는 다운로드 확인 팝업을 연다. 내보내기 확인 카드/기존 영수증 링크도 같은 팝업을 사용한다. 기존 URL의 의미와 서버 권한 검사는 유지한다.
4. native dialog는 클릭/Enter로만 열며 제목·닫기·Escape·focus 복귀·모바일 내부 스크롤과 결과 안내를 제공한다. 파일은 기존 API로 직접 전송하며 모델 프롬프트에 원문을 넣지 않는다. 1MiB/500행 CSV,10MiB 첨부 한도 및 미리보기 후 명시적 등록을 유지한다.
5. 생성 중 화면 갱신/팝업 닫기·재열기는 재업로드·자동 등록을 유발하지 않는다. 대화 전환/계정 변경/휴지통 이동 때 선택 파일·preview token과 팝업 상태를 비우고 오래된 응답을 무시한다. 처리 결과 유실은 재전송하지 않으며 새 파일 선택/미리보기는 명시 조작으로만 수행한다.
6. Staging overlay에만 구현하고 변경 EN revision을 올린다. 격리 Linux에서 기존 회귀와 CSV/팝업/악성 링크/CSRF·계정/대화 전환 시나리오를 검사한다. Windows에서는 AST/구문/파일 비교만 수행한다. 앱·운영 DB·실모델은 검사에서 사용하지 않는다.
7. PC/태블릿/모바일·라이트/다크의 기본 대화와 요청형 팝업 스크린샷을 생성하고 직접 검토한다. 좁은 화면·키보드·오류/미리보기/완료 안내의 겹침/잘림/가로 넘침이 있으면 Staging에서 보완 후 관련 검사를 다시 수행한다.

서버/모델 연결/큐/기존 대화·v4·삭제 원장/보류 AI-TECHDEBT-001·WebMCP037은 변경하지 않는다. 구현을 철회하면 이번 overlay만 제외하며 기존 운영 코드로 계속 사용할 수 있다.
