# 다중 AI 프로바이더·대화 중 모델 변경 확장 계획

## 1. 판단과 현재 작업 경계

**기존 기능을 확장한다. 전체 폐기·신규 재작성은 필요하지 않다.** 현재 후보는 대화/작업을 장비관리 시스템에 저장하고, 장비 권한·변경 제안/확정·영수증을 별도 Domain에 두며, 모델 호출을 worker에 분리했다. 이 경계를 유지하면서 고정된 연결 설정과 단일 실행 큐를 확장할 수 있다. 모델 호출부 일부는 adapter/dispatcher로 교체하지만 기존 대화·업무·감사 기능을 폐기하는 계획은 아니다.

이번 산출물은 **판단·계획 문서만**이다. Gemini의 005 평가·검증은 완료되었다. 그 원본과 `Staging/20261104-user-ai-assistant/`, 운영 소스/DB/설정은 보존한다. 현재 후보의 기존 68개/45개 시험 통과는 신규 확장이나 005의 추가 지적에 대한 검증 근거가 아니다. 005를 실제 코드와 대조한 008 검토의 선행 보완을 계획에 반영하고, 별도 구현 지시가 있을 때 해당 보완·회귀를 마친 기준선에서 확장한다. 이번 계획 갱신으로 코드 수정이나 운영 병합을 시작하지 않는다.

### 후속 사용자 결정 — 명세 보완만 반영

007 Hermes 비교 이후 사용자가 정한 아래 범위를 이 계획의 최신 기준으로 적용한다. **계획 보완만 수행하며 기능 구현·Staging 반영·운영 병합을 승인한 것으로 해석하지 않는다.** 007은 당시의 비교 기록으로 보존한다.

| 항목 | 최신 결정 | 적용 범위 |
| --- | --- | --- |
| 세션 선택 복원 | 명세 보완에 포함 | 대화 재개 시 마지막 유효한 provider·model·추론값을 복원한다. 기존 세션 선택이 새 대화 기본값보다 우선한다. |

### Gemini 완료 평가에서 반영한 선행 보완

기존 계획은 실패 종결·감사·복귀 원칙은 다루었지만 아래 전역 middleware/준비 단계/최초 사유의 구체적 경계를 빠뜨렸다. | 원본 ID | 기존 계획에서 부족했던 부분 | 반영할 계약 |

005 기준표 중 삭제·관리자 승인/반려, 루프백 전용 AI 서버, MB 단위 보관량 등의 서술은 현 코드/사용자 범위와 다르므로 확장 요구로 채택하지 않는다. 장비 업무는 일반 사용자 범위로 유지하고, 내부 worker API의 루프백 제한과 LAN AI endpoint 연결을 구분하며, 32M+32M는 문자 예산으로 유지한다.

## 3. 용어와 기본 구조

- **프로바이더:** 관리자가 등록하는 하나의 API 연결. 예: Strata PC A, Strata PC B, 다른 로컬 API 서버. 같은 Strata 소프트웨어라도 PC/주소가 다르면 별개 연결이다.
- **모델:** 그 연결이 실제로 제공하는 upstream model ID. 식별은 이름 단독이 아니라 `provider_id + upstream_model_id`이며 같은 모델명이 여러 PC에 있어도 구분한다.
- **자원 그룹:** 실제 동시 실행 한도를 공유하는 PC/추론 backend. 서로 다른 URL이 같은 GPU/서버를 공유하면 같은 그룹에 넣는다. 프로바이더별 큐를 두되 실행 한도는 이 그룹에 적용한다.
- **모델 기능 프로필:** 대화·도구 호출·추론 출력/설정·context·완료 형식의 검증 결과. 목록에 이름이 보이는 것만으로 업무 수행 가능 판정을 하지 않는다.

흐름은 `사용자 모델 선택 → 장비관리 API의 권한/선택 검증 → 요청별 고정 스냅샷 → 내부 자원 그룹 큐 → adapter → 선택한 AI API → 공통 이벤트/장비 도구 검증 → 기존 확인·감사·대화 저장`이다. 브라우저가 로컬 AI 서버에 직접 접속하거나 API 키를 갖지 않는다.

## 4. 관리자 화면 계획

독립된 **관리자 → AI 연결 관리** 화면을 추가한다. 기존 관리자 인증·실제 DB Role 검사·관리 메뉴 권한·CSRF/Origin을 매 요청에 적용하고, AI 일반 사용자 도구에는 이 관리 기능을 포함하지 않는다.

| 기능 | 설정·동작 | 기준 |
| --- | --- | --- |
| 연결 추가/수정 | 표시 이름, adapter 종류, API 기준 주소/포트, 인증 방식, 비밀값, 자원 그룹, 활성 여부, 연결/읽기 제한 | API 기준 주소의 `/v1` 중복 결합을 막는다. 등록만으로 사용자에게 공개하지 않는다. |
| 비밀 관리 | 최초 입력·교체·설정 여부 표시, 원문 재조회 불가 | 권장: 별도 서버 마스터 키로 검증된 암호 라이브러리를 사용해 암호화 저장하고 DB에는 secret 참조를 둔다. 마스터 키는 DB/저장소 밖에서 보관한다. |
| 연결 확인/모델 새로고침 | 고정된 읽기 API로 인증·목록 확인, 마지막 성공 시각·장애 사유 | 목록 조회는 생성이나 모델 다운로드/교체를 뜻하지 않는다. 무제한 자동 탐색·공유 서버 관리 API는 제공하지 않는다. |
| 모델 공개/기능 확인 | 서버 목록에서 모델을 선택해 공개 여부·대화/업무 모드·지원 추론·context 한도 지정 | 자동 발견한 모델은 기본 미공개. 구조화 도구·추론·종료 규약은 별도 시험 후 공개한다. |
| 기본값 | 새 대화의 기본 모델, 선택 가능한 모델 범위 | 이미 접수한 요청이나 기존 대화의 과거 답변은 바꾸지 않는다. |
| 사용 중지/보관 | 신규 접수 차단, 대기 작업의 명확한 중단 처리, 실행 중 작업 정리, 과거 기록 유지 | 논리적 비활성화를 우선한다. 과거 참조가 있는 연결/모델을 물리 삭제하거나 다른 연결로 몰래 바꾸지 않는다. |
| 상태·감사 | 그룹별 내부 대기/실행 수, 연결·모델 공개·키 교체·설정 revision 이력 | 장비관리 자체 상태만 표시한다. 다른 서비스의 요청 목록/취소/순서 제어는 하지 않는다. |

관리자 수동 모델 등록은 기본 경로가 아니다. ‘수동 모델 등록 사용’을 선택한 연결에 한해 model ID·표시 별칭·기본 모델을 등록하도록 계획한다. 모델 목록 API가 없거나 자동 조회로 제공 모델을 확인할 수 없는 경우의 보조 경로이며, 수동 등록 자체가 도구/추론 기능 검증 완료를 뜻하지 않는다.

**고급 연결 설정 UI는 보류한다.** 추가 헤더, 자유로운 요청 옵션/추론·템플릿 body, 사용자 지정 API 방식 편집은 향후 별도 지시 대상이다. 1차 연결에는 검증된 adapter의 기본 규약/프로필을 사용하며, 기본 연결 등록과 서버 내부의 안전한 프로토콜 처리를 고급 커스터마이징 기능으로 확대하지 않는다.

암호화 저장에는 현재 requirements에 없는 암호 라이브러리 추가가 필요하다. 직접 암호 알고리즘을 작성하지 않는다. 추가 의존성을 피하는 대안은 `secret_ref`를 보호된 환경/credential 파일에 연결하고 UI에서는 참조만 선택하는 방식이다. 이 대안은 키 추가/교체 때 운영자의 파일 설정이 필요하므로, 화면에서 키까지 관리하려는 목적에는 암호화 저장이 더 적합하다. 키 유실·교체·백업 복구 절차도 구현 범위에 포함한다.

연결 주소·키·기능 프로필은 revision별로 고정한다. 수정은 새 revision을 만들고 신규 요청부터 사용한다. 대기 요청의 구 revision이 폐기되면 사유와 함께 중단하고 재선택하도록 하며, 실행 중 요청은 기존 스냅샷/비밀 참조로 종료 보고를 수용한다. 기존 요청이 정리될 때까지 필요한 구 credential을 보호해 유지한다. 실제 upstream 키가 즉시 폐기된 경우에는 해당 요청의 오류·중단을 기록한다.

## 5. 모델 목록과 API 호환

| 연결 종류 | 목록/생성 경로의 후보 | 계획 |
| --- | --- | --- |
| Strata 두 PC | 기존 연동의 `/v1/models`, `/v1/chat/completions` | 1차 지원. Strata 전용 옵션은 해당 adapter에 한정한다. 실제 두 서버의 주소·버전·목록/도구 동작은 구현 시 확인한다. |
| 다른 OpenAI 호환 로컬 서버 | `/v1/models`, `/v1/chat/completions` | 1차 공통 adapter. llama.cpp 계열·다른 호환 서버를 연결하되 서버/모델별 지원 옵션을 검증한다. OpenAI 유료 서비스 연결을 전제로 하지 않는다. |
| Ollama 등 별도 규약 | 호환 API 사용 가능 여부 확인; native 방식은 `/api/tags`, `/api/chat` 등 | 호환 경로로 충족되면 공통 adapter를 사용한다. 필요할 때 NDJSON/종료/도구·추론 형식을 변환하는 native adapter를 추가한다. 설치되어 있다고 단정하지 않는다. |
| 지원 adapter가 없는 API | 임의 URL/동적 코드로 처리하지 않음 | 명시적 adapter 개발·검증 전에는 ‘미지원’으로 표시한다. 모든 AI가 즉시 연결된다고 약속하지 않는다. |

공식 자료에서 LM Studio는 `/v1/models`에 JIT 사용 시 다운로드 모델도 포함될 수 있다고 설명하며, llama.cpp 직접 서버의 목록과 router 목록도 의미가 다르다. 따라서 목록 응답을 ‘현재 GPU에 올라와 즉시 사용 가능한 모델’로 해석하지 않는다. 제공 상태·관리자 공개·호출 가능 여부를 구분하고 embedding/TTS 등 비대화 모델은 일반 대화 선택에서 제외한다. 근거: [LM Studio 모델 목록](https://lmstudio.ai/docs/developer/openai-compat/models), [llama.cpp server 문서](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md).

모델 목록은 장비관리 backend가 받아 정규화·제한·캐시한다. 기본 제안은 60초 캐시와 관리자 수동 새로고침이며, 사용자 화면을 열 때마다 모든 PC를 전수 조회하지 않는다. 실패하면 마지막 확인 시각/상태를 표시하고 자동으로 다른 프로바이더를 선택하지 않는다. stale 목록으로 접수할 수 있는 유효기간과 장애 시 차단 정책을 정하고 접수·실행 시 공개/호출 가능 상태를 재검증한다. 사용자에게는 이름·기능·상태·선택 ID만 보내고 upstream 주소/키/파일 경로·원시 metadata는 보내지 않는다.

**기본값은 자동 조회·자동 선택이다.** 관리자가 사용을 허용한 자동 조회 목록에서 새 대화의 초기 모델을 정한다. 우선순위는 유효한 관리자 기본 모델 → 사용 가능한 모델이 하나이면 그 모델 → 여러 개이면 관리자가 정한 공개 순서상 첫 유효 모델이다. 실제 선택을 화면에 표시하고 사용자는 목록에서 다른 모델을 고를 수 있다. 유효한 후보가 없으면 선택 불가 사유와 재조회/재선택 경로를 제공한다. 자동 조회 실패만으로 수동 등록을 강제하거나 요청을 다른 서버로 자동 재발신하지 않는다.

로컬 `C:/Project/local-llm-manager`는 별도로 만든 앱이며 상용 LM Studio 제품과 동일하다고 가정하지 않는다. 현재 참고 소스 `app/core.py`는 엔진을 `127.0.0.1`에 바인딩한다. 이 실행 설정은 다른 PC의 장비관리 backend가 직접 호출할 수 있는 LAN 공개 상태의 증거가 아니다. 연결할 실제 LAN 서비스/프록시가 있는지 구현 시 확인하며, 이번 계획에서 그 앱의 바인딩·방화벽·엔진 실행 설정을 변경하지 않는다.

추론은 프로필별 지원값만 노출한다. 기존 Qwen/Strata의 낮음=none·중간=medium·높음=xhigh 매핑은 해당 프로필에 유지하고 다른 모델에 그대로 강제하지 않는다. 미지원은 ‘추론 설정 미지원’, 도구 미지원은 ‘대화 전용’으로 설명한다. 실제 지원하지 않는 추론을 표시하거나 일반 텍스트를 도구 명령으로 해석하지 않는다. [Ollama 호환 문서](https://docs.ollama.com/api/openai-compatibility)도 추론값이 모델에 따라 달라진다고 명시한다. 이는 설치된 서버 버전의 지원을 보장하는 근거가 아니므로 실서버 확인이 필요하다.

## 6. 사용자 모델 선택과 같은 대화 이어가기

대화 상단에 `프로바이더 → 모델` 선택을 제공하고, 같은 이름이면 `Strata PC A / 모델명`, `Strata PC B / 모델명`처럼 구별한다. 모델별 ‘장비 업무 가능/대화 전용’, 지원 추론, 연결 상태를 표시한다. 답변마다 실제 사용한 모델 출처를 남기며 과거 답변의 라벨은 바꾸지 않는다.

**세션 재개 명세:** 대화별로 마지막 유효한 `provider_id + model_id`와 사용자 추론 선택을 저장·복원한다. 기존 세션의 저장 선택이 새 대화 자동 선택/관리자 기본값보다 우선하며 다른 사용자·다른 세션으로 전파하지 않는다. 재개 시 현재 공개/권한/기능 프로필을 다시 확인하고, 신규 요청은 현재 유효한 연결 revision/비밀 참조를 사용한다. 이미 접수된 요청의 스냅샷과 과거 답변 출처는 바꾸지 않는다. 추론 미지원·모델 제거·연결 중지 등으로 이전 선택을 복원할 수 없으면 이전 선택과 사유를 표시하고 재선택을 안내한다. 기존 세션을 다른 provider/model로 몰래 대체하지 않는다.

| 상황 | 처리 원칙 |
| --- | --- |
| 대기/실행 작업이 없는 대화에서 변경 | 대화 ID·소유권·기록을 유지하고 다음 요청부터 새 모델을 사용한다. 새 대화를 강제하지 않는다. |
| 이미 접수됐거나 추론/도구 단계가 실행 중 | 현재 요청 전체는 고정된 모델로 처리한다. 선택 변경은 ‘다음 요청부터 적용’으로 표시한다. 대기 요청도 접수한 선택을 유지하며 취소 후 새 요청을 만들어야 바뀐다. |
| 여러 도구 단계로 이어지는 한 요청 | 모든 단계에 같은 provider/model/config revision을 사용한다. 중간 tool call을 다른 모델에 넘기지 않는다. |
| 준비 중인 장비 등록/수정 업무 | 서버에 저장한 초안·선택 항목·미입력 필드·사용자 수정·출처를 다음 모델에 전달한다. 모델의 내부 기억이나 KV cache 전달을 전제로 하지 않는다. |
| 미확정 확인 카드가 있는 상태 | 카드의 내용·서명·소유권·기한·현재 업무 revision은 유지한다. 모델 변경만으로 실행/재실행하지 않는다. 내용 변경을 요청하면 새 카드를 만들고 대체 대상의 이전 카드를 명시적으로 무효화한다. |
| 이미 적용한 업무 | 실제 서버 영수증을 인계 자료에 포함한다. 모델이 바뀌어도 같은 작업을 다시 실행하지 않는다. |
| 대화 전용 모델로 변경 | 대화는 이어갈 수 있으나 장비 업무 제안은 중지하고 지원 모델 선택/기존 수동 화면을 안내한다. 권한을 넓히거나 텍스트를 실행으로 우회하지 않는다. |
| 작은 context의 모델로 변경 | 최근 대화+검증된 업무 상태+출처 있는 요약을 길이에 맞춰 구성한다. 포함하지 못한 자료가 있으면 알리고 필요한 정보를 재질문한다. 원본 기록은 보존한다. |
| 연결 유실로 기존 요청의 종료를 모름 | 해당 대화와 기존 자원 그룹의 해당 슬롯에 ‘중단·종료 확인 필요’ 잠금을 유지한다. **다른 자원 그룹의 다른 대화는 처리할 수 있다.** 다른 모델로 자동 재발신하지 않는다. |

대화/업무 인계의 핵심은 `conversation_id`와 독립적인 서버 기록이다. 다음 모델에는 사용자·최종 답변, 서버가 확인한 변경 결과, 미확정 카드 요약, 출처를 둔 작업 초안을 전달한다. 이전 모델의 원시 추론·provider session ID·인증정보·해결되지 않은 tool call/도구 ID는 넘기지 않는다. 인계 자료는 정책 지시가 아닌 데이터로 취급하고, 장비 권한과 도구 allowlist는 매번 서버가 다시 제공·검사한다.

현재 최근 8개 메시지만 사용하는 context 구성은 장기 작업 인계에 부족하므로 `ContextBuilder`와 최소 `task_drafts`를 추가한다. 초안은 정규화·검증한 필드와 원문 message ID, 수정 revision을 보관하고 모델 추측은 확정 사실과 구분한다. 요약은 원문/영수증을 대체하지 않으며, 모델마다 답변 품질이 같거나 모든 과거 내용을 무제한 기억한다고 보장하지 않는다. draft/summary도 기존 저장 예산과 별도 크기 상한에 포함해 새로운 무제한 저장 경로를 만들지 않는다.

초안/요약을 영속 저장하는 경로를 추가할 때에는 문자 사용량과 완료 예약식도 함께 확장한다. 기존 426,144자 출력 예약만으로 새로운 저장 경로가 자동 충당된다고 가정하지 않는다. context는 대상 모델의 실제 token 한도와 완료 여유를 기준으로 구성하며 한도가 불명확하면 검증한 보수적 프로필을 요구한다. 문자 수를 token 수와 같다고 취급하거나 모든 모델에 기존 65,536 context를 강제하지 않는다.

모델/프로바이더 비활성화와 장비 업무 쓰기 비활성화는 구분한다. provider가 오프라인이어도 이미 만들어진 유효한 확인 카드는 모델을 다시 부르지 않고 기존 서버 권한·만료·revision 조건으로 확인할 수 있다. 전체 AI 쓰기 기능이 닫히거나 카드가 취소/만료된 경우에는 기존 규칙대로 실행하지 않는다.

## 7. 내부 큐와 실패 처리

장비관리 시스템에서 접수한 요청만 제어한다. PC A와 PC B가 독립된 추론 자원이라면 각각 기본 동시 1개를 허용해 합계 2개 처리가 가능하다. 같은 PC/backend를 공유하는 연결은 같은 그룹 한도를 공유한다. 실제 용량을 확인하기 전에는 임의로 동시 한도를 높이지 않는다.

DB의 전역 단일 실행 index를 그대로 둔 채 worker만 늘리지 않는다. 다음 버전에서는 그룹/슬롯 lease와 작업 state를 **같은 짧은 writer transaction에서** 확보·반납하도록 변경한다. lease가 만료돼 보인다는 이유로 실행 요청을 다시 보내지 않으며 `recovery_required`도 해당 그룹 슬롯을 점유한다. 모델 네트워크 대기 동안 SQLite writer를 잡지 않는다.

기존 worker를 기반으로 제한된 dispatcher/네트워크 실행자를 두고, 최종 claim 권한은 서버 DB 슬롯으로 결정한다. 연결 추가를 위해 관리자에게 매번 수동 프로세스 실행을 요구하지 않도록 활성 연결을 갱신하되, worker/서버의 프로토콜 버전 불일치는 fail-closed로 중단한다. 그룹 안에서는 접수 순서와 사용자 간 공정성을 유지하고, 도구 후속 단계는 기존 방식처럼 뒤로 재진입한다. PC A 장애/긴 응답으로 PC B의 큐가 막히지 않게 한다.

기존 사용자별 열린 작업 2개·전체 20개·분당/일별 제한과 저장 예약은 계정 전체에 합산한다. 모델별로 나눠 우회하지 못하게 한다. 같은 대화에서는 동시에 한 요청만 생성하고, 변경 확인은 기존 권한/영수증 transaction을 따른다. 모델 기능 확인을 위한 합성 생성 시험도 내부 슬롯을 사용하며 관리자 시험으로 동시 한도를 우회하지 않는다.

연결/형식/도구 오류는 기존의 중단·사유 보존 계약을 유지한다. 자동 provider 대체나 다른 모델로의 무단 재시도는 제공하지 않는다. 외부 서비스가 같은 AI 서버를 사용해 혼잡해지면 그 응답을 처리할 뿐, 외부 요청을 취소·재정렬하거나 서버 전체 idle을 요구하지 않는다.

### 작업 준비 실패·점검·취소의 수명주기 보완

**준비 실패(S03):** 슬롯 선점부터 actor/도구/context·연결 revision/비밀 참조·모델 기능 검증과 worker 응답 생성까지 종결 책임을 지정한다. 예외 안전망은 actor 검사 한 함수에만 두지 않는다. 외부 추론 발신 전임이 확인되는 예외는 허용된 사유 코드로 failed 처리하고, 미확정 카드·완료 예약·그룹 슬롯을 함께 정리한다. 외부 발신/종료가 불명확한 상태와 구분하고, 오래됐다는 이유만으로 lease를 빼앗거나 자동 재발신하지 않는다.

**점검(S02):** `DRAINING`/`RESTORING`/`RECOVERY`에서는 신규 대화 업무·claim·새 모델 호출을 막는다. 인증된 기존 lease의 heartbeat/event·완료/정리 보고가 브라우저 로그인 유무 때문에 전역 게이트에서 먼저 차단되지 않도록 별도 계약을 둔다. `/internal/ai/` 전체를 무조건 통과시키지 않고 고정 메서드·경로·worker 인증·현재 lease·허용 상태를 확인한다. 점검 중에는 업무 DB를 열거나 도구/변경 제안·확정을 실행하지 않으며, 안전하게 접근 가능한 별도 AI DB에만 중단/종료 정보를 남긴다. 자체 AI DB까지 교체하는 복구는 먼저 신규 접수 중지→자체 응답 정리/종료 확인→일관된 백업/교체 순서로 조율하고, 이전 epoch/lease의 지연 보고를 새 작업에 적용하지 않는다.

**최초 사유(S04):** 작업별 최초 오류 코드/메시지는 후속 취소·오프셋 오류로 덮어쓰지 않는다. 후속 진단은 크기가 제한된 감사 사건으로 기록한다. 권한 철회/점검 차단 등 실제 실행 금지는 표시 사유 보존과 독립적으로 계속 강제한다. `cancel=true`만으로 조각이 저장됐다고 가정하지 말고 수락 여부/서버 확인 offset으로 동기화한다. 중단 신호 뒤 일반 출력 조각 재전송은 멈추되 자체 요청의 종료 추적·필요한 heartbeat·최종 보고는 유지한다. 다른 서비스의 생성은 중단하지 않는다.

## 8. 데이터·API 변경 초안과 안전 경계

아래 이름과 경로는 구현 계약 초안이며 현재 생성된 테이블/API가 아니다. 별도 AI DB의 다음 합의 버전으로 가산 이전하고 업무 DB의 장비 schema는 변경하지 않는 방향이다. 005 검토가 schema를 변경하면 그 이후 버전에 맞춰 번호·쿼리를 다시 확정한다.

| 영역 | 추가·변경 초안 |
| --- | --- |
| 연결 설정 | `ai_providers`, 불변 `ai_provider_revisions`, 비밀 참조·공개/중지 상태 |
| 모델 | provider+upstream ID가 유일한 `ai_provider_models`, 기능 프로필 revision·공개 여부·최근 확인 시각 |
| 실행 자원 | `ai_resource_groups`, 슬롯별 `ai_resource_leases`, 해당 그룹의 단일/제한 실행과 종료 불명확 잠금 |
| 대화·작업 | 대화의 다음 기본 선택/revision, jobs의 선택 모델·연결/프로필 revision·그룹·추론 실제 적용값·출처 스냅샷 |
| 인계 | `ai_task_drafts`/한도 있는 요약과 원문·영수증 참조, 모델 변경 사건. 기존 메시지·제안·확정 결과는 보존 |
| 관리자 API | `/api/admin/ai/providers`, 연결별 수정/확인/모델 갱신/공개/중지. 모든 변경은 실제 admin+CSRF+Origin+revision 검사 |
| 사용자 API | `/api/ai/models`로 허용된 목록만 반환. 대화 기본 선택 변경, turns에 서버 선택 ID 추가. URL/key/raw 도구/역할은 받지 않음 |
| 내부 worker API | claim 결과와 event/finish를 고정된 route/config revision·그룹/슬롯 lease에 결합. 다른 작업/모델 결과를 대입하지 못함 |

멱등 접수 hash에는 모델 선택과 추론/설정 revision을 포함한다. 같은 키로 다른 모델을 보내면 충돌로 처리하고 기존 요청을 새 모델 요청으로 변조하지 않는다. 여러 탭의 대화 기본 선택 변경에는 revision 검사를 적용하며, 실제 turns는 접수한 선택을 명시적으로 고정한다.

관리자 입력 URL도 서버가 제한한다. 로컬 LAN 사용 목적이므로 사설 IP 전체를 일괄 금지하지 않고 **운영자가 승인한 host/IP·포트·대역**만 허용한다. 브라우저/모델 입력으로 주소를 바꾸지 못하게 하고, 자격정보 내장 URL·redirect·환경 proxy·메타데이터/관리 포트·허용 외 loopback/link-local 등을 차단한다. 접속 시 실제 목적지를 검증·고정해 DNS 변경 우회를 막으며, HTTPS 인증서 검증을 끄지 않는다. `/v1` prefix와 고정 API 경로만 adapter가 조합하고 임의 관리·download/load/unload/전역 취소 경로는 제공하지 않는다.

장비 업무·개인 대화가 어느 PC로 전달되는지 관리자가 공개 범위로 통제하고 사용자가 선택한 연결을 화면에 표시한다. 프로바이더 변경으로 정보가 외부 서비스로 자동 전송되지 않는다. 업무/대화/오류와 사용 모델·설정 변경 이력은 감사에 남기고, API 키 등 재사용 인증 원문은 기존 지문 보호 정책을 유지한다. 신규 관리자 키 입력 경로도 기존 전역 logger의 원문 기록 전에 보호해야 한다.

### 파일·CSV 감사와 로그 훅의 실패 격리(S01)

AI 경로의 업무 내용 전체를 감사에서 제외하지 않는다. 질문·추론·답변·제안·확정/오류 및 CSV 검증/실행의 구조화된 업무 내용은 보존한다. binary/multipart wire 본문은 로그 훅이 추가로 읽거나 텍스트로 변환하지 않는다. 검증된 파일명·크기·형식·대상·기존 파일 참조/해시와 성공/거부 결과를 기록하며, 인증/용량 검사 전 거부되어 알 수 없는 값은 미확인으로 남긴다. 거부된 본문을 감사 목적으로 재파싱·전수 소비하지 않는다.

CSV 내보내기처럼 큰 결과는 원문을 접근 로그 문자열로 무조건 복제하지 않고 보호된 감사 원문 저장/참조와 해시·행 수·조회 범위·주체·시각·결과로 추적하는 방식을 명세한다. 이는 결과 원문을 버리는 정책이 아니다. 이미 보호된 원문이 있으면 그 참조를 쓰고, 별도 보존이 필요하면 접근권한·보존기간·물리 저장 예산을 먼저 확정한다. 원문 보존이 필요한 작업에서 공간이 부족하면 성공으로 처리하고 기록을 누락하지 않도록 사전에 거부/사유를 기록한다. 대화의 32M+32M 문자 예산과 감사 파일의 물리 바이트 예산은 구분한다.

감사 metadata 사건 생성과 본문 처리의 예외 경계를 분리하여, 본문 읽기 실패/413/클라이언트 단절/응답 streaming으로 audit 사건 전체가 유실되지 않게 한다. 신규 관리자 키 입력과 모델 목록 등 추가 경로에도 같은 경계를 대조한다. 경로만 보고 `/api/ai/*`를 일괄 제외하지 않는다.

필수 교차 시험은 동일 모델명이 두 provider에 존재하는 경우, 대기/실행/도구 후속/확인 대기 중 모델 변경, 목록에는 있으나 제거된 모델, stale 목록·서버 중지, 설정·키 교체 중 실행, 위조 selection/revision/슬롯 lease, 연결 단절의 무단 재발신 차단, 다른 서비스 요청을 제어하지 않는지, 과거 추론이 새 모델 프롬프트에 들어가지 않는지, 사용량/초안 한도와 계정 변경을 포함한다. 검증 없는 모델을 ‘장비 업무 가능’으로 자동 승격하지 않는다.

008에서 추가한 필수 회귀는 다음과 같다. 기존 fixture의 `after_request_func`뿐 아니라 실제 `maintenance_request_gate`와 인증 진입 순서도 합성 fixture에 연결하고 Linux에서 실행한다. 운영 앱 import/운영 DB 접근으로 대신하지 않는다.

- **감사:** 파일/CSV가 파싱 전에 401/403/413/503으로 거부되거나 연결이 끊긴 경우에도 사건이 남고, logger가 거부 본문을 다시 읽지 않는지 확인한다. CSV 결과의 원문/참조·업무 증거는 보존하며 대화 본문 일괄 제외나 token 원문 노출이 없어야 한다.
- **점검:** 응답 생성 중 NORMAL→DRAINING→RESTORING/RECOVERY 전환, 인증된 기존 lease의 종료 보고, 위조 worker/lease, 점검 중 claim·도구 차단을 검사한다. 업무 DB connect를 실패하도록 주입해 점검 정리 경로가 그 DB를 열지 않는지 확인한다.
- **준비:** slot/claim 직후 actor 조회·도구 목록·context 파싱·provider/key/profile 준비 단계마다 예외를 주입한다. 발신 전 확정 실패는 사유/카드/예약/슬롯이 일관되게 정리되고 다른 그룹의 요청이 진행되어야 한다. 발신 불명확은 잠금을 유지한다.
- **중단 사유:** 첫 크기/권한 오류 뒤 후속 offset 오류·사용자 취소·종료 보고가 이어져도 최초 사유와 실제 차단 상태를 유지한다. 거절 조각의 offset/저장 사용량을 늘리지 않으며, 재접속 후에도 사유가 남아야 한다.

## 10. 이전·복귀와 보류 사항

현재 단일 provider의 환경 설정은 초기 ‘기존 Strata’ 연결로 한 번만 이관하고 평문 비밀은 테이블에 복사하지 않는다. 이미 실행/종료 불명확인 작업은 설정을 추측해 재연결하지 않고 그 작업의 연결을 확인·고정한 뒤 단계적으로 이전한다. 안전한 가산 컬럼/테이블과 새 스케줄러의 index 전환은 접수 중지·진행 작업 확인·백업·합성 이전 검증 뒤 수행한다.

과거 답변에 실제 사용 모델 정보가 남아 있지 않으면 현재 설정으로 소급해 채우지 않는다. ‘이전 연결·모델 기록 없음’으로 보존하고, 신규 요청부터 실제 접수/호출 스냅샷으로 출처를 남긴다.

비상 시 신규 접수/쓰기와 다중 dispatch를 먼저 중지하고 기존 데이터·영수증·감사를 유지한다. **옛 v2 실행 파일로 즉시 되돌리면 전역 단일 index 재생성이 다중 활성 작업과 충돌할 수 있으므로**, 새 schema를 읽을 수 있는 호환 release 또는 검증한 백업 복구 경로를 준비한다. 미종료 자체 요청이 있는 상태에서 index를 강제로 바꾸거나 재발신하지 않는다. 업무 DB만 과거로 돌려 이미 확정된 업무를 지우는 복귀는 금지한다.

지금 필요한 것은 구현 승인 요청이 아니라 확장 방향의 판단이다. 정확한 LAN 연결 목록·버전·자원 공유·키 관리 방식·각 모델의 실제 context/도구/추론 지원은 구현 착수 시 조사·확정할 항목이다. 임의 값·성능·완료 일정을 만들지 않는다. 기존 D07 주석 보류 항목은 별도 사용자 지시까지 유지한다.

추가 헤더·추가 요청 body/생성 옵션·사용자 지정 API 방식 등의 **고급 연결 설정은 사용자 결정으로 보류**한다. 현재 단계의 구현 필수 조건으로 되살리거나 선행 개발하지 않는다. 세션 선택 복원과 자동 기본/관리자 선택형 수동 모델 등록은 계획 명세에만 포함하며, 실제 작업 착수는 별도 지시를 따른다.
