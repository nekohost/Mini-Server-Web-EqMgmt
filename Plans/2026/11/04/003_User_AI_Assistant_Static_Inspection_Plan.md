# 장비관리 AI Staging 정적검사 계획

대상은 `Staging/20261104-user-ai-assistant/`의 15개 후보 파일과 기존 코드의 연결 계약이다. 직전 사용자에게 제시한 F01~F12(기능), Q01~Q15(품질), L01~L08(기본 제한) 총 35개 기준을 임의로 완화하지 않는다.

Task 생성 후 검증 1~8을 순차 수행한다. 후보 SHA256을 기존 검증 JSON과 대조한 뒤 Python AST와 JavaScript 구문을 검사한다. 소스·기존 서비스·시험 fixture를 읽고 정상 경로 및 실패/경합/취소/권한 변경 경로를 추적한다. 소스를 실제로 실행해 얻은 결과처럼 보고하지 않는다.

판정은 정적 충족/부분 충족/미충족/실행 확인 필요를 구분하고, 코드 결함에는 발생 조건·영향·기준 번호·파일/행·수정 방향을 기록한다. P1은 운영 전 필수 수정, P2는 기능/품질의 구체적 결함, P3는 유지보수·낮은 영향의 문제다. 주관적 제안이나 이미 제외한 기능은 결함으로 부풀리지 않는다.

이번 작업은 검토다. Staging/운영 소스·설정·DB·기존 검증 기록을 변경하지 않는다. 동작 시험·실제 Strata 호출·서버 접속/서비스 제어·Git 변경·병합은 수행하지 않는다. 추가 도구 설치나 운영 DB 조회 없이 기존 소스와 표준 정적 검사만 사용한다.

검사 결과는 `Reports/2026/11/04/003_User_AI_Assistant_Static_Inspection_Report.md`에 누적한다. 기존 49개 합성 시험/29개 화면 검사의 통과 기록은 참고 자료이며 이번 정적검사의 합격 근거를 대신하지 않는다. 답변 정확도·응답 지연·운영 부하 등 수치 미정/실행 의존 목표는 별도로 남긴다.

검사 완료: P1 2건/P2 4건/P3 1건. 35개 기준은 정적 충족 24개·부분 충족 10개·미충족 1개다. 후보 15개와 기존 보존 대상 13개 파일의 전후 hash는 동일하다. 소스는 수정하지 않았고 상세 발생 조건·근거 행·수정 방향은 Report에 기록했다. 현재 후보의 운영 병합 판단은 보류한다.
