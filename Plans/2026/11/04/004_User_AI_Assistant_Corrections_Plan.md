# 장비관리 AI 결함 수정 계획

대상은 기존 `Staging/20261104-user-ai-assistant/overlay/`다. 사용자 답변에 따라 이전 감사 로그 전체 제외 권고를 정정한다. 대화·추론·업무 제안/확정·오류와 주체/시각/결과를 감사에 보존한다. session/API/worker/CSRF/확정 token 같은 재사용 가능한 권한값의 원문만 마스킹하고 서버 HMAC 지문으로 연관성을 남긴다. 일반 업무 내용은 일괄 삭제하지 않는다. 참고: [OWASP Logging의 Data to exclude](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html#data-to-exclude)는 사건을 제외하지 않으면서 세션·접근 토큰을 보호하는 지침을 구분한다.

## 수정 범위

1. 전역 접근 로그가 AI 내용은 보존하되 인증/확인 원문은 보호하도록 별도 순수 감사 formatter와 연결한다. HTML의 CSRF 값과 JSON token/lease를 지문 처리한다. 로그 사건 자체를 제외하지 않는다.
2. 유효한 lease로 받은 완료 보고는 전체 구조 검증 후 처리한다. 완료가 확인된 형식/처리 오류는 failed로 마감하고 pending proposal을 중단하며 이유를 저장한다. 네트워크 단절로 upstream 종료를 모르는 경우에는 재발신을 막되 사용자 화면은 ‘중단·종료 확인 필요’로 표시한다. 다른 Strata 요청/서버를 제어하지 않는다.
3. 별도 AI 저장소에 단계별 스냅샷을 보존하고 event offset으로 중복을 방지한다. 완료 스냅샷은 해당 단계의 수신 내용과 조정한다. 누적 추론 cursor를 줄이지 않고 앞 단계 추론을 덮어쓰지 않는다. 자동 접힘 여부는 generation마다 초기화하지 않고 턴 단위로 유지한다.
4. 대화 목록과 메시지에 제한된 cursor 페이지를 제공한다. 서버의 owner/account_key 검사와 현재 권한을 유지하고, UI에 이전 대화/내용 불러오기를 추가한다. 대화 전환 중 늦은 응답은 이전 화면에만 귀속한다.
5. 기본 기준 32,000,000자는 기준선/안내 기준으로 유지한다. 생성/확정 결과를 보존하기 위한 추가 완료 예산 기본 32,000,000자를 두어 계정별 기본 총 예산은 64,000,000자가 된다. 기준선 초과는 안내하되 남은 총 예산으로 완료 공간까지 확보할 수 있는 요청은 허용한다. 질문 접수 시 출력·확인 결과의 상한을 예약하고 모든 메시지 저장/종료 경로에 사용량·예약 정합성을 적용한다. 기존 생성 결과를 자동 삭제·숨김 처리하지 않는다. 대화 200개·질문/표시 크기·도구 수 제한은 유지한다. 운영자는 보호된 환경 설정으로 추가 예산을 조정할 수 있다.
6. 기존 값과 변경 입력을 합친 뒤 공통 장비 validator의 반환값을 사용한다. 정규화된 값으로 제안을 고정하고 확정 때 같은 규칙을 다시 적용한다.
7. D07 함수별 주석 일괄 보완은 `AI-TECHDEBT-001`로 ROADMAP과 미구현 목록에 보류 기록한다. 추후 별도 사용자 지시 전에는 이를 일괄 수정하거나 감사 완료로 표시하지 않는다. 이번에 수정/추가하는 함수의 필요한 메타 주석과 EN revision 관리는 수행한다.

## 데이터·검증·반영 경계

업무 DB schema를 변경하지 않는다. 별도 AI DB만 버전 2의 가산 테이블/컬럼으로 이전하며 기존 대화·작업·제안·불명확 요청 잠금을 보존한다. v1 합성 migration 회귀에서 보존을 확인한다. 기존 운영 DB를 열람·보정하지 않는다.

Task 생성 후 구현 전 1~8 순차 검토를 마치고 수정한다. Windows에서는 AST/JS 구문·소스 전달만 수행하고 앱/동작 시험은 Linux의 임시 합성 DB·가짜 모델로 실행한다. 전역 접근 로그 hook까지 포함한 시험과 실제 Chromium 데스크톱/모바일 회귀를 수행한다. 실제 모델·운영 앱·생산 부하·전체 백업 복구는 별도로 남긴다.

기존 Report/검증 JSON은 바꾸지 않고 새 수정 검증 JSON/Report를 만든다. 기존 dirty 변경은 보존하며 ROADMAP 두 파일에는 사용자 요청의 보류 기록만 추가한다. 운영 루트 병합·Git·서버 활성화는 이번 수정 검증 결과 승인 전 수행하지 않는다. 복귀는 AI 접수/쓰기 flag와 자체 worker 정리로 한정하고 확정 업무·감사·대화는 보존한다.

실행 결과: 수정 후보와 Linux 68개·Chromium 45개 검증을 완료했다. 상세 결과·예산·가산 이전·남은 운영 검증은 [004 보고서](../../../../Reports/2026/11/04/004_User_AI_Assistant_Corrections_Report.md)에 기록한다. 이 계획의 완료는 Staging 수정/검증 범위이며 운영 병합이나 배포 승인을 뜻하지 않는다.
