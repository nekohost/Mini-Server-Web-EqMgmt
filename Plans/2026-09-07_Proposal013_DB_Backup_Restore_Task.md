# [Task] 제안-013 데이터베이스 백업·복원

## 작업 모드와 범위

- 모드: 운영 병합, Staging 정리 및 Git 원격 반영
- 승인 범위: 검증을 마친 제안-013 산출물을 운영 코드·문서·테스트 위치에 반영하고 `Staging/`을 비운 뒤 커밋·push한다. 운영 DB와 실행 중인 서비스는 변경하지 않는다.
- 대상: `app.py`, 신규 `templates/backup_restore.html`, 메뉴·권한 초기화 경로, 배포 절차 및 문서 동기화
- 제외: 운영 DB 열람, 실제 백업·복원, 서비스 중지, Linux 서버 pull 및 실행 검증

## 순차 Task

1. 현재 코드의 DB 연결, 비동기 접근 로그 워커, 인증·CSRF·메뉴 구조를 정적으로 확인한다. 완료.
2. 백업 및 복원의 분리된 운영 모델과 보안 경계를 설계한다. 완료.
3. 검증 1~8단계를 수행하고 차단 조건을 기록한다. 완료.
4. 선행 제안-046 점검 모드의 운영 구현·검증이 완료되었다. Staging에 제안-013 DB 백업·복원 기능을 구현한다. 완료.
5. 복원 확인 문구를 영문 `RESTORE`에서 한국어 `데이터베이스 복원`으로 확정한다. 완료.
6. 관리자 메뉴, 백업 다운로드, 후보 DB 업로드·검증, 비동기 복원·상태 조회, DB 연결·로그 쓰기 동결, 자동 원복을 Staging에 구현한다. 완료.
7. 정상 복원과 후속 검증 실패 시 자동 원복을 검증하는 모의 DB 테스트를 작성한다. 완료. 운영 `tests/`로 이동 완료.
8. Staging 정적 검증을 수행한다. 완료.
9. 사용자 승인에 따라 검증된 `app.py`, `templates/backup_restore.html`, 운영 가이드와 테스트를 운영 위치에 병합한다. 완료.
10. 운영본과 Staging 사본의 동일성을 확인한 뒤 중복 파일을 제거하여 `Staging/`을 비운다. 완료.
11. 운영본 구문·구조·Git diff를 재검증한다. 완료.
12. 제안-013 변경만 커밋하고 `origin/main`에 push한다. 완료.
