# 메뉴 명칭 전역 통일 및 정규화 계획서 (Menu Name Normalization Plan)

- **작성 일자:** 2026-08-15
- **관련 작업:** 운영 시스템 전역 메뉴 명칭 불일치 해소 및 유비쿼터스 언어(Ubiquitous Language) 정립

---

## 1. 개요 및 목적
포털 화면의 메뉴 카드명, 개별 페이지 상단 바(Header) 타이틀, 본문(Body) 헤더, 백엔드 라우팅 및 주석, 시스템 산출물 문서 간에 메뉴 명칭이 파편화되어 있어 발생하는 사용자 경험(UX) 혼선 및 코드 가독성 저하를 해결하기 위해 전역적인 명칭 통일(정규화)을 수행한다.

---

## 2. 전수조사 및 정규화 기준표

| 라우팅 키 (메뉴코드) | 과거 파편화된 명칭들 (수정 대상) | **최종 통일 명칭 (정규화 타겟)** | 비고 |
| :--- | :--- | :--- | :--- |
| `my_equipment` | 나의 장비 관리 | **나의 장비** | 카드명 기준 |
| `public_equipment` | 공개된 장비, 공개된 장비 열람, 공개 장비 열람 | **공개 장비** | 카드명 기준 |
| `admin_center` | 통합 관리 시스템 (상단바 기본값) | **관리자 센터** | 카드명 기준 |
| `dashboard` | 장비 통계 대시보드 | **통계 대시보드** | 카드명 기준 |
| `master_management` | 마스터 관리 | **마스터 데이터 관리** | 본문 채택 (사용자 피드백) |
| `permissions` | 권한 관리, 메뉴 접근 권한 관리 | **메뉴 권한 관리** | 본문 채택 (사용자 피드백) |
| `users_management` | 사용자 관리 (관리자 전용), 전체 사용자 관리 | **사용자 관리** | 카드명 기준 |
| `audit_logs` | 감사 로그, 보안 감사 로그 시스템 | **보안 감사 로그** | DB/카드명 기준 |
| `approvals` | 전자결재 관리, 전자결재함 | **전자결재함** | DB/본문 기준 |
| `access_logs` | 웹 접근 로그 모니터링 | **웹 접근 로그** | DB/카드명 기준 |

---

## 3. 대상 파일 및 세부 수정 계획

### 3.1. 프론트엔드 템플릿 (`templates/`)
1. `templates/miniserver_frame.html`: 기본 `page_title` 블록을 `관리자 센터` 또는 각 페이지에서 명확히 오버라이드하도록 점검.
2. `templates/index.html`: `나의 장비 관리` / `공개된 장비 열람` / `공개 장비 열람` ➡️ `나의 장비` / `공개 장비`
3. `templates/dashboard.html`: 본문 헤더 `📊 장비 통계 대시보드` ➡️ `📊 통계 대시보드`
4. `templates/admin_center.html`: `{% block page_title %}관리자 센터{% endblock %}` 추가
5. `templates/permissions.html`: 상단바 `메뉴 접근 권한 관리` ➡️ `메뉴 권한 관리`
6. `templates/users_management.html`: 상단바 `사용자 관리 (관리자 전용)` 및 본문 `👥 전체 사용자 관리` ➡️ `사용자 관리` / `👥 사용자 관리`
7. `templates/audit_logs.html`: 상단바 `보안 감사 로그 시스템` 및 본문 `🛡️ 보안 감사 로그 모니터링` ➡️ `보안 감사 로그` / `🛡️ 보안 감사 로그`
8. `templates/access_logs.html`: 상단바 `웹 접근 로그 모니터링` 및 본문 `🌐 웹 접근 로그 모니터링` ➡️ `웹 접근 로그` / `🌐 웹 접근 로그`
9. `templates/master_management.html`: 상단바/본문 `마스터 데이터 관리` 유지 및 일관성 확인.
10. `templates/approvals.html`: 상단바/본문 `전자결재함` 유지 및 일관성 확인.

### 3.2. 백엔드 코드 (`app.py`)
1. `default_menus` 내 메뉴명 확인 및 정규화 (`공개된 장비` ➡️ `공개 장비`).
2. 라우팅 함수 상단 주석 및 Docstring 내 파편화된 명칭 일괄 정규화.

### 3.3. 시스템 산출물 문서
1. `FEATURES.md`, `ROADMAP.md` 내의 파편화된 메뉴 명칭 일괄 교체.

---

## 4. 파이프라인 준수 계획
1. `Staging/` 디렉토리에 대상 파일들의 모의 수정본을 먼저 작성 및 검증.
2. 검증 완료 후 보고서 제출 및 운영(Production) 환경 병합.
