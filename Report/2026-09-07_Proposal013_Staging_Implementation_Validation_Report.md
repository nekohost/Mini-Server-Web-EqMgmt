## 구현 결과

- 관리자 센터 하위 `DB 백업 및 복원` 메뉴와 관리자 전용 권한 마이그레이션을 추가했다.
- 점검 상태가 `DRAINING` 또는 `RECOVERY`일 때 현재 DB를 SQLite 온라인 백업으로 생성·검증해 내려받는다.
- 후보 파일은 512MB로 제한하고 임의 서버 ID로 저장하며 SQLite 헤더, `integrity_check`, `foreign_key_check`, 필수 테이블, 현재 DB의 전체 앱 테이블·컬럼·마이그레이션 호환성과 후보 관리자 비밀번호를 검증한다.
- 복원은 한국어 확인 문구 `데이터베이스 복원`과 현재·후보 DB 관리자 인증을 모두 요구한다.
- 접근 로그 수집을 멈추고 큐를 비운 뒤 신규 DB 연결을 차단하며, 기존 추적 연결이 종료된 다음 복원한다.
- 복원 직전 자동 백업, 후보 DB 온라인 복원, 후속 무결성 검사, 전 세션 토큰 갱신, 실패 시 자동 원복을 구현했다.
- 세션 만료 뒤에도 일회성 모니터 토큰으로 해당 작업의 공개 상태만 확인한다.
- 비밀번호, DB 파일, 모니터 토큰이 접근 로그의 요청·응답 본문에 저장되지 않도록 DB 작업 API를 페이로드 로깅에서 제외했다.
- 후보·백업·작업 저널은 `instance/database-operations` 또는 `DATABASE_OPERATION_ROOT`에 저장하고 Git 무시 후보를 추가했다.

## Validation 1~8

### 1. 거버넌스

운영 파일과 실제 DB를 변경하지 않고 Staging 격리 사본만 수정했다. 외부 패키지를 추가하지 않았으며 Python 표준 `sqlite3.Connection.backup()`을 사용했다. 거버넌스 검증은 오류 0건, 경고 0건이다.

### 2. 사용자 의도

관리자가 화면에서 DB를 내려받고, 보유 DB를 업로드·비교·복원하며, Flask와 점검 안내가 살아 있는 흐름을 구현했다. 확인 문구와 사용자 메시지는 한국어다.

### 3. 논리와 동시성

단일 프로세스 안에서 복원 Lock, DB 연결 계수, 접근 로그 큐 배출, 신규 연결 차단 순서를 적용했다. 정상 복원, 후속 인증 실패 시 자동 원복, 필수 스키마 누락 후보 거부를 위한 `unittest`를 작성했다. 로컬 정책상 Staging 앱을 Windows에서 구동하지 않았으며 AST 구문 검사는 통과했다.

잔여 제한: 조정기와 작업 상태는 프로세스 메모리에 있으므로 Gunicorn은 현재 운영 가이드와 같이 `--workers 1`이어야 한다. 프로세스가 복원 도중 강제 종료되면 외부 JSON 저널과 자동 백업을 이용한 수동 복구가 필요하다.

### 4. 운영 병합 영향

신규 라우트는 `/backup_restore`와 `/api/admin/database/*`로 기존 라우트와 충돌하지 않는다. `get_db_connection()`이 추적 연결로 바뀌므로 모든 DB 요청에 파급되지만 정상 상태에서는 기존 SQLite 연결과 같은 인터페이스를 제공한다. 부분 병합은 금지하며 `app.py`, 신규 템플릿, `.gitignore`를 함께 반영해야 한다.

### 5. 보안과 예외

화면과 변경 API는 로그인·관리자·CSRF 검사를 적용했다. 파일명은 사용하지 않고 크기·헤더·무결성·스키마·관리자 인증을 검증한다. 작업 상태는 무작위 토큰으로 제한하고 내부 경로와 비밀번호를 응답·저널·접근 로그에서 제외했다. 다운로드는 `no-store`로 제공한다.

### 6. 롤백

적용 전 자동 백업을 만들고 적용 또는 후속 검증 실패 시 SQLite 온라인 백업으로 원복한 뒤 원복 DB도 재검증한다. 원복 실패 시 `RECOVERY` 점검 상태를 유지하고 자동 점검 해제를 하지 않는다.

### 7. 휴먼 에러와 UX

점검 모드가 아니면 작업 대신 점검 관리 화면으로 안내한다. 업로드 검증이 끝나야 복원 영역이 나타나며 현재·후보 필수 테이블 건수를 비교한다. 복원 버튼은 `데이터베이스 복원`을 정확히 입력해야 작동하고 진행 중 중복 클릭을 막는다.

### 8. AI 메타 검증

기존 미추적 문서와 `equipment.db`를 작업 범위에서 제외했다. 구현 전 부적합 보고서는 대체 사실을 명시해 기록을 보존했다. 실행하지 않은 Linux 테스트를 통과로 표현하지 않았다.
