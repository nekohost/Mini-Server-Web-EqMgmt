## 1. 검증 근거

1. 기준 `app.py`는 4,568행이며 계획의 기준 blob과 Git 조회 결과가 일치했다.
2. 기본 분할표 54개를 기계적으로 읽어 검사한 결과 첫 행 1, 마지막 행 4,568, 공백·중복 구간 0개였다.
3. 기본 패킷의 최대 크기는 127개 물리 행이며, 비공백·비주석 코드 행의 최대값은 110개였다.
4. 큰 패킷 15개에는 두 개씩의 사전 정의 하위 패킷이 있다. 모두 사용하면 총 실행 단위는 69개가 된다.
5. 현재 `git diff --exit-code -- app.py`가 통과하여 계획 작성 중 운영 소스가 바뀌지 않았음을 확인했다.
6. 과거 손상 commit `15bf550`은 `app.py`에 1,479행 추가와 622행 삭제를 발생시켰다. 계획은 이 손상본을 검증기 필수 거부 표본으로 지정했다.
7. 분할 경계, 검증·복구 구조, 소형 모델 인계 계약을 서로 다른 세 개의 독립 검토 세션에서 대조했고 지적 사항을 계획에 반영했다.
8. 거버넌스 도구 `validate` 결과는 governance `1.1.0`, manifest node 40개, human map node 40개, 오류 0개, 경고 0개, status `pass`였다.

## 2. 검증 중 발견하여 보완한 사항

- 함수 내부 분할 금지와 실제 패킷 경계의 모순을 없애고, manifest에 미리 선언한 논리 경계에서만 본문을 나눌 수 있게 했다.
- 단순 hash만 있던 중간 상태를 실제 복구 가능한 Staging checkpoint commit으로 바꿨다.
- 작은 모델이 전체 계획과 전체 파일을 함께 읽지 않도록 패킷용 축약 규칙과 직접 의존성 조각만 전달하게 했다.
- Node 검사만으로 삼중 따옴표 문자열 내부 삽입을 판별할 수 없음을 명시하고 Linux Python 토큰·AST 검사를 최종 관문으로 분리했다.
- 허용 주석을 제거하면 기준본이 바이트 단위로 복원되는 가역성 검사를 추가하여 중복 원문 행의 삭제·이동도 차단했다.
- 로컬에 Python이 없는 상황에서 패킷별 Linux 검증을 수행할 Git 운반 경로가 빠져 있던 점을 보완했다.
- 검증 전 후보를 승인본으로 오인하지 않도록 `transport`와 `checkpoint` commit을 구분했다.
- 주석으로 물리 행 번호, traceback·coverage 위치, 소스 hash와 `.pyc`가 달라지는 불가피한 관찰 가능 변화를 명시했다.
- 기준본 후보를 PowerShell 텍스트 왕복으로 만들지 않고 바이트 보존 복사 또는 Git 물질화를 사용하도록 고정했다.
- 최종 Staging 결과를 운영 후보에 다시 생성하지 않고 검증된 동일 diff 한 번만 적용하도록 했다.

- 차단 조건: 저장소 안에 소스 행 번호 introspection 의존성이 발견되거나 외부 운영 도구가 고정 행 번호를 요구하면 영향 분석 전 병합하지 않는다.
- 추가 발견: 현재 저장소의 Python 파일에서는 `inspect`, `linecache`, `co_firstlineno`, `getsourcelines` 등 명시적 의존성을 찾지 못했다. 저장소 밖 도구까지 없다고 단정할 수는 없다.

## 4. 구현 전에 남은 선행조건

현재 계획 승인을 막는 미해결 결함은 없다. 다만 실제 구현은 다음 순서를 충족해야 한다.

1. 사용자가 구현 범위를 별도로 지시한다. 권장 첫 범위는 주석이 아니라 Staging 검증기와 실패 표본만 만드는 0단계다.
2. 검증기가 정상 표본을 통과하고 과거 손상본을 포함한 모든 필수 실패 표본을 거부해야 한다.
3. 패킷별 Linux 검증에 사용할 비운영 Git 브랜치 또는 기존 CI 통로와 그 승인 범위를 확정한다.
4. A04 파일럿 한 패킷만 작성·검증한 뒤 사용자가 설명 밀도와 난이도를 확인한다.
5. 그 이후에만 나머지 패킷을 checkpoint 단위로 순차 실행한다.

## 5. 최종 판정

계획은 이전 손상의 직접 원인이었던 전체 파일 재작성, 늦은 일괄 검증, 복구 불가능한 중간 상태, 로컬 Python 검증 가장을 구조적으로 차단한다. 기본 54개 또는 필요 시 최대 69개의 작은 실행 단위, 추가 전용 주석 형식, 가역성·토큰·AST 검증, 독립 검토, Git 운반과 운영 승인 분리를 갖췄다.

따라서 이 문서는 **사용자가 검토할 수 있는 구현 계획으로 통과**한다. 이 판정은 검증기 작성, `app.py` 주석 추가, Git commit·Push 또는 미니서버 명령 실행을 승인하지 않는다.
