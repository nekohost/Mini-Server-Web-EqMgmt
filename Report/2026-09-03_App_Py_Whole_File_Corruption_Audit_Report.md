# app.py 전체 손상 감사 보고서

- 작성일: 2026-09-03
- 대상: `app.py` (`0bc15ed`)
- 정상 비교 기준: `61fdddb9`의 `app.py`
- 판정: **부분 수선 중단, 정상본 기준 전체 복원이 필요함**

## 1. 기준점 검증

- `61fdddb9`의 `app.py`는 마지막 기능 커밋 `23d8c20`의 파일과 동일하다.
- 이후 `app.py` 변경은 `15bf550`의 전역 주석 정비와 긴급 복구 커밋 2건뿐이다.
- `15bf550`은 문서·주석 정비를 목적으로 했지만 `app.py`에서 1,479줄 추가, 622줄 삭제가 발생했다.

## 2. 확인된 실행 구조 손상

1. `init_db()`의 `conn = get_db_connection()` 및 `cursor = conn.cursor()`가 삭제되어 현재 보고된 `NameError`가 발생한다.
2. 초기화 스키마에서 다음 5개 테이블 생성문이 정상본 대비 누락됐다.
   - `equipment`
   - `lineup_nodes`
   - `equipment_options`
   - `equipments`
   - `equipments_audit_log`
3. 다음 3개 3-Tier 인덱스 생성문이 누락됐다.
   - `idx_lineup_nodes_parent_id`
   - `idx_equipment_options_lineup_node_id`
   - `idx_equipments_option_id`
4. `/api/lineup_tree_all`의 `@app.route`와 `@login_required`가 각각 두 번 연속 적용돼 있다.
5. 같은 변경 계열에서 이미 다음 손상이 확인·응급 복구됐다.
   - `init_db()` 부근의 비 UTF-8 바이트 및 닫히지 않은 문서 문자열
   - 접근 로그 마이그레이션 사이에 삽입된 180줄의 중복·파손 조각

함수 정의 수가 정상본과 동일하다는 사실만으로는 안전성을 보장할 수 없다. 함수 내부 실행문, SQL 초기화문, 데코레이터가 훼손됐기 때문이다.

## 3. 원인 판정

직접 원인은 `15bf550`에서 수행된 대규모 주석 재작성이다. 주석만 변경하려던 작업이 실행 코드와 SQL 블록까지 재구성하면서 삭제·중복·인코딩 손상을 만들었다. 현재 오류는 개별적인 세 번째 버그가 아니라 동일한 전역 손상의 다음 증상이다.

## 4. 권고 복구안

1. 현재 파일에 누락문을 하나씩 덧대지 않는다.
2. `app.py` 전체를 검증된 정상 기준 `61fdddb9:app.py`로 복원한다.
3. `15bf550` 이후에는 정당한 기능 변경이 없으므로 별도로 이식할 실행 기능은 없다.
4. 복원 후 Linux 미니서버에서 다음 순서로 검증한다.
   - `python3 -m py_compile app.py`
   - `python3 app.py`
   - 초기 DB 생성/마이그레이션 로그 확인
   - 로그인 및 주요 3-Tier·접근 로그 화면의 간단 점검
5. 상세 주석은 서비스 정상화 뒤 작은 단위로 재도입하며, 매 단위마다 컴파일 및 구조 차이를 검증한다.

## 5. 현재 조치 상태
