# Codex · GPT-6 Astra 독립 실행 노드

이 노드는 AGENTS의 현재 턴 `profile` 결과가 이 노드를 선택한 경우에만 적용한다. 기존 규칙은 모델의 한계를 보완하는 강제 도구이며, 이 경로는 그 체계의 예외나 하위 노드가 아니다. 기존 kernel·always_load·router·Task 모드·Validation 체인을 상속하지 않는다. 다른 모델은 기존 경로를 유지한다.

## 작업 책임

- 요청의 목적과 승인 범위를 파악하고 그 범위의 완료까지 수행한다. 질문·검토·계획을 승인 없는 구현으로 확대하지 않는다. 이미 승인된 범위에서 반복 승인을 요구하지 않으며 플랫폼 지시·도구 권한은 별도로 따른다.
- 사용자 데이터·기존 수정·기록·비밀을 보존한다. 변경은 Diff와 복구가 가능한 구조화 편집으로 수행하고, 파괴적 조치는 현재 승인의 정확한 대상인지 확인한다. 비밀번호·키·토큰·불필요한 개인정보를 출력하거나 기록하지 않는다.
- 고정 Staging 복사/병합/정리, 고정 8단계 검증, 작업마다 별도 Plan/Task/Report, 매 행 설명 주석을 의무화하지 않는다. 작업 규모·위험에 맞는 구현·검증·기록 방법을 선택하고, 설명이 필요한 설계와 의존성은 명확히 남긴다. 사용자가 특정 작업에 명시한 절차는 지킨다.
- 실제 변경에 필요한 코드·스키마·화면·운영 상태를 확인한다. 적절한 테스트와 복구 수단으로 결과를 검증하고, 확인된 결과·미확인 제한·미해결 문제를 구분해서 보고한다. 통과한 검사를 변경·실패·남은 우려 없이 반복하지 않는다.
- Windows는 편집·정적 검사 및 거버넌스 도구/격리 fixture 검사, 실제 Flask 실행 검증은 사용자가 지정한 Linux 서버에서 수행한다. 운영 소스 직접 수정 가능과 서버에서 검증 없이 즉석 수정하는 행위를 혼동하지 않는다. 배포는 승인 범위와 대상·실행 상태를 확인한다.
- 이 프로젝트의 외부 참고나 부수 실행으로 작업 owner를 바꾸지 않는다. 다른 governed workspace의 쓰기는 해당 진입점으로 분리하고, 독립 작업·owner 변경은 사용자 의도를 따른다.
- 기존 자동 대화 기록기의 `ensure --platform all --workspace . --json`과 Git 읽기 보호 도구(`git-readonly.mjs`)를 유지한다. 기록기 오류는 승인된 복구에 한정해 다루고 정상화 전 일반 작업을 시작하지 않는다. capability는 실제 도구 연결 정보이며 그 안의 legacy 절차를 새로 상속하는 통로가 아니다.

## 선택·유지보수

매 턴과 모델·작업·정책 변경 후 AGENTS의 `profile`을 새로 실행한다. 현재 작업 ID, 진행 중 턴, 프로젝트 경로가 맞는 Codex 런타임의 정확한 모델 ID만 사용한다. 자가 선언·기본 설정·과거 완료 턴·부모 작업의 모델은 근거가 아니다. 이전 노드를 기억하고 있어도 현재 선택이 그 노드의 적용 범위를 결정하며, 하위 작업자는 자신의 경로를 선택한다.

등록부에는 Codex/gpt-6-astra만 최초 등록한다. 미래 모델은 실제 적합성·접근성·도구 지원·사용자 채택 후 정확한 ID와 독립 노드를 등록한다. 같은 플랫폼은 모델 조건문 추가 없이 확장하며 새 플랫폼은 어댑터가 필요할 수 있다. 미등록·미확인·비활성은 이유를 표시하고 legacy, 손상·중복·경로 탈출·상속은 오류다. CLI의 `--model`로 적용할 수 없다.

일상 선택은 최소 계약만 검사하며 전체 legacy 정책을 읽지 않는다. 기술 문서를 참고해도 기존 절차가 활성화되지는 않는다. Rule 자체의 검토·개정 때만 Rule과 human-rule-map을 함께 읽는다. 정책 변경·활성화 때에는 전체 `validate`, 변경 섹션의 `sync-status`/`sync-plan --expected-rule-sha`, 의미 대조 및 관련 노드·map·baseline·manifest·등록부 해시 동기화를 수행한다. 이는 고정 Staging·8단계·문서 분리의 재도입이 아니다.

패키지 불일치나 도구 오류를 무시하지 않는다. 선택 결과는 프로젝트 절차를 정할 뿐 모델/구독/플랫폼 권한을 바꾸지 않는다. 이 노드와 관련 파일을 한 버전으로 함께 반영·복구하고 다른 작업의 변경이나 DB를 되돌리지 않는다. 도구는 파일시스템의 다중 변경 원자성이나 앱의 지침 캐시 강제 삭제를 보장하지 않는다.
