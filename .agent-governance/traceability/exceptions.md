# 추적성 예외와 충돌 기록

## EX-001: 잘못된 내부 참조

`Rule.md` 7-5-4는 `6-3-10`을 참조하지만 해당 조항은 존재하지 않는다. 의미상 실제 모델명 기록은 6-1-3 및 6-3-1과 연결된다. 원문은 수정하지 않고 `workflow.multi-agent-handoff`에서 두 조항과 함께 보존한다.

## EX-002: Chat 저장 도구의 조건부 표현

`Rule.md` 8-0은 Chat 저장에 제6조를 우선시키며, 6-1-6은 IDE 편집 API를 우선하되 불완전 위험 시 문의 후 터미널 사용을 허용한다. `tools.conversation-exception`은 이 순서를 그대로 유지한다.

## EX-003: 플랫폼이 정확한 대화 시각·원문을 제공하지 않는 경우

원문과 실제 시각을 확보할 수 없는 플랫폼에서는 값을 임의 생성하지 않는다. capability 제한을 보고하며 충족하지 못한 기록을 성공으로 표시하지 않는다.

## EX-004: 행 단위 주석의 비용

`Rule.md` 4-3 후단의 모든 코드 행 상세 주석 요구는 의미 변경 없이 `engineering.code-comments`로 이전했다. 정책의 타당성 개정은 이 노드화 작업 범위가 아니다.

## EX-005: Validation의 추가 기준

Validation 각 단계의 관찰점은 최소 기준이다. 노드에 추가된 점검 질문은 원본을 완화하지 않고 자율 위협 발굴 의무를 구체화한다.

## EX-006: 운영 활성화와 원본 보존

검증된 노드 트리는 거버넌스 버전 1.0.0부터 프로젝트 루트의 운영 진입점으로 활성화되었다. 노드화 전 `Rule.md`, `VALIDATION_METHODOLOGY.md`, 0번 조항이 제거된 `GEMINI.md`의 내용 스냅샷은 `legacy-sources/`에 보존하여 출처 추적과 회귀 검증에 사용한다.
