# 대화 저장

대화는 `Chat/YYYY/MM/DD.md`에 날짜별로 저장한다. 연·월·일은 두 자리 월과 일 파일명을 사용하며 날짜가 바뀌면 새 파일을 만든다.

1. 대화 기록은 별도 승인 없이 진행한다.
2. 최종 저장에는 사용자 발언, AI 최종 응답, 사용자에게 실제 전달한 중간 안내를 원문 그대로 함께 기록한다. 내부 추론·도구 호출·사용자에게 전달하지 않은 세부 작업은 기록 대상이 아니며, 긴 작업 중 매 과정마다 Chat을 즉시 갱신하도록 강제하지 않는다.
3. 대화는 `Chat/YYYY/MM/DD.md`에 저장하고 날짜 변경 시 새 날짜 파일을 사용한다.
4. 저장할 블록의 KST 발생 시각은 `records.timestamps` 절차로 확인한다.
5. 현재 날짜 파일이 없으면 새 파일을 만든다. 파일이 있으면 가장 최근 32개 대화 헤더만 먼저 읽어 저장 블록의 시각과 비교한다.
6. 저장 시각이 마지막 헤더보다 같거나 늦으면 블록 전체를 파일 끝에 append한다. 더 이르면 최근 범위에서 첫 번째 더 늦은 헤더 바로 앞에 블록 전체를 삽입한다.
7. 대상 시각이 최근 범위보다 더 이르면 본문 전체를 추가로 읽지 않고 이전 구간의 헤더와 위치 정보만 제한적으로 탐색한다. 같은 시각의 블록은 기존 동률 블록 뒤에 기록한다.
8. 삽입은 기존 블록의 원문·헤더를 수정하거나 삭제하지 않고 순서만 바꾼다. 삽입 직전 최근 헤더 또는 그 fingerprint가 바뀌었으면 오래된 판단으로 쓰지 않고 최근 범위를 다시 확인한다.
9. 삭제나 덮어쓰기를 사용자가 요청해도 즉시 실행하지 않고 한 번 더 재확인한다. 시간순 삽입은 이 정책으로 명시 허용된 블록 단위의 순서 조정이며 내용 삭제·덮어쓰기가 아니다.
10. 최종 저장에는 현재 플랫폼의 capability profile이 지정하고 원문 완전성·Diff·Undo를 신뢰성 있게 제공하는 구조화된 편집 수단을 우선한다. Antigravity의 내장 API 위험은 그 플랫폼에 한정하며, 실제 누락·오기입 때문에 터미널 저장이 필요하면 사용자에게 필요성과 절차를 먼저 보고하고 승인을 받는다. 이 Chat 기록 예외는 일반 소스·리소스 편집으로 자동 확장하지 않는다.
