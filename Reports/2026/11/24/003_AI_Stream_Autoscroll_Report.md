# AI 도우미 출력 자동 스크롤 사용자 우선 검증 보고서

## 1. 원인과 변경

- **원인(대화 영역):** `follow()`가 매 출력 프레임마다 "바닥에서 100px 이내"를 다시 계산해 그 안이면 바닥으로 이동시켰다. 사용자가 100px보다 적게 올리거나 조작 도중 프레임이 그려지면 화면이 다시 바닥으로 끌려 내려갔다. 사용자 조작 여부를 기억하는 상태가 없었다.
- **원인(추론 과정):** 최대 높이 350px의 추론 상자(`.ai-thought-text`)는 내부 스크롤을 전혀 따라가지 않아, 긴 추론에서 최신 추론이 상자 아래에 가려졌다.
- **변경:** `scrollFollower(element)`(`ASSISTANT.CLIENT.SCROLL.FOLLOW`)를 추가해 스크롤 영역마다 따라가기 상태를 보관한다. 대화 영역과 각 추론 상자가 각자의 상태를 가진다.
  - 위쪽 휠, 내용을 위로 올리는 터치 이동, 위쪽 이동 키, 실제 스크롤 위치의 위쪽 이동이 발생하면 따라가기를 해제한다.
  - 사용자가 최신 출력 끝 24px 이내로 돌아오면 따라가기를 다시 켠다.
  - 휠·터치·스크롤바 조작 직후 450ms 동안은 끌어내리지 않고, 보류가 끝나면 1회 따라잡는다.
  - 안쪽 스크롤 영역(추론 상자·표·코드)이 그 방향으로 더 움직일 수 있으면 바깥 대화 영역의 상태를 바꾸지 않는다.
  - 내용이 줄어 위치가 바닥에 다시 맞춰지는 경우는 사용자 조작으로 보지 않는다.
- **유지:** 새 질문 전송과 대화 열기는 바닥에서 따라가기 상태로 시작한다. 상태 동기화 재표시(`preserveReader`)는 위치와 따라가기 상태를 함께 복원한다. 답변 시작 후 사용자가 접힌 추론을 다시 펼치면 다시 보기로 보고 자동 이동하지 않는다. 서버 API·DB·설정·의존성 변경은 없다.

## 3. 검증 결과

모든 검증은 `HEAD`(`0a7505e`) 임시 사본에 Staging 패치를 적용한 후보로 수행했다. 실행 환경은 `eqmgmt-backup`의 Linux tmpfs와 격리 Chromium이며, 실제 모델 호출·운영 계정·운영 DB 접근은 없었다.

### 3.1 가상 답변 모델 시나리오 (`--browser-target stream-follow`)

## 6. 한계와 남은 결정

- **실제 모델 미검증:** strata 연결이 개선 중이어서 실제 모델 스트림으로는 확인하지 않았다. 클라이언트는 출력 출처와 무관하게 같은 표시 경로(`presentStream`·`poll`)를 사용한다.
- **미검증 입력:** 마우스로 스크롤바를 끄는 동작과 키보드(PageUp 등)는 자동 검증에 포함하지 않았다. 둘 다 스크롤 위치가 위로 이동하면 이탈하는 공통 판정이 적용된다.
- **실제 기기 미검증:** 실제 휴대폰·폴더블 기기의 관성 스크롤(플링)은 확인하지 않았다. Chromium 터치 에뮬레이션의 끌기로만 확인했다.
- **기존 문제:** `polish-stream` 묶음의 오래된 가상 전송은 이번 범위 밖이라 그대로 두었다.
- **운영 반영:** 사용자 승인에 따라 병합·commit·`eqmgmt-backup` 배포를 진행한다(7절).
