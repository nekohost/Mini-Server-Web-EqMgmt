# 메뉴 도구줄 Staging 검증

구현 전 검토

1. recorder와 정책 1.8.1 검사 통과. legacy/runtime-session-mismatch 경로의 25개 노드를 적용한다.
2. 사용자 요청은 메뉴별 판단과 기존 002를 포함하는 Staging까지다. 인증·안내와 업무 화면을 구별하고 AI 도우미의 현재 비율을 기준으로 삼는다.
3. Jinja 폼·동적 이벤트·페이지 ID·숨김·비활성 상태와 동일 행 조작을 확인한다.
4. 프레임 전체 또는 일반 버튼에 적용하는 전역 재정의 없이 업무 컨텍스트에 치수를 연결한다.
5. 원본 인증·권한·CSRF·위험 동작 확인·기존 스코프를 보존한다. 검사에는 합성 데이터를 사용한다.
6. 002 원문과 SHA, 운영 루트 및 Git 기준을 보존한다. 통합 후보를 별도 디렉터리에 둔다.
7. 폼 제출과 필터 유지, 긴 페이지 수·키보드·접힘 메뉴·모바일 가로 넘침과 확대를 확인한다.
8. 계획과 실제 수정 및 검증 결과를 대조하고 재현 범위와 발견/수정 사항을 기록한다.

## Staging 반영 결과

기존 장비 개선 후보 002를 포함해 [메뉴 도구줄 통합 후보 원문](003_Menu_Toolbars/reviewed-source.zip)을 구성했다. 14개 메뉴 템플릿에 새 조정을 적용했다. 묶음은 기존 장비 부품까지 포함한 템플릿 15개, CSS 3개, 검사 파일 8개로 구성된다. 후속 운영 반영은 [배포 보고서](004_Menu_Toolbars_Release_Report.md)에서 추적한다.

| 화면 | 반영한 내용 |
|---|---|

| 전자결재함·서버 점검·DB 백업 및 복원 | 승인·반려는 해당 행에 둔다. 점검 전환과 복원은 단계별 안내·확인을 유지하고 같은 단계에 있는 다운로드 선택지만 묶었다. |
| 메인 포털·관리자 센터·장비·AI 도우미 | 두 포털은 카드 탐색을 유지한다. 나의·공개 장비와 임시저장함은 기존 002 배치를 사용한다. 사용자 AI 도우미는 대화와 입력 공간의 현재 비율을 유지한다. 로그인·재설정·공지도 목록 조작이 없어 적용 범위에서 제외했다. |

## 구현 후 검증

1. **조작 규격과 확장.** 표시한 도구의 기본 최소 높이는 44px, 글자는 13px, 바깥 그룹 간격은 8px다. 컨테이너의 남은 폭에 따라 같은 DOM이 줄을 바꾼다. 사용자 관리에 예시 작업 버튼을 추가하는 검사, 결재함 기본 글자 125% 확대 검사, 포커스·선택값·조회 횟수를 유지한 연속 크기 변경 검사를 통과했다.
2. **폼과 접근성.** 템플릿 15개에서 파싱한 버튼·입력·링크·옵션 338개와 폼 21개를 대조했다. 기존 ID, 이벤트, 필드 이름과 폼 소유 관계를 검사했다. 오류 유발 IP 화면의 동일 목적지 복귀 링크 하나를 통합했다. 11행 이상인 결재함·감사 로그·접근 로그에는 마지막에 페이지 이동으로 돌아가는 키보드 링크를 추가했다. 25·200·50행 표에서 고정 상단 바 아래로 포커스가 복귀했다. [구조 대조](003_Menu_Toolbars/structure.json)
3. **정적 검사.** 기존 Node 검사 7개 파일에서 36개 통과, 실패 0개였다. 별도 실행형 브라우저 항목 1개는 정적 실행에서 건너뛰며, 실제 템플릿과 Linux Chromium을 사용한 화면 검사를 별도로 수행했다. 후보 JS 문법과 Python 구문 검사도 통과했다. [정적 결과](003_Menu_Toolbars/static.json)
4. **기능과 화면.** 아래 83개 브라우저 조건, 총 1,811개 판정을 통과했다. 업무 메뉴 검사에서는 기존 양식과 대화상자를 열고 합성 조회·필터·페이지 이동을 확인했다. 서버의 실제 사용자·장비 데이터에 쓰지 않았다. 모바일은 실기기와 동일한 CSS 폭을 사용하는 브라우저 검증이다. [최종 기계 판독 결과](003_Menu_Toolbars/verification.json)
5. **발견 사항과 재검사.** 결재함 조회에 남은 40px 예외 규칙, 넓은 화면에서도 로그 페이지 버튼이 줄바꿈되는 최소 폭 계산, 320px에서 열린 로그 정리 메뉴가 잘리는 문제를 수정했다. 웹 접근 로그의 이전·다음 버튼에 중복된 class 속성도 정리하고 읽을 수 있는 이름과 화살표를 부여했다. 수정한 세 화면을 다시 검사한 후 최종 메뉴 49개 조건을 전수 재실행했다. [최종 메뉴 결과](003_Menu_Toolbars/menus-final/results.json)
6. **시각 검토.** PC와 모바일에서 필터·버튼의 정렬, 일괄 작업 그룹, 표 내부 스크롤, 위험 작업의 위치와 화면 전체 가로 넘침을 확인했다. 로그처럼 제어가 많은 화면은 필요한 만큼 줄을 사용한다. 업무 표는 모바일에서도 자체 가로 스크롤을 지원한다. 7. **AI 도우미.** 1440px와 384px에서 대화 영역 스크롤, 다중 행 입력, 터치 전송과 키보드 동작을 기존 전용 검사로 검증했다. 채팅 템플릿·CSS·JS 원문에는 차이가 없다. 관리자 AI 연결 관리의 편집·모달·작업 중 잠금은 전용 화면 검사로 별도 확인했다. [PC 대화](003_Menu_Toolbars/regression-ai/screen-000.png) · [폴드 외부 화면 크기](003_Menu_Toolbars/regression-cover/screen-000.png)
8. **검토본 보존.** Git 기준 커밋은 `16c34d902cebc87422a01359864a9ffef49f7e46`이다. 운영 참조 파일 50개와 장비 Staging 원문 6개 해시를 시작 시점과 대조했다. 이번 후보·계획·작업·증거 밖의 기존 Git 변경 목록도 일치한다. ZIP 원문 26개를 다시 열어 각각의 SHA-256까지 확인했다.
