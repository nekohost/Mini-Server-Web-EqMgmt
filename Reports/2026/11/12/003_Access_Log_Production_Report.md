## 실제 AI 도우미

장비관리 서버와 5650U에서 기존 260Strata의 8080 접속이 처음에는 시간 초과됐다. 이때 모델 목록이 사용 불가 상태가 되어 질문은 접수되지 않았다. 사용자가 제공 장비를 복구한 뒤 장비관리 서버에서 같은 주소의 TCP 연결과 모델 목록 검증 상태 복귀를 확인했다. 운영 웹의 모델 연결 설정은 그대로 두었다.

일반 계정 `test04`로 운영 HTTPS에 로그인해 Chromium에서 새 대화를 열었다. `qwen3.8-flash-next-iq3_xxs`가 `33 + 9`에 `42`를 답했으며, 보내기 클릭부터 작업 완료 관측까지 14.68초였다. 실제 질문 1건·답변 1건을 AI DB에 저장했고 같은 대화를 다시 열어 화면에 같은 답이 표시되는 것을 확인했다. 최초 접수 HTTP 202, 진행 조회·재열람 HTTP 200이었다. 검증 시간 동안 대조한 관련 웹 접근 52건에서 요청·응답 본문 사본은 0건, 정상 내부 워커 접근 기록도 0건이었다. 시험 대화는 보존했고 시험 사용자 세션은 정상 로그아웃했다. [운영 브라우저·모델 결과](003_Access_Log_Production/live-ai.json)

배포 보조 명령의 첫 시도는 시스템 Python에 의존성이 없어서 웹을 멈추기 전에 종료됐다. 프로젝트 가상환경으로 재실행했다. 브라우저 검증 보조 프로그램의 격리 모드 모듈 경로도 로그인 전에 바로잡았다. 두 준비 오류 모두 운영 작업·대화를 만들지 않았다.
