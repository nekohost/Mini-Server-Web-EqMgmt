# 다중 프로바이더 확장 판단·계획 검토

## 결론과 범위

**확장 가능. 기존 기능의 전면 폐기·재작성은 불필요하다.** 현재 대화/작업 저장·업무 Domain·사용자 화면·독립 worker의 분리를 유지하고, 고정된 모델 호출부/실행 한도에 provider registry·adapter·그룹별 슬롯·작업 인계를 추가한다. 이는 정적 구조를 근거로 한 설계 판단이며 신규 기능의 실행 검증 완료 판정은 아니다.

사용자는 현재 Staging이 다른 AI에게 검토되고 있으므로 즉시 구현하지 말고 판단/계획을 요구했다. 이번에 만든 파일은 006 Plan·Task·Report 3개뿐이다. 005는 기존 검토 작업이므로 수정하거나 완료로 표시하지 않는다. 후보 16개 파일의 읽기 시작/검토 중 SHA-256은 동일했다. 실제 모델/서버 호출, 운영 DB 열람, 기존 소스·설정·배포 변경은 수행하지 않았다.

상세 설계는 [006 계획](../../../../Plans/2026/11/04/006_Multi_Provider_AI_Extension_Plan.md)에 보존한다. 004의 기존 68개/45개 시험 결과를 이번 신규 기능의 검증으로 재사용하지 않는다.

## 실행 조건과 완료 상태

이번 작업의 완료 범위는 확장 가능 판단과 설계다. 기능 구현·API 추가·스키마 이전·실제 연결/모델 시험·운영 병합은 실행하지 않았다. 필요한 실제 접속 주소/버전/키·자원 공유·모델 기능은 구현 착수 시 조사할 항목이며, 이를 받기 위해 현재 계획 작업을 중단하거나 승인을 재촉할 필요는 없다.

현재 다른 AI의 005 평가가 확정되면 그 결과를 먼저 대조한다. 필수 수정이 있으면 이를 정리한 기준선에서 006 계획의 adapter/관리 화면/인계/큐 확장을 진행한다. 신규 범위를 덧붙여 기존 평가 대상의 해시를 바꾸지 않았다. 참고했던 외부 API 자료와 출처는 계획 문서에 연결했으며, 전체 재작성을 권고할 근거는 현재 소스에서 확인되지 않았다.

새 대화의 초기 선택은 관리자 기본 모델, 단일 유효 모델, 관리자 공개 순서의 첫 유효 모델 순으로 정한다. 기존 세션의 복원 불가나 실행 오류를 다른 provider/model로 자동 대체하는 의미가 아니다. 007 비교 보고서는 당시 근거로 보존하며, 본 절과 갱신한 006 계획이 최신 사용자 결정을 나타낸다.
