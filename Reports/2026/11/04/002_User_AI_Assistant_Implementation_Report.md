## 구현한 후보와 현재 결론

`Staging/20261104-user-ai-assistant/overlay/`에 실제 기능 후보를 작성했다. `/assistant` 독립 화면, 사용자별 대화 저장, 11개 고정 업무 도구, 17개 신규 route, 별도 worker와 장비관리 내부 영구 큐를 포함한다. 기존 app의 import·포털 메뉴·설치 함수 세 곳과 AI 자동 조회에 대한 session_timer 예외만 overlay에 연결했다. 루트 앱·기존 Strata 화면·운영 설정은 미변경이다.

화면은 모델의 reasoning_content와 답변을 구분한다. 추론은 처음 표시될 때 펼치고 첫 답변 시 한 번만 닫으며, 사용자가 다시 펼치면 polling이 이를 덮어쓰지 않는다. 낮은 추론=none(추론 없음), 중간=medium(기본), 높은 추론=xhigh로 제공한다. 모델이 보내지 않은 추론을 생성하거나 원시 추론을 다음 프롬프트에 넣지 않는다.

일반 질문은 도구 없이 답할 수 있다. 실제 업무는 현재 일반 사용자 메뉴·소유권·입력 검증을 통과한 본인 장비 등록/수정/상태, 본인·공개 조회, 카탈로그/라인업/옵션 신청, 내 신청 조회와 개인 설정/파일/CSV로 한정했다. 관리자도 AI 도구에서는 본인 일반 사용자 범위를 사용한다. 폐기·삭제·소유권 이전·관리자 승인/사용자 관리·임의 SQL/코드/URL/경로 실행 도구는 없다.

새 카테고리·제조사·라인업 승인 전의 특수 임시 노드/대체 옵션을 복합 생성하는 기존 등록 화면 동작은 자동화하지 않았다. 신청 승인 후 등록하거나 기존 수동 화면을 이용한다. 승인 모델 아래 본인 대기 옵션으로 임시 장비를 저장하는 흐름은 지원한다.

인가는 프롬프트가 아닌 서버에서 강제한다. 서명 cookie·실시간 SessionToken/활성 상태/메뉴·유효기간·유지보수 revision 기반 HMAC을 확인하고, 브라우저 변경에는 Origin/CSRF를 검사한다. UserId와 서버 CreatedAt을 함께 사용해 DB 복원 후 회원 번호 재사용으로 이전 대화·작업·proposal이 다른 계정에 연결되는 경우도 차단했다. 로그인 이름 변경은 같은 계정의 기록을 유지한다. 실제 계정 생성 정보가 없으면 닫고 운영 DB를 자동 수정하지 않는다.

모델/worker는 읽기 또는 불변 변경 제안만 만들 수 있다. 실제 변경은 사용자의 내용 확인 후, 현재 권한·장비 revision·선택 옵션 상태·서명·만료를 다시 확인해 실행한다. 업무 변경·감사·AI 실행 영수증을 같은 장비 DB transaction에 기록하고 중복 확인/AI 상태 유실 시 기존 영수증을 재사용한다. 기존 audit_logs를 이용하므로 장비 DB DDL은 추가하지 않았다. 별도 AI SQLite는 대화·큐·proposal·위임 철회를 보관한다.

큐는 장비관리에서 보낸 요청만 한 번에 하나씩 처리한다. 도구 단계가 끝나면 뒤로 재진입하고 확인 대기 중에는 점유하지 않는다. 다른 Strata 소비자의 요청이나 공유 서버 설정은 조회·중단·재시작하지 않는다. 자체 요청 종료가 불명확하면 자동 재전송을 차단하고 운영자의 자체 요청 종료 확인 후에만 내부 복구를 허용한다.

## 승인 후 남은 작업과 복귀

현재 상태는 **Staging 검증 완료·운영 병합 승인 대기**다. 독립 화면·API·worker·시험·설정 안내는 실제 후보 파일로 준비했으나 기능은 현재 운영 화면에 나타나지 않는다. 검증 결과 승인 후 기존 사용자 변경을 다시 대조하고 필요한 후보만 root에 병합한 뒤 정적 확인→Git→Linux pull/commit 대조→전체 앱·실제 Strata 연동 확인→조회/대화 우선→쓰기 별도 확인 순서로 적용한다.

운영 전 잔여 조건은 실제 계정 CreatedAt/감사 DB 계약, 강한 고정 SECRET_KEY와 독립 worker/Strata key의 서버 보관, 장비관리→Strata 통신 보호, 장기 요청/자체 요청 취소·복구, 실제 모델의 도구 정확성, audit 영수증 조회 비용, 두 DB의 일관된 백업·보존이다. 운영 DB 조회나 schema 보정은 이 후보 시험에 포함하지 않았다. 현재 프로필은 해당 조회를 별도 명시 승인 사항으로 제한하므로 적용 시 필요한 최소 확인 범위를 먼저 제시한다.

기능 문제 시 신규 AI 접수/쓰기 flag를 닫고 장비관리 자체 작업을 정리한다. 확정된 장비·감사·대화/영수증은 보존한다. 다른 서비스의 Strata 요청/모델을 중단하는 복구는 사용하지 않는다. 원래 기능·수동 등록 화면·기존 Strata 시험 화면은 계속 별도로 유지한다.

운영 병합의 명시적 근거는 `.agent-governance/workflow/staging-merge.md`의 “사용자가 검증 결과를 승인한 뒤에만 운영에 병합한다.”이다. 실제 결과가 준비되었으므로 이 결과에 대한 최종 승인만 요청한다.
