## 구현 중 확인

기준 root121개 파일의 SHA를 baseline.json에 보존하고 후보16개 기준 파일을 구조화 편집으로 복사했다. 첫 대량 읽기는 출력 상한으로 JSON이 잘려 후보 소스 쓰기 전에 중단됐고, 작은 조각의 읽기로 전환해 원문을 복사했다. 기존 운영 파일은 수정하지 않았다.

출력의 원인은 worker의4096문자/1초 flush와 client의1.5초 poll 및 전체 snapshot 재렌더링이다. worker 후보는 완성 SSE line의 추가 byte-buffer 대기를 제거하고, 기존4096문자 경계를 유지하며 작은 batch의 전달 간격을150ms로 단축한다. 독립 presenter는30fps 목표/448ms 수준의 유한 catch-up과 원문 별도 보존·완료 즉시 flush를 검사한다.

실제 선택 연결/자체 큐 API는 passive GET으로 구현했다. 동결된 자기 요청이 있으면 그 요청을 우선하며, 기존 group guard와 claim fairness로 선행 대기를 판단한다. 최근 연결 성공/실패 근거만 사용하고60초 지난 근거는 stale, HTTP 설정 거절은 확인 중으로 구분한다. 별도 모델 probe나 다른 서비스 제어는 없다.

초기 Linux 합성9개 중 입력 경계1개는 기존 opaque ID 계약이400이 아닌404를 반환하여 기대값이 달랐다. 현행 ID 은닉 계약을 확인하고 검사 기대값을404로 정정했다. fixture runner의 새 Staging 깊이에서 root 탐색이 C:/Project로 벗어나는 오류도 발견하여 AGENTS를 가진 실제 조상 경로를 찾도록 수정했다.

## 확장 검증에서 확인한 경계

final-polish-01의20개 화면 중 레이아웃/상태8개와 이름/휴지통8개는 모두 통과했다(각42/35개 검사). 출력4개는 대형 표의 시험 조성/시간 기대값에서 실패해 그대로 보존하고 분리 재검증했다. 기존 UI 회귀의 가상 시간은 실제 rAF보다 빠르게 완료 응답을 소비하여 중간 추론 열림을 관찰하지 못했다. 실제 프레임 캡처로 바꿨고, 별도의 stale 클라이언트 검사는 DOM에서 떨어진 disabled 버튼을 누르던 문제를 확인했다. 보관된 옛 버튼만 의도적으로 활성화해 오래된 revision이 실제로 전송·거부되는지 확인하도록 강화했다.

출력 모듈에서 별도의 실제 경계 결함도 결정적 시계로 재현했다. 진행 중 batch 종료 직전에 새 큰 suffix가 도착하면 그 suffix도 이전 deadline에 밀려 한 프레임에 표시될 수 있었다. 종료96ms 내의 정상 추가 수신에 한해 기존 수신분을 먼저 확정하고 새 수신분을 새480ms 창으로 분리했다. 중복 snapshot·완료·오류·세대 변경·hidden/reduced-motion은 이 분리에서 제외한다. 기존17개와 새 경계1개를 합친 Node18개가 통과했다. 재현은 종전 t432ms의10000자 단일 표시에서, 기존5000자 t416ms 확정 후 새5000자를14프레임/t864ms까지 분산하는 결과로 바뀌었다.

대형 표 시험은 실제 running 상태로 큰 표를 유지하는 별도 scenario로 분리했다. 적응형 렌더링은 약48.5ms 비용의120행 표에서6개 답변 프레임으로 분산했으므로 `2000자 초과 중간 프레임4개`라는 임의 조건 대신 `답변 중간 프레임4개 이상 + 실제 큰 prefix2개 이상`을 검증한다. 최종 원문 일치·700ms 이내 수신분 표시·스크롤 오차1px 기준은 유지한다. 재생성 표의 CSS 폭은 body 뒤의 더 구체적인 selector로 유지하여 테스트 전용 가로 스크롤 조건을 실제로 조성하고 폭/위치 측정값을 남긴다.

stream-smoke-05는390px 다크33개 전부 통과했다. 일반 출력 중간 프레임 간격 중앙값33.5ms,120행 표 최대 렌더44.5ms·수신분 따라잡기459.6ms, 본문65→65/표130→130 및 종료 후 presenter 자원0을 확인했다. 뒤의 전체 matrix와 중복 합산하지 않는다.
