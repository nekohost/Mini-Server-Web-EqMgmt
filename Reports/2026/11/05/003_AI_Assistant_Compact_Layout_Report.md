# AI 도우미 공간 절약 계획 검토

사용자 1~10번을 [Plan 003](../../../../Plans/2026/11/05/003_AI_Assistant_Compact_Layout_Plan.md)에 반영했다. 결론은 상단의 중복 정보/모델 툴바를 정리하고 입력창 하단으로 선택 컨트롤을 모으는 방식으로 기존 Staging을 확장할 수 있다는 것이다. 이번에는 계획 문서만 작성했다.

## 1. 거버넌스 준수성

- 근거: AGENTS recorder ensure 성공 후 profile은 `legacy/runtime-session-mismatch`, verified=false였다. 임의 모델명으로 독립 profile을 활성화하지 않았다. manifest 1.8.1 validate에서 44 nodes, 오류/경고 0을 확인했다.
- 관련 intent는 plan/review/frontend/ux/responsive로 분류하고 새 Plan/Task/Report 세 경로를 쓰기 대상, 현재 Staging 소스와 Report 002를 참고 대상으로 선언했다. context 두 pack의 필수 25개 unique 노드를 모두 읽고 Task를 만든 뒤 단계별로 검토했다.
- 긍정: 소스·DB·운영 설정을 건드리지 않고 요청한 추가 계획에 한정했다. 외부 라이브러리나 별도 UI 프레임워크가 필요하지 않다.
- 위험/차단: 이번 요청을 앞선 구현 지시의 연장으로 해석해 즉시 후보를 수정하면 범위를 벗어난다. 구현으로 넘어가지 않았다. 중간 validation 노드 경로 조회에서 존재하지 않는 이름을 사용한 오류는 manifest의 실제 `validation/phases/` 경로를 확인해 정정했고, 필수 노드를 생략하지 않았다.

## 2. 사용자 의도 달성도

- 근거: Plan의 요청별 표에서 1~10번을 전부 추적했다. 제목은 좌측 목록이 숨을 때만 보이고 넓은 화면에서는 헤더 영역 전체를 제외한다. 상단 모델/연결명, “내 장비, 더 간편하게”, 정상 “장비 업무 가능”을 제거한다.
- 긍정: 모델/새로고침을 추론 왼쪽으로 옮겨 입력·선택 동선을 모으고 중복 상단 높이를 본문에 돌려준다. 표시 라벨은 “AI 모델”로 통일한다.
- 위험/차단: 8번의 최대 너비를 새로 축소한 추론 너비로 잘못 해석할 수 있다. 변경 전 추론 기준 너비 W0와 변경 후 추론 폭을 구분했다. 2번의 정보 제거는 상단에 한정하며 모델 선택과 기존 응답 출처까지 삭제하지 않는다.

## 3. 논리적 구동 가능성

- 근거: template의 `.ai-header`/`.ai-model-control`/`.ai-composer-actions`, CSS의 760px media와 서랍 `top:71px`, `modelControls()`의 직접 DOM 참조와 동적 추론 사유 표시를 확인했다.
- 긍정: 기존 ID와 이벤트를 유지하며 DOM 위치와 scoped CSS, 표시 문구만 조정할 수 있다. 서버 요청 형식·DB·큐를 바꾸지 않아도 된다. 너비 변화로 재렌더링/API 호출을 추가할 이유가 없다.
- 위험/차단: 헤더 텍스트만 감추면 78/70px 최소 높이가 남고, 서랍 위치만 그대로 두면 틈/겹침이 생긴다. 헤더의 높이·구분선·패딩까지 제거하고 모바일 서랍 기준을 연동하도록 했다. 동적 사유 때문에 select 폭이 늘어나는 문제는 짧은 단계 이름과 별도 지원 안내로 해소한다.
- 후속 측정: W0는 현재 CSS 상수가 아니므로 변경 전 고정 브라우저·모델·폰트·뷰포트에서 실제 외곽 CSS px를 측정해 구현 상수/근거로 남겨야 한다. 현재 정적 검토로 실제 DOM 치수를 측정했다고 주장하지 않는다. 이 측정은 구현 작업이며 추가 사용자 입력이 필요하지 않다.

## 4. 운영 병합 영향

- 근거: 향후 주 변경 대상은 후보 template/CSS/JS 세 파일과 관련 UI fixture/설치·검증 기록이다. 현재 쓰기는 새 문서 세 개뿐이다.
- 긍정: 전역 테마·관리자 연결 설정·백엔드 권한·API/DB migration을 새로 바꾸지 않는 범위로 계획할 수 있다.
- 위험/차단: 캡션 마크업만 없애고 직접 참조 JS를 배포하면 null 접근으로 초기화가 중단될 수 있다. template/CSS/JS를 한 후보로 검증하고 함께 적용하는 조건을 적었다. 기존 002 fingerprint를 새 배치의 성공 근거로 재사용하지 않는다.

## 5. 보안과 예외 엣지 케이스

- 근거: 제목/모델은 현재 `textContent`·안전한 option 생성으로 표시된다. 기존 휴지통 읽기 전용과 모델/추론 비활성 제어를 계획의 보존 조건에 넣었다.
- 긍정: 출력 위치를 바꾸어도 권한을 클라이언트 라벨로 결정하지 않는다. 새로고침이 form 안으로 들어갈 때 `type=button`을 명시적으로 유지한다.
- 위험/차단: 공간 축소 과정에서 오류·미지원 사유까지 숨기면 사용자는 전송 실패를 이해할 수 없다. 정상 가능 문구만 제거하고 실제 제한/실패는 입력창 근처 조건부 상태 안내로 표시하도록 구분했다. 비활성 추론 단계는 숨기거나 활성화하지 않는다.

## 6. 롤백과 기록 보존

- 근거: 기존 `source-manifest.json`의 후보 43개 파일과 `baseline.json`의 주요 운영 원본 24개 파일 SHA-256을 각각 다시 대조했다. **불일치 0**이었다. HEAD는 `3d9dacc65b83b754f7162b5ba520b0f130551208`, index는 비어 있으며 기존 tracked dirty 9개 목록이 유지된다.
- 긍정: 기존 완료 후보·검증 JSON/PNG·이력 문서를 고정하고 추가 문서를 별도 순번으로 보존했다. 신규 배치는 DB/schema/localStorage 형식의 변경 없이 되돌릴 수 있는 범위다.
- 위험/차단: 미래 구현은 기존 후보를 수정한 뒤 과거 성공 hash를 그대로 보고해서는 안 된다. 변경 전 기준과 새 후보를 각각 식별하고 새 fingerprint·결과를 남기는 절차를 Plan에 넣었다. 현재 정리/삭제/복구 명령은 수행하지 않았다.

## 7. 휴먼 에러와 UX 방어

- 근거: 기존 모바일 `screen-010.png`와 PC dark `screen-015.png`를 직접 보았다. 선택 컨트롤의 상단/하단 분산, 별도 모델 상태 줄과 중복 제목이 공간을 사용한다. 새 배치 이미지는 아직 없다.
- 긍정: 모바일은 제목 한 줄로 대상 식별을 유지하고, 넓은 화면은 좌측 선택 강조를 사용한다. 하단 컨트롤을 좁은 폭에서 자연스럽게 줄바꿈하고 공통 크기로 정렬하는 기준을 정했다.
- 위험/차단: 820px처럼 좌측 목록은 보이지만 입력창이 좁은 화면, 긴 모델/제목, 760/761px 경계, 기본 추론 예외, 초기 로딩/오류, 휴지통, 200% 확대, 모바일 키보드를 별도 수용 항목으로 다룬다. 읽기 쉬움·터치 영역·포커스를 해치면서 한 줄을 강제하지 않는다. 실제 변경 전후 가용 본문 높이는 구현 후 같은 상태에서 비교해야 한다.

## 8. AI 메타 거버넌스와 종합 판정

- 근거: 구현 승인 요청을 새로 만들거나 사용자에게 재확인을 요구하지 않고 계획 산출물을 완성했다. 새 하위 작업자·외부 메시지·실모델 호출·서버 명령·브라우저 실행은 사용하지 않았다.
- 긍정: 기존 구현 완료와 신규 계획 완료를 구분하고, 확인한 사실과 향후 수용 기준을 문서에 나누었다. 기존 backend 178개/UI 803 checks는 변경 전 결과라고 명시했다.
- 남은 작업: 실제 후보 구현, W0/본문 높이 측정, 새 화면/회귀 검증은 후속 구현 단계다. 계획 검토의 미해결 차단 사항이나 필수 사용자 입력은 없다.

최종 판정은 **추가 계획 수립 완료·소스 미변경**이다. [Task 003](../../../../Tasks/2026/11/05/003_AI_Assistant_Compact_Layout_Task.md)과 같은 work_id로 보존한다.
