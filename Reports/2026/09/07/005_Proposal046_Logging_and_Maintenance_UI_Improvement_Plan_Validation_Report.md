# [계획 검증 보고서] 제안-046 로그 운영 및 점검 화면 개선

작성일: 2026-09-07
대상: `Plans/2026/09/07/003_Proposal046_Logging_and_Maintenance_UI_Improvement_Plan.md`

## 1단계: 거버넌스 준수성

Staging 우선, 무의존 Vanilla JavaScript, 서버 권한 재검증을 유지한다. systemd 유닛은 서버 설정이므로 코드 Staging 검증 뒤 사용자 확인 후에만 적용한다. 통과.

## 2단계: 사용자 의도

Gunicorn 로그를 SSH 콘솔에서 실시간으로 확인할 수 있고, 점검 화면에는 현재 상태에서 가능한 동작 하나만 보인다. 한글 확인 문구와 날짜·시간 입력 요구도 반영한다. 통과.

## 3단계: 정적 논리

`journalctl -f`는 Gunicorn의 표준 출력·표준 오류를 유지한다. 날짜와 시간을 분리한 뒤 서버에서 재결합·검증하므로 브라우저 입력 형식 차이를 안전하게 처리한다. `RESTORING`의 해제 금지는 그대로 유지한다. 통과.

## 4단계: 운영 병합 영향

systemd 등록 전 기존 Gunicorn 종료와 포트 확인이 필요하다. 템플릿 조건은 화면만 바꾸며 API의 인증·권한·CSRF 방어를 약화시키지 않는다. DB 스키마 변경은 없다. 통과.

## 5단계: 보안과 엣지 케이스

확인 문구는 한글로 바뀌어도 관리자 비밀번호, 서버 DB 역할, CSRF 검증과 감사 로그를 유지한다. 날짜만 입력, 시간만 입력, 잘못된 시각, 변조된 API 요청은 서버에서 거부한다. 통과.

## 6단계: 롤백

systemd 유닛은 중지·비활성화 후 기존 Gunicorn 실행 방식으로 되돌릴 수 있다. 코드 롤백은 DB 변경 없이 가능하다. 통과.

## 7단계: 휴먼 에러와 UX

상태별 하나의 양식으로 오조작을 줄인다. `RESTORING`은 동작 버튼 없이 이유를 표시한다. 날짜는 달력·수동 입력, 시간은 수동 입력·목록 선택을 함께 제공하며, 부분 입력은 전송 전에 설명한다. 통과.

## 8단계: AI 메타 거버넌스

현재 요청은 계획 작성이며 구현·서버 설정·재기동으로 확대하지 않았다. 미확인인 기존 서비스 관리 방식은 추정하지 않고, 새 systemd 유닛을 별도 검증 대상으로 남겼다. 통과.

## 결론

계획은 구현 준비가 되었으며, 승인 후 Staging 구현과 별도 서버 설정 검증이 필요하다.
