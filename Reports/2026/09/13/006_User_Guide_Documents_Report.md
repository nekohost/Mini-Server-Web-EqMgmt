## 실제 확인 범위

운영 도메인 `https://nekohost.org`의 `/login`, `/register`, `/portal`, `/my_equipment`, `/public_equipment`, `/dashboard`, `/mypage`를 일반 사용자 테스트 계정으로 확인했다.

- 로그인과 로그아웃, 포털 3개 메뉴, 공통 내비게이션과 테마 전환.
- 나의 장비·임시저장 0건, 공개 장비 1건 조회. 타인 공개 장비의 수정·삭제 권한이 없고 상태 이력 입력도 제한됨을 확인했다.
- 신규 등록 폼에서 카테고리·제조사·노드를 순차 선택하고 기존 옵션 `256GB/블랙` 선택 시 저장 버튼 활성화를 확인했다. 입력값은 저장하지 않고 취소했다.
- 신규 옵션명·Key/Value·기한 입력 예시를 촬영하고 취소했다. 노드 요청·장비·옵션 저장은 제출하지 않았다.
- CSV 창의 제한·미리보기/확정 단계 및 공개 장비 상태/첨부 창의 파일 제한을 확인했다.
- 통계에서 스마트폰 + 삼성 검색으로 1건 조회를 확인했다.
- 프로필 수정·이메일 수정·비밀번호 재설정 창과 가입 화면을 열어 입력 항목을 확인했다. 본인 확인 비밀번호·PIN은 입력하지 않았고 메일도 발송하지 않았다.

## 미실행 및 경계

소유 장비가 없는 계정이므로 실제 수정·삭제·상태 변경·첨부 업로드는 실행하지 않았다. CSV 파일 제출·확정, 신규 카탈로그 승인 요청·승인 후 발행, 이메일 인증·기한 알림 발송, 비밀번호 변경·회원 탈퇴도 실행하지 않았다. 해당 절차는 구현 근거로 문서화하고 실제 성공 테스트와 구분했다. 관리자 전용 화면은 범위 밖이다.

관찰 중 회원가입 제목에 `계정 생성 (Staging 검증)` 문구가 남아 있음을 확인했다. 접속 대상은 운영 도메인이며 배포 상태를 의미한다고 추정하지 않았다. 문서에 주의를 넣고 애플리케이션은 수정하지 않았다.

## 자격증명·운영 영향

- 전용 테스트 계정 자격증명만 사용했다. CUA 실행 환경의 SSH가 실패하여 일반 실행 도구의 정상 SSH/SCP 경로로 최소 범위의 임시 사본을 만들었다.
- 사본은 현재 Windows 사용자만 접근하도록 상속 제거·ACL 설정한 로컬 전용 디렉터리에 두었고, 브라우저 입력을 위한 메모리 로딩 직후 삭제했다. 마지막 `Test-Path`는 false였다.
- 비밀번호 값·쿠키·토큰은 출력·문서·Git에 포함하지 않았다. 로그인 캡처는 자동 채움 값을 비우고 재촬영했다.
- 운영 코드·스키마·장비·카탈로그·프로필은 변경하지 않았다. 로그인 세션·접근 로그 등 정상 조회 부수 효과는 발생할 수 있다. 검증 세션은 로그아웃했다.
- 이전 작업의 미커밋 로드맵 문서 등은 보존했다. 이번 요청에 없는 Git commit/push·서버 배포는 수행하지 않았다.

1. 규칙: 시작 시 recorder ensure, validate/context 및 적용 pack을 읽었다. Task·Plan을 선행했다. 문서 생성이므로 코드 Staging·배포는 해당 없음. 최종 governance validate: 43개 노드, 오류·경고 0.
2. 사용자 의도: 실제 일반 사용자 화면을 기반으로 Markdown 1종과 PPT 1종을 완성했다. 기능·버튼 의미와 사용 순서를 두 형식에 반영했다.
3. 정적 논리: 카탈로그 공식명과 경로, 신규 옵션/노드의 승인, 공개 기본값, CSV 전체 검색 범위와 신규 등록 의미를 소스와 대조했다. 운영 서버와 주요 로컬 구현 파일의 SHA-256을 비교해 동일함을 확인했다.
4. 운영 영향: 로그인·조회·입력 후 취소에 한정했다. 업무 데이터의 저장·변경·삭제 없이 제작했다.
5. 보안: 제한된 테스트 계정 사용, 임시 자격증명 사본 삭제, 비밀정보 비기록, 공개 첨부 위험과 탈퇴 시 데이터 정책 주의를 포함했다.
6. 복구: 신규 문서 산출물만 추가했다. 원본 스크린샷은 유지하고 PPT용 필요한 부분만 손실 없는 영역 추출로 확대했다. 중간 PPT는 `.build/`에 보관했다.
7. 휴먼 에러: 미실행 절차를 성공 증거처럼 표현하지 않았다. 회색 저장 버튼·권한없음·카탈로그 복원 경고·동시 변경에 대한 확인 순서를 넣었다. PPT 초안의 작은 캡처와 10·15장 텍스트 간격 문제를 수정했다.
8. AI 메타: 촬영일·권한·운영 대상·근거·미실행 항목을 명시했다. 최종 PPT 재열기 렌더링 22장을 각각 전체 크기로 시각 검수했다. 파일 구조 검사를 실제 PowerPoint 앱 실행 검증과 구분했다.
