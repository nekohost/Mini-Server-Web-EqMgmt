## 검토 결론

사용자가 전달한 세 권고는 모두 실질적인 누락 위험을 줄이므로 계획에 반영했다. 하위 에이전트는 전면 제외할 필요가 없다고 재판단했다. 사용자 직접 대화의 탐색성을 유지하면서 하위 작업의 존재와 결과를 확인할 수 있도록 주 대화에는 작업 receipt를, 별도 companion에는 허용된 부모↔하위 에이전트 메시지 원문을 기록한다.

Antigravity 보고서에 별도로 언급된 preflight 임시 bypass는 반영하지 않았다. 자동 기록 장애 상태에서 일반 작업을 계속 허용하면 이번 개선의 핵심인 누락 차단이 다시 무력화되기 때문이다. 복구 가능한 오류는 제한 재시도하고, 지속 오류는 마지막 성공 cursor와 원인을 보고한 뒤 fail-closed하는 기존 계획을 유지한다.

## Validation 1~8

### 1단계 — 거버넌스 준수성: 통과

수정은 계획·Task·검증 문서에 한정됐다. 하위 에이전트 companion 경로와 전용 writer 권한은 향후 `Staging/Rule.md`, conversation 노드, router, manifest와 traceability를 같은 변경 단위로 갱신하도록 계획했다. 활성 Rule과 노드는 변경하지 않았다.

### 2단계 — 사용자 의도 달성도: 통과

하위 에이전트 사용 여부, 맡긴 작업과 결과를 사용자가 확인할 수 있게 했다. 직접 대화에는 간결한 receipt만 두고 상세 원문은 링크된 companion으로 분리하여 정보 접근성과 일자별 기록의 가독성을 함께 유지한다.

### 3단계 — 논리적 구동 가능성: 통과

Windows 감시는 `fs.watch`에 의존하지 않고 1.5초 stat 폴링으로 cursor 이후를 재검사한다. Antigravity는 가장 최근 폴더 선택 대신 conversation ID, workspace, 상위 세션 메타데이터를 대조하며 전환 전 세션도 끝까지 재조정한다. 64 KiB를 넘는 하위 에이전트 기록은 순번 파일로 분할하여 누락 없이 크기를 제한한다.

### 4단계 — 운영 병합 영향: 통과

변경 대상은 개발 PC의 로컬 기록기와 `Chat/`이다. Flask·DB·Linux 서비스에는 영향이 없다. polling은 추적 중인 경로의 stat만 검사하고 전체 원본 재파싱은 변화가 있을 때 cursor 이후로 제한하여 상시 I/O 부하를 통제한다.

### 5단계 — 보안과 예외: 조건부 통과

하위 에이전트 기록 범위가 넓어지면서 비밀과 내부 지시 노출 면적도 커진다. companion에도 동일한 redaction을 적용하고 시스템·개발자 지시, 내부 추론, 도구 호출·결과와 approval-review를 제외한다. 이 필터와 64 KiB 분할 경계에서 UTF-8 문자가 손상되지 않는 시험은 운영 활성화 전 필수다.

### 6단계 — 롤백: 통과

polling, Antigravity 식별과 하위 에이전트 기록은 adapter·projector 모듈 단위로 비활성화할 수 있다. 롤백 시 이미 정상 기록된 주 대화와 companion은 삭제하지 않고, 잘못된 항목만 provenance 대조를 거쳐 별도 정정한다.

### 7단계 — 휴먼 에러와 UX: 통과

사용자는 주 대화의 receipt에서 하위 작업 수, 상태와 상세 링크를 확인할 수 있다. 대용량 상세 기록도 번호가 붙은 companion으로 분리되어 주 대화를 스크롤하지 않고 필요한 작업만 열 수 있다. 식별이 불명확한 Antigravity 폴더를 임의 선택하는 동작은 금지했다.

### 8단계 — AI 메타 거버넌스: 통과

하위 에이전트의 숨은 추론을 공개하거나 재구성하지 않고 실제 task·status·handoff event만 기록한다. Antigravity 검토의 기술 권고는 채택했지만 “운영 위험 0%”, “환각 가능성 0%” 같은 절대 표현은 검증 근거로 사용하지 않았다. source 기반 투영도 parser 오류와 필터 오류 가능성이 있으므로 fixture와 shadow 대조가 필요하다.

## 운영 활성화 차단 조건

- `fs.watch` 이벤트가 없어도 stat 폴링으로 5초 안에 반영되지 않음
- Antigravity conversation 전환 또는 병렬 후보에서 누락·혼입 발생
- 하위 에이전트 내부 추론·도구 출력·비밀값이 companion에 노출됨
- task·status·handoff receipt의 누락 또는 중복 발생
- Codex·Antigravity shadow 검증 전에 Claude까지 한꺼번에 활성화함

위 조건이 없고 수정 계획의 수용 기준을 모두 통과한 경우에만 1차 Codex·Antigravity 운영 활성화를 검토한다.
