# 제안 047 운영 반영 전 검토

판정: 후보 보완 후 운영 소스 반영 진행. 사용자가 검토·운영 반영을 명시 승인했다.

1. 거버넌스: recorder·manifest 검증 통과, 기존 Task와 별도 통합 Task 연결. Windows 앱 실행 없이 정적·격리 서비스 검사. 운영 소스 반영과 Linux 서비스 적용 구분.
2. 사용자 의도: 루트/하위 생성→선택→옵션→장비 저장 및 관리자 전용 관리 화면을 완성해야 함. 013 시험은 제외.
3. 정적 논리: 후보는 중복 검사 앞에 쓰기 잠금이 없고 소수 ID를 정수로 절삭할 수 있음. 어댑터 감사 콜백이 commit 전에 별도 연결을 열면 SQLite 잠금 충돌. BEGIN IMMEDIATE와 엄격한 입력, 동일 연결 감사 기록으로 보완. 등록 경로 재선택 구현 필요.
4. 운영 영향: 기존 node CRUD route는 교체하여 중복 등록 방지. 관리자 페이지·snapshot와 메뉴를 연결. 노드에 옵션과 자식이 공존해도 기존 옵션을 선택할 수 있게 해 신규 하위 추가로 기존 장비 경로가 막히는 것을 방지.
5. 보안·예외: 로그인·admin·CSRF 유지. JSON 배열/숫자 입력 거부, 부모 승인·동일 분류 검사, 내부 예외 일반화. PENDING 노드 삭제/이동은 승인 문서와 불일치를 만들므로 결재 화면으로 안내.
6. 롤백: 앱·템플릿·정적 모듈을 같은 변경 단위로 복귀. 메뉴 추가는 멱등 INSERT OR IGNORE이며 기존 정렬·권한 덮어쓰기 없음. 기존 데이터 삭제·스키마 변경 없음.
7. 휴먼 에러: 생성 후 새 경로 재선택, 로딩 중 저장 차단, 선택 변경 시 이전 옵션 초기화. 관리 트리의 손상 순환은 방문 집합으로 제한하고 누락 노드를 경고 표시.
8. AI 메타: 이전 구성요소 검사만으로 운영 준비 완료라 판정하지 않음. 보완 뒤 검사 결과와 미실행 Linux 검증을 명시. 기존 사용자 변경 보존.

잔여 검증: 위 보완 코드·등록 동선 및 메뉴 연결의 정적 대조, 격리 DB 불변식 시험, 운영 소스 재검사.
