# 메뉴 이동·검색·카드 및 모바일 세로 화면 개선 결과

2026-09-14 · 운영 대상: eqmgmt-backup / nkhst-pentium / https://nekohost.org

## 완료한 변경

| 요청 | 현재 동작 |
|---|---|
| 이동 버튼 인접 배치 | 메인메뉴·이전으로·상위 메뉴를 왼쪽의 한 그룹에 배치한다. 방문 이력과 상위 메뉴 계층은 별개다. |
| 최상위 메뉴 표시 | 사용자 추가 지시대로 메인 포털은 상위 메뉴 링크를 HTML에 생성하지 않는다. 비활성 버튼의 자리도 남기지 않는다. |
| 부모 메뉴 | 일반 화면→포털, 관리자 하위 화면→관리자 센터, 에러 IP 분석→접근 로그. 이력이 없거나 외부/인증 화면에서 직접 들어오면 이전으로는 비활성이다. |
| 일반/조건 검색 | 나의/공개 장비는 검색어만 사용하는 일반검색이 기본. 검색 옆 조건검색 버튼으로 기존 상세 필터를 확장하고 일반검색 버튼으로 돌아간다. |
| 조건 상태 | 일반검색에서는 숨겨진 조건을 API·CSV 조회·URL에서 제외한다. 같은 화면에서 다시 펼치면 입력값을 유지·재적용한다. 모드 전환은 1페이지부터 조회하며, 이전 상세 조건 URL은 조건검색으로 복원한다. |
| 카드 설명 | 포털·관리자 메뉴 카드의 설명 영역을 3줄/60px로 고정한다. 초과 문장은 말줄임하고 native title로 마우스 hover 전체 설명을 제공한다. 텍스트 렌더링으로 HTML 해석을 막는다. |
| 세로 화면 | 검색창을 한 줄에, 검색·모드 전환 버튼을 다음 줄에 나란히 배치한다. 상단 영역은 실제 높이에 따라 늘어나고 장비 작업 버튼·프로필 제목/버튼은 요소 단위로 줄바꿈한다. |

별도 신규 제안이 아니라 기존 019(레이아웃), 020(내비게이션), 023(검색)의 후속 개선으로 PROPOSALS.md와 FEATURES.md에 기록했다. 기존 가운데 배치·카드 폭·넓은 표·테마·카탈로그 선택·제조사 표시는 유지한다. Python/DB 스키마/API 권한은 바꾸지 않았다.

## 검증과 발견한 결함

- 실제 템플릿 16종의 320~2560px 응답형 검사, Standard/Edge, 가운데 배치·넘침·카드 3줄/동일 높이·텍스트 안전성·부모 경로·검색 상태 복원·기존 등록/수정/제조사 회귀를 포함해 Node 검사 43건 통과. 마지막 포털 링크 생략 후 영향받는 브라우저/정적 내비게이션 12건도 재검증했다. Windows에서는 Flask를 실행하지 않고, 로컬 소스를 Linux Jinja DictLoader로 읽기 전용 렌더링한 격리 fixture를 사용했다.
- 실제 도메인에서 기존 일반 사용자 guide_test_user로 로그인하여 PC 중심 37개 폭/상태를 통과했다. 상단 이동, 실제 API 검색 조건, Enter, 초기화, 기존 URL, 환경 설정 저장/새로고침, 프로필 창, Chart.js, 관리자 API 403을 확인했다. CSS/JS 6개 정적 자산의 도메인 바이트 해시도 로컬 배포본과 일치한다.
- 사용자의 추가 요청으로 Pixel 7 설정(터치·모바일 viewport·DPR)의 headless Microsoft Edge에서 320×568, 360×800, 390×844, 412×915 세로 화면을 검사했다. Standard/Edge × 포털·나의 장비·공개 장비·내 정보·통계 × 4크기 = 40개 기본 상태와 16개 상세검색 상태를 확인했다.
- **처음 세로 검사에서 자동 수치 검사는 통과했지만 스크린샷 육안 검토에서 헤더/본문 겹침을 발견했다.** `.app-nav-row`의 자동 높이보다 뒤늦게 생성된 Tailwind `h-16` 고정 높이가 우선했고, 줄바꿈된 계정·로그아웃 영역이 헤더 밖으로 나왔다. 고정 높이 및 중복 `space-x` 유틸리티를 제거했다. 단순 가로 넘침뿐 아니라 모든 헤더 컨트롤이 헤더 안에 있는지, 본문과 겹치지 않는지 검증 조건을 추가했다. 첫 검사 결과만으로 정상이라고 판정하지 않았다.
- 보정 배포 후 **56개 세로 상태를 새 조건으로 다시 통과**했고 320/390px 실제 스크린샷을 다시 확인했다. 검색·조건검색의 인접 배치, 터치 검색/조건 제외/값 복원, 이전·상위 메뉴 이동, 포털의 상위 링크 부재를 검증했다. PC 중심 37개 상태도 보정본에서 재통과했다.
- 최초 PC 실검증의 상태 선택자 오류는 검색 폼과 상태 변경 모달의 동일 name을 구분하지 않은 테스트 코드 문제였다. `#roadmap-filter`로 범위를 한정해 수정하고 다시 통과했다. 당시에도 설정 복원/로그아웃이 실행됐으며 증거 JSON은 별도로 보존했다.

최종 관측 서버 5xx=0, 브라우저 pageerror=0. 테스트 계정 설정을 원래 동작값으로 복원하고 로그아웃했다. 비밀번호/쿠키/토큰은 로그·보고서·파일에 저장하지 않았다. 로그인 및 설정 저장/세션 연장 이외의 변경 요청은 브라우저에서 차단했다. 장비/프로필/비밀번호 변경이나 관리자 권한 부여는 하지 않았다.
