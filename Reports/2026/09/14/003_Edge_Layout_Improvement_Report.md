Standard의 페이지 폭과 기존 카드 그리드는 유지한다. 단, 내 정보의 설정 통합·패널 분리는 두 스킨에 공통이며 Standard에서는 한 열로 보인다. 대시보드 분포 표의 내부 스크롤 보완도 공통이다.

기존 Edge의 모든 둥근 모서리를 일괄 축소하는 CSS를 제거했다. 공통 기능 스타일은 roadmap.css에, 폭·배치 정책은 새 layout.css에 둔다. 명시적인 영역 클래스만 대상으로 하므로 편집 창 내부에 넓은 레이아웃이 전파되지 않는다.

앱 Python/DB/API/권한/업무 JavaScript는 변경하지 않았다. 설정 저장도 기존 /api/user_settings와 기존 CSRF 헤더를 그대로 사용한다.

## 최초 구현 단계의 격리 검증 결과

**Node 테스트 40건 통과, 실패·건너뜀 0.** 기존 장비 등록·수정 선택 복원·제조사 표시·WebMCP·공통 JS 검사와 새 Edge 검사 포함. 새 브라우저 묶음은 7개 하위 검사와 정적 연결 검사로 구성한다.

- 실제 로컬 Jinja 템플릿 전체의 문법을 검사하고 15개 화면 + 공개 장비 변형, 총 16개 화면을 렌더링했다.
- Edge 화면 16개 × 8개 폭(320, 390, 640, 768, 1024, 1440, 1920, 2560px)을 검사했다. 페이지 가로 넘침·중복 ID 없음. 표 자체의 가로 스크롤은 허용한다.
- Standard도 16개 화면의 기본 최대 폭을 확인했다. 포털 1024px/3열, 내 정보 672px/1열을 별도로 검증했다.
- 카드 2개만 남겼을 때도 폭이 커지지 않으며, 포털 카드의 패딩·모서리·글자 크기는 Standard와 같음을 확인했다.
- 내 정보의 1199/1200px 경계, 다크/라이트 배경, 편집 모달 폭·모서리, 긴 닉네임·관리자 권한명·세션 만료 임박 문구를 확인했다.
- 긴 장비/로그/분포 표 행이 들어와도 페이지 전체가 늘어나지 않는 것을 확인했다.
- 실제 설정 JavaScript를 격리 브라우저에서 실행하되 저장 응답은 모의 처리했다. 요청 필드·CSRF·스킨 변경·실패 안내·버튼 재활성화를 확인했다. 테마 선택 이벤트, 프로필 창 기존 값 로드, 비밀번호 불일치 시 요청 차단도 확인했다.
- 변경 파일의 Git diff 검사는 공백 오류 없이 통과했다. 기존 MyPage 업무 스크립트는 수정하지 않았다.

### 검증 방법과 한계

Windows에서 Flask를 실행하지 않았다. 백업 서버의 기존 가상환경 Jinja 3.1.6으로 **stdin으로 전달한 로컬 템플릿과 가상 사용자 값만 메모리 렌더링**했다. app.py import, DB 조회/변경, 원격 파일 쓰기, 프로세스 재시작은 없다.

렌더링 결과를 새 headless Microsoft Edge에 넣고 프로젝트의 로컬 Tailwind와 CSS를 적용했다. 브라우저 HTTP 요청은 전부 차단했다. CDN 아이콘은 상단 배치 검사에 필요한 자리표시자로 대체했으며 Chart.js는 실행하지 않았다. 스크린샷은 실제 서비스 화면이 아니라 이 합성 데이터 기반 검증 화면이다.

실제 nekohost.org는 로그인 화면까지 확인했으며 인증된 실서비스 조작·모바일 실기기·다른 브라우저 엔진·실제 이메일 발송은 새로 검증한 것으로 주장하지 않는다. CSS 배치와 클라이언트 연결 확인이지 서버 배포 검증이 아니다.

재실행(Playwright 설치/모듈 경로 및 eqmgmt-backup의 기존 키 인증 필요):

~~~powershell
$env:NODE_PATH='C:/Users/dooly/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules'
$env:EDGE_LAYOUT_BROWSER='1'
$env:EDGE_LAYOUT_SCREENSHOTS='Reports/2026/09/14/edge-layout'
node --test tests/test_roadmap_static.mjs tests/test_release_frontend.mjs tests/test_proposal047_registration.mjs tests/test_edge_layout_browser.mjs
~~~

EDGE_LAYOUT_BROWSER를 설정하지 않으면 브라우저 묶음은 명시적으로 건너뛰고 정적 검사는 실행된다. 따라서 기본 실행의 skip을 실브라우저 통과로 간주하지 않는다.
