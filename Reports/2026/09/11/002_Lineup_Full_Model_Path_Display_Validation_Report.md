# [검토 보고서] 라인업 전체 모델 경로 표시 개선 Validation 1~8

## 결론

현재 증상은 데이터 등록 실패가 아니라 조회 프로젝션 누락이다. /api/equipment가 최하위 node.name만 ModelName으로 반환하고 templates/index.html이 이를 그대로 출력한다. DB 스키마를 바꾸지 않고 공통 경로 조립 결과인 FullModelName을 추가하는 방안이 가장 낮은 위험으로 사용자 요구를 충족한다.

이번 개선은 노드화 자체와 등록·관리 기능의 표시 완성도 문제이므로 새 제안보다 제안 047 후속 개선으로 기록하는 것이 적절하다.

## Validation 1~8

1. 거버넌스 준수: recorder와 governance validate 통과 후 계획·frontend·문서 route를 적용했다. 계획만 작성하며 운영 코드는 변경하지 않았다. 기존 작업 트리의 별도 governance 변경은 보존했다.
2. 사용자 의도: 나의 장비와 공개 장비에서 각 노드를 순차 나열한다는 요구를 직접 수용 기준으로 삼았다. 카테고리·제조사 재설계나 등록 UX 변경으로 확대하지 않았다.
3. 정적 논리: 현재 JOIN은 option이 가리키는 단일 최하위 노드만 읽으므로 증상이 재현되는 구조다. parent_id 기반 경로 조립과 메모이제이션으로 순서를 보장하고 N+1 쿼리를 피한다.
4. 운영 영향: /api/equipment 외에 동일 ModelName 축약을 가진 /api/equipments_v2와 /api/dashboard/stats를 함께 정합화해야 한다. DB migration과 저장 payload 변경은 없다.
5. 보안·예외: 노드명은 신뢰하지 않고 기존 escapeHtml을 유지한다. 순환·유실 부모·과도한 깊이는 전체 요청 실패 대신 최하위 이름 후퇴를 사용한다. 상세 내부 오류는 화면에 노출하지 않는다.
6. 롤백: FullModelName 생성과 화면 우선 표시를 제거하면 기존 동작으로 복구된다. 영구 데이터 변경이 없어 별도 DB 복원은 필요하지 않다.
7. 휴먼 에러·UX: 루트와 잎의 순서를 뒤집거나 제조사를 중복 출력할 위험을 예시 기반 테스트로 차단한다. 긴 경로도 일부 노드를 생략하지 않으며 기존 가로 스크롤 정책을 우선 유지한다.
8. AI 메타: 실제 데이터베이스는 로컬에서 0바이트이므로 운영 데이터가 정상이라고 추정하지 않았다. 코드의 명시적 SELECT와 렌더링 경로만을 근거로 원인을 판정했으며 구현 완료나 실서버 검증을 주장하지 않는다.

## 위험과 차단 조건

- 기존 ModelName 값을 전체 경로로 덮어쓰면 외부 소비자의 의미가 바뀔 수 있으므로 금지한다.
- 행마다 조상 조회를 반복하는 구현은 장비 수 증가 시 성능 저하를 일으키므로 금지한다.
- parent_id 대신 depth 또는 이름 정렬로 경로 순서를 추정하는 구현은 금지한다.
- 구현 중 FullModelName이 등록·수정 payload에 역으로 사용되는 의존성이 발견되면 병합을 중단하고 계약을 재검토한다.

## 판정

계획은 구현 후보 작성 단계로 진행 가능하다. 다만 현재 요청은 계획에 한정되므로 Staging 및 운영 코드 구현은 사용자 후속 승인 전까지 보류한다.
