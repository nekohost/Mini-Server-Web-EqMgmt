# 중단 로드맵 계획 작업 재개 검토

2026-09-11 예약된 문서 경로를 유지하고 2026-09-12에 작성했다. 기존 Task 004의 원래 범위인 전체 미구현 로드맵 상세 계획 작성을 완료했다.

1. 거버넌스: recorder/manifest/context/validate 통과. 소스 기준과 실제 DB 조사 근거를 연결하고 원본 Task를 보존했다. 새 계획은 파일 삭제나 DB migration을 실행하지 않는다.
2. 의도: 15개 기능 묶음과 16개 제안 번호를 전수 포함했다. 이번 사용자의 기존 작업 재개 승인은 해당 계획 작업의 완결과 별도 DB 개선 구현에 적용했다.
3. 논리: 현재 3-Tier를 기준으로 상태→검색→첨부→기한→스킨→CSV 의존 순서를 정했다. validation/인증 시도 제한은 앞단에 배치했다. 일부 코드가 이미 있는 기능을 완전 미구현으로 분류하지 않았다.
4. 운영: 파일 첨부와 DB-only 백업의 불일치, CSV 응답 계약, 스키마/코드 부분 배포를 발견하고 기능별 게이트에 반영했다. 실제 운영에는 개별 기능 검증이 필요하다.
5. 보안: 소유권·관리 권한·CSRF·입력 타입·첨부 경로·수식 주입·프록시 신뢰·계정 잠금 남용을 범위별로 명시했다. 접근 로그의 운영자 결정은 변경하지 않는다.
6. 복구: 컬럼·파일·이력의 무조건 DROP을 배제하고 코드 rollback과 데이터 복구를 분리했다. CSV의 가져오기 식별자와 첨부 manifest를 복구 근거로 설계했다.
7. 사용자 오류: 필터 초기화, 잘못된 날짜, import 미리보기, 상태 전이 사유, 알림 수신 동의, 스킨 기본값 복구를 포함했다.
8. AI 메타: 046 사용자 확인, 017/038/039 실제 구현, 037 제한적 도구 범위를 구분했다. 초기 로드맵의 전면 soft-delete를 현행 hard-delete 계약으로 오인하거나 강제하지 않았다.

원본 대비 15/15 묶음과 교차 시나리오 5종을 대조했다. 결론은 계획 작성 완료이며 모든 로드맵 기능의 신규 구현 완료를 뜻하지 않는다. 그 범위는 각각의 구현 Task에서 추적한다.
