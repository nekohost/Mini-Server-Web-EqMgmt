## 2. Validation Methodology 1~8

### 1단계 — 거버넌스 준수성

- 근거: Staging 격리, 실제 Task 사용, 구조화 편집, 다중 AI 인계 규칙을 대조했다.

- 위험: Task 자동 동기화 명령은 파일을 쓰므로 manifest 근거와 Diff 확인 없이 사용하면 안 된다.
- 차단 조건: `sync` 뒤 `validate`와 Diff 검토가 없으면 상태 변경을 승인하지 않는다.

### 2단계 — 사용자 의도 달성도

- 위험: `[x]`를 단순 작성 완료로 오해할 수 있다.
- 차단 조건: manifest의 상태가 `checkpointed`일 때만 `[x]`가 생성된다.
- 결과: 통과.

### 3단계 — 논리적 구동 가능성

- 근거: Node 구문 검사, manifest·Task 검증, self-test, 계획↔manifest 범위 대조를 수행했다.

### 4단계 — 운영 병합 영향

- 위험: Staging 제어면을 곧바로 운영 주석 완료로 오인할 수 있다.
